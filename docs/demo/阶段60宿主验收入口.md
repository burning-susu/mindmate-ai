# 第六十批：Windows 宿主验收入口

这是一页给普通 Windows PowerShell / VS Code 终端使用的验收入口。它复用仓库现有脚本和第 56 批测试夹具，不创建第二套服务，不读取 `%LOCALAPPDATA%\MindMateAI`，不下载模型，也不需要真实 Provider Key。

本页命令默认从仓库根目录执行。所有端口、数据根和会话都属于本批合成验收；发现已有端口被占用时，换成另一组端口，并把实际端口写入验收记录。

## 0. 前置检查

在普通 VS Code PowerShell 终端中执行：

```powershell
Set-Location 'C:\path\to\mindmate-ai'
Get-Location
node --version
npm --version
Test-Path '.\backend\.venv\Scripts\python.exe'
Test-Path '.\backend\model-cache\manager-validation'
```

要求：Node/npm 可用，仓库虚拟环境存在，固定 ONNX 缓存已经准备为 `READY`。本入口不会通过网络补装依赖或下载模型；若前置检查失败，记录退出码和缺失项后停止。

## 1. 后端关键 pytest

在仓库根目录打开一个终端，使用仓库虚拟环境 Python 和仓库内隔离临时目录：

```powershell
Set-Location '.\backend'
$env:PYTHONPATH = "$(Resolve-Path '.\src');$(Resolve-Path '.\.venv\Lib\site-packages')"
& '.\.venv\Scripts\python.exe' -m pytest -p no:cacheprovider `
  --basetemp '.\build\stage60-host-pytest-tmp' `
  tests/test_stage8_history_purge.py `
  tests/test_stage8_history_fulltext.py `
  tests/test_stage57_learning_multistep.py `
  tests/test_stage8_history_query_trash.py `
  tests/test_stage8_conversation_history.py `
  tests/test_stage8_learning_history.py
$pytestExit = $LASTEXITCODE
Write-Host "pytest exit code: $pytestExit"
```

预期结果为 `29 passed`。失败时保留完整输出和退出码，不用 Ruff、compileall 或前端 Vitest 代替 pytest。

同时核对迁移 head：

```powershell
& '.\.venv\Scripts\python.exe' -m alembic heads
```

本批预期 head 为 `d17a5e9c4b20 (head)`。运行中的隔离 Demo 数据库应使用同一 revision；不要把个人数据根作为检查目标。

## 2. 隔离 Mock Demo

在第二个终端从仓库根目录启动现有 Demo 入口：

```powershell
Set-Location 'C:\path\to\mindmate-ai'
$demoData = Join-Path $env:TEMP 'mindmate-ai-stage60-demo'
& '.\scripts\demo.ps1' -DataDir $demoData -ApiPort 8014 -WebPort 5182
```

`demo.ps1` 会准备固定资料、检查模型和知识库为 `READY`，随后调用现有 `scripts/dev.ps1` 启动 Mock 后端和 Vite。默认 Provider 是 Mock；它不会读取或切换真实 Key。浏览器地址由脚本输出，通常为 `http://127.0.0.1:5182/` 或对应知识库页。

另开一个终端做无点击的运行检查：

```powershell
Invoke-RestMethod 'http://127.0.0.1:8014/api/v1/health'
Invoke-RestMethod 'http://127.0.0.1:8014/api/v1/ready'
$env:MINDMATE_DATA_DIR = $demoData
Set-Location '.\backend'
$env:PYTHONPATH = "$(Resolve-Path '.\src');$(Resolve-Path '.\.venv\Lib\site-packages')"
& '.\.venv\Scripts\python.exe' -c "from mindmate.config import Settings; from sqlalchemy import create_engine,text; s=Settings(); e=create_engine(f'sqlite:///{s.database_path.as_posix()}'); print(e.connect().execute(text('select version_num from alembic_version')).scalar())"
```

健康检查和 revision 只能证明服务可达与数据库状态，不能替代页面点击。回到运行 Demo 的终端按 `Ctrl+C` 停止；脚本会只停止它启动的后端/前端，不会结束系统浏览器或其他端口进程。

## 3. Test-only Provider 夹具

第 56 批已有的 `stage56_online_browser_server.py` 会在后端进程内启用 `learning_provider_fixture=True`，通过 `httpx.MockTransport` 截获 DeepSeek/OpenAI 请求并记录安全调用摘要。它就是本批的 test-only 假 Provider，不需要再启动第三个 Provider 服务。

终端 A：

```powershell
Set-Location 'C:\path\to\mindmate-ai\backend'
$fixtureData = Join-Path (Resolve-Path '.\build') 'stage60-online-fixture'
& '.\.venv\Scripts\python.exe' -u '.\tests\stage56_online_browser_server.py' `
  --data-dir $fixtureData --api-port 8015 --web-port 5183
```

终端 B：

```powershell
Set-Location 'C:\path\to\mindmate-ai\frontend'
npm.cmd run dev -- --host 127.0.0.1 --port 5183 --strictPort
```

浏览器打开 `http://127.0.0.1:5183/settings`。只允许使用合成夹具 Key，例如 `stage60-deepseek-fixture-key` 和 `stage60-openai-fixture-key`；不要输入真实 Key。分别选择 DeepSeek 和 OpenAI，完成每家一次题目和一次点评，并在每次外发前完成页面的独立费用确认。

查看服务端调用计数：

```powershell
Invoke-RestMethod 'http://127.0.0.1:8015/api/v1/health'
Invoke-RestMethod 'http://127.0.0.1:8015/api/v1/testing/provider-fixture/calls'
```

应看到两家固定 Host 的合成调用摘要；响应不应包含 Key 或请求正文。该计数证明的是本地 MockTransport 业务路径，不是官方服务请求。结束时分别在两个终端按 `Ctrl+C`；不要结束其他 Python、Node 或浏览器进程。

## 4. 页面走查清单

使用新的隔离数据根和合成会话逐项记录 URL、状态码、会话 ID、截图路径和结果：

1. 空隔离库上传合成 TXT，创建知识库，等待索引 `READY`；问一个有出处的问题，再问资料不足的问题，确认前者显示来源、后者严格拒答。
2. 在 Mock 默认一题和三题流程中逐题提交、进入下一题、结束统计；刷新页面并重启同一隔离 Demo，确认题目、作答和来源恢复。
3. 用合成对话和学习记录进入历史回收站：分别测试取消、Escape、错误确认词和正确确认词；正确确认后服务端只收到一次永久删除请求，文件、知识库和共享来源仍在。
4. 分别搜索三道题的题干、已提交选项和反馈，点击每个结果，确认定位到对应的 `question_id` 题目或反馈区域。
5. 在 test-only 夹具下分别选择 DeepSeek/OpenAI 完成一题和点评，核对每家调用计数、固定 Host、费用确认和刷新恢复；不要执行官方模型付费冒烟。
