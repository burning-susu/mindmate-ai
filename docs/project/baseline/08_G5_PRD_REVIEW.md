## 7. G5-BLOCKER-001 本地数据备份、保留和恢复责任

### 7.1 背景和当前事实

V1 的原始文件、解析结果、业务数据和向量默认本地保存，删除默认不可恢复；项目不需要云服务器。当前 PRD 已明确数据丢失风险和删除提示，但没有确认 V1 是否提供应用内备份/恢复，也没有确认卸载、数据目录移动和磁盘损坏后的责任边界。

这是数据保留和恢复责任决策，不是数据库技术选型。本轮用户已完成二次确认并授权应用。

### 7.2 可选方案

方案 A：V1 不提供应用内备份/恢复。

- 用户手动管理本地数据目录；
- 删除、卸载、磁盘损坏和目录丢失后不可恢复；
- 产品提供明确风险提示和手动备份建议；
- 交付成本最低，但用户数据丢失风险最高。

方案 B：V1 提供轻量本地导出/备份和恢复。

- 用户可将知识库、原始文件、会话和必要索引元数据导出到用户指定位置；
- V1 不承诺跨设备同步或云备份；
- 需要定义备份格式、敏感数据保护、版本兼容和恢复失败行为；
- 提高交付成本，但更符合个人资料工具的可恢复性要求。

方案 C：V1 引入云备份。

- 提供远程备份和恢复；
- 改变 LOCAL_ONLY、隐私、成本和部署边界；
- 需要重新评估 Provider、存储、权限、合规和 Workflow；
- 不符合当前 V1 交付边界。

### 7.3 已应用结果

DEC-G5-001 已应用方案 B：V1 提供轻量本地导出/备份和恢复，不提供云同步或远程备份。具体备份格式、内容、加密、覆盖、索引重建和失败恢复规则继续留到 G6/G8/G10。

### 7.4 最晚解决阶段

具体备份格式和恢复机制在 G6/G10 设计；本决策不替代技术方案评审。
