# MindMate AI 需求规格总纲 V1

> 本文档是新一轮需求设计的目录、边界和执行规则。后续在当前对话窗口中按本文档逐部分完成详细设计；全部确认后拆分为多份 Markdown 文档，统一打包为 ZIP，作为 Codex 直接进入代码开发阶段的唯一需求输入。

## 1. 项目基本信息

| 项目项 | 当前基线 |
| --- | --- |
| 项目名称 | MindMate AI |
| 仓库 | burning-susu/mindmate-ai |
| 产品定位 | 个人 AI 知识学习助手 |
| 核心能力 | 文件整理、个人知识库、AI 对话、引用溯源、学习陪练 |
| 首版用户 | 单用户 |
| 首版形态 | Web 优先，本地运行 |
| 服务部署 | 不依赖公网服务器 |
| 数据原则 | 原始文件、业务数据、索引和向量默认保存在本地 |
| 外部模型 | 仅由本地后端调用，外发当前任务所必需的文本 |
| 密钥原则 | API Key 仅保存在本机环境变量或未提交的本地配置中 |

## 2. 本轮重新设计的含义

本轮不是推翻产品重新立项，而是停止之前耗时过长的逐层门禁与反复确认流程，重新建立一套可以直接开发的需求基线。

处理旧资料时遵守以下规则：

- 旧需求、设计稿、DEC、评审记录和技术分析作为参考资料保留；
- 已经稳定且没有争议的产品目标可以继承；
- Provider、Embedding、向量库、框架等技术选择必须在本轮最终技术方案中统一确认；
- 旧文档与本轮结果冲突时，以本轮最终需求包为准；
- 不继续维护旧的多轮 G6 决策链作为开发入口；
- 不删除旧资料，但 Codex 开发时只读取最终交付包和必要设计稿；
- 本轮每次最多集中处理 5 个真正影响实现的决策；
- 用户作出明确选择后直接写入当前需求，不再二次确认。

## 3. 本轮最终目标

本轮完成后，应具备一套“无需 Codex 再做产品决策”的开发输入：

1. 产品目标和 V1 范围明确；
2. 页面、功能、流程、状态和异常明确；
3. 文件整理、知识库、AI 对话和学习陪练细节明确；
4. 数据结构、接口边界和本地存储方式明确；
5. AI Provider、Embedding、RAG 和引用规则明确；
6. 设计稿与功能的映射明确；
7. 验收标准和非功能要求明确；
8. 技术架构和开发顺序明确；
9. Codex 可以按照任务清单直接创建项目、编写代码和测试；
10. 未进入 V1 的功能统一记录到后续版本，不在开发中临时扩张。

## 4. V1 产品范围总览

### 4.1 首页 / 工作台

首页用于展示个人知识与学习工作的入口和状态，包括：

- 最近文件；
- 最近知识库；
- 最近对话；
- 最近学习记录；
- 文件处理和索引任务状态；
- 快速上传、快速提问和开始学习入口。

### 4.2 文件整理

文件模块负责个人资料的导入、分类、整理和处理状态管理，包括：

- 文件上传或本地导入；
- 文件类型、大小和重复文件校验；
- 文件夹、分类、标签和搜索；
- 文件重命名、移动、删除和批量操作；
- 文本解析、摘要和元数据提取；
- 解析失败、索引失败和重新处理；
- 文件与知识库的关联；
- 删除文件后的索引失效处理。

### 4.3 个人知识库

知识库模块负责将多个文件组织为可检索、可问答的资料集合，包括：

- 创建、编辑和删除知识库；
- 添加或移除文件；
- 文档解析、切片、Embedding 和索引；
- 索引进度、失败重试和重建；
- 知识库范围检索；
- 文件、切片和引用的关联；
- 资料更新后的增量索引或重建策略；
- 无可用资料时的明确提示。

### 4.4 AI 对话

AI 对话模块提供普通问答和基于知识库的资料问答，包括：

- 新建对话；
- 普通聊天；
- 选择知识库或指定文件提问；
- 流式回答；
- 停止生成、重新生成和继续追问；
- 引用来源展示与定位；
- 资料不足时拒答或提示；
- 多份资料冲突时提示差异；
- 对话标题、历史保存、恢复和删除；
- 长对话上下文控制。

### 4.5 学习陪练

学习陪练基于用户资料进行逐题练习，而不是一次生成整套静态试卷，包括：

- 选择知识库、文件或学习主题；
- 设定学习目标或练习方式；
- AI 逐题出题；
- 用户作答；
- AI 点评、解释和引用依据；
- 继续下一题、重试当前题或结束练习；
- 根据回答动态调整后续问题；
- 结束后生成学习总结；
- 保存学习会话和结果。

V1 不设置独立错题本，错误回答保留在学习历史和总结中。

### 4.6 历史记录

历史模块统一管理：

- AI 对话记录；
- 学习陪练记录；
- 最近使用的知识库和文件；
- 会话恢复；
- 删除历史；
- 原文件被删除或知识库失效时的历史提示。

### 4.7 后台任务与状态反馈

本地解析、切片、Embedding 和索引属于可能耗时的任务，需要：

- 排队；
- 进度展示；
- 成功、失败和取消状态；
- 错误原因；
- 失败重试；
- 应用重启后的状态恢复；
- 防止同一文件重复处理。

## 5. 本轮不纳入 V1 的范围

除非后续明确调整，以下内容不进入首版：

- 多用户注册、登录和权限系统；
- 团队空间与协作；
- 公网服务器部署；
- 移动端原生应用；
- 独立设置页面；
- 独立错题本；
- 社交分享；
- 云端文件同步；
- 在线支付和订阅；
- 复杂插件市场；
- 多 Provider 自动切换；
- 生产级多租户与运维系统。

未进入 V1 的内容统一放入“版本规划与需求待办”，不能在编码过程中临时加入。

## 6. 详细需求文档拆分结构

最终需求包按以下结构拆分。每个文件都必须达到可以直接指导开发和测试的程度。

### 00_需求规格总纲.md

定义项目目标、边界、文档结构、设计规则和开发交付标准，即本文档的最终版。

### 01_产品定位与V1范围.md

详细说明用户画像、使用场景、用户问题、产品目标、成功标准、V1 范围、非目标、术语表和版本边界。

### 02_信息架构与页面清单.md

详细说明一级导航、页面树、页面职责、入口和出口、跳转关系、全局区域、页面状态以及设计稿映射。

### 03_首页与全局交互需求.md

详细设计工作台、全局搜索、通知提示、任务状态、弹窗、抽屉、确认操作和通用交互反馈。

### 04_文件管理详细需求.md

详细设计文件导入、目录和标签、搜索筛选、详情、摘要、批量操作、删除、失败重试和文件生命周期。

### 05_知识库与RAG详细需求.md

详细设计知识库、解析、切片、Embedding、向量索引、召回、重排、引用、增量更新和失效处理。

### 06_AI对话详细需求.md

详细设计对话模式、知识范围选择、消息结构、流式输出、引用、拒答、重新生成、长上下文和历史会话。

### 07_学习陪练详细需求.md

详细设计学习目标、陪练模式、逐题流程、题型、难度调整、作答、点评、引用、重试、结束条件和总结。

### 08_历史记录与后台任务.md

详细设计对话历史、学习历史、任务队列、任务状态、失败恢复、应用重启恢复和数据失效提示。

### 09_数据模型与本地存储.md

详细说明核心实体、字段、实体关系、状态枚举、本地数据库、文件目录、向量数据、删除级联、备份恢复和数据升级。

### 10_AI能力与Provider规范.md

详细说明 Chat Provider、默认模型、Provider Adapter、Embedding、Prompt、RAG 上下文、引用、成本限制、异常处理、密钥和外发数据边界。

### 11_API与模块边界.md

详细说明前后端模块、REST API、OpenAPI、请求响应、错误码、流式接口、上传接口、后台任务接口和 Provider Adapter 接口。

### 12_非功能与安全要求.md

详细说明本地隐私、密钥保护、文件安全、Prompt Injection、防护、性能、容量、日志、错误恢复和 Windows 本地兼容性。

### 13_验收标准与测试场景.md

为主要功能给出前置条件、操作步骤、期望结果、异常场景、边界场景和可验收判定。

### 14_UI设计映射与前端规范.md

详细说明设计稿节点与页面映射、布局、响应式规则、组件、视觉规范、表单交互和缺失设计补充规则。

### 15_技术架构与开发约束.md

在产品需求稳定后统一确认前端框架、本地后端、模块结构、数据库、向量存储、文档解析、任务方案、Provider、Embedding、打包和运行方式。

### 16_Codex开发任务书.md

Codex 的直接执行入口，包含权威输入、禁止重新决策的事项、项目目录、开发阶段、任务清单、文件级范围、测试、验收命令、Git 节点、停止条件和完成报告格式。

### 17_版本规划与需求待办.md

记录 V1 之外的扩展功能、延期需求、待验证想法和后续版本规划。

### 18_最终决策表.md

集中记录产品范围、页面、业务规则、数据策略、AI Provider、Embedding、向量数据库、技术栈、本地运行、成本和隐私边界的最终值。Codex 只读取最终值，不重新发起已完成选型。

## 7. 每部分的详细设计标准

后续编写每一个功能模块时，至少覆盖以下内容：

1. 目标；
2. 使用者；
3. 使用场景；
4. 前置条件；
5. 页面与入口；
6. 主流程；
7. 分支流程；
8. 状态变化；
9. 数据输入；
10. 数据输出；
11. 业务规则；
12. 异常处理；
13. 空状态；
14. 权限与安全；
15. 与其他模块的关系；
16. 验收标准；
17. 不包含的范围；
18. 尚未确定的决策。

不得只写“支持上传”“支持聊天”等一句话需求。每个功能必须明确用户操作、系统行为、状态变化和验收结果。

## 8. 当前窗口的设计方式

### 阶段 A：产品需求设计

依次完成：

1. 产品定位和 V1 范围；
2. 信息架构和页面；
3. 文件管理；
4. 知识库与 RAG；
5. AI 对话；
6. 学习陪练；
7. 历史记录和后台任务；
8. 非功能与安全；
9. 验收标准。

### 阶段 B：技术方案定稿

在需求稳定后一次完成：

1. 前端和本地后端技术栈；
2. 数据库与文件存储；
3. 向量存储；
4. Chat Provider；
5. Embedding；
6. 文档解析；
7. 后台任务；
8. 打包和本地运行。

技术方案不得提前反复阻塞产品需求设计。没有影响当前需求描述的技术项延后到阶段 B 集中决定。

### 阶段 C：整理与交付

1. 检查模块之间的冲突和遗漏；
2. 统一术语、状态和编号；
3. 完成数据模型与 API；
4. 完成验收标准；
5. 生成最终决策表；
6. 生成 Codex 开发任务书；
7. 将全部文档打包为 ZIP。

### 阶段 D：Codex 直接开发

Codex 收到 ZIP 后：

- 先读取 00_需求规格总纲.md；
- 再读取 16_Codex开发任务书.md 和 18_最终决策表.md；
- 按任务书创建或修改项目代码；
- 不重新发起已完成决策；
- 只在需求相互矛盾、缺少实现必需信息或存在安全风险时停止询问；
- 完成每个开发阶段后执行测试并提交结果。

## 9. 决策控制规则

为避免再次长期停留在决策阶段，采用以下规则：

- 只讨论会改变用户体验、数据结构、架构或开发成本的决策；
- 小的实现细节由最终技术方案或 Codex 按通用最佳实践处理；
- 每轮最多展示 5 个独立决策；
- 给出推荐方案和简短理由；
- 用户明确选择后立即写入当前文档；
- 不进行二次确认；
- 不要求用户执行额外应用口令；
- 暂时不影响当前部分的事项记录到待办，不阻塞继续设计；
- 每完成一个部分就冻结该部分，除非后续发现明确冲突；
- 进入 Codex 开发前只进行一次整体一致性检查。
