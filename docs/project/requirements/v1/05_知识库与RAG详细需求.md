# 05 知识库与 RAG 详细需求

## 1. 文档目的

本文档定义 MindMate AI V1 知识库创建、文件关联、切片、Embedding、索引、检索、重排、引用、拒答、资料冲突和索引重建规则。

本模块为 AI 对话和学习陪练提供统一的资料检索能力。两个模块不得各自实现一套不一致的 RAG 逻辑。

## 2. 已确认决策

| 决策项 | 最终选择 |
| --- | --- |
| Embedding 时机 | 文件加入知识库时生成 |
| 检索方式 | 关键词检索＋向量检索＋重排 |
| 资料不足 | 严格拒答，不使用模型通用知识补全 |
| 数据位置 | 文件、切片、Embedding 和向量索引默认保存在本地 |
| 引用原则 | 回答和学习点评必须能定位到来源文件与具体位置 |

## 3. 知识库定位

知识库是用户围绕一个主题组织的可检索资料集合。

知识库不是文件夹：

- 文件夹用于日常文件整理；
- 知识库用于问答和学习；
- 同一个文件可以加入多个知识库；
- 移动文件夹不会改变知识库关系；
- 删除知识库不会删除原始文件。

## 4. 知识库基本信息

每个知识库至少包含：

- 唯一 ID；
- 名称；
- 描述；
- 颜色或图标；
- 文件数量；
- 可用文件数量；
- 索引状态；
- 创建时间；
- 更新时间；
- 最近使用时间；
- 当前切片策略版本；
- 当前 Embedding 模型版本；
- 当前索引版本。

名称必填，长度建议为 1～100 个字符。同一用户允许存在同名知识库，但创建时应提示，避免误操作。

## 5. 知识库操作

V1 支持：

- 创建知识库；
- 编辑名称、描述、颜色或图标；
- 添加已有文件；
- 导入新文件并加入知识库；
- 移除文件；
- 查看索引进度；
- 重试失败文件；
- 重建知识库索引；
- 从知识库开始提问；
- 从知识库开始学习；
- 移入回收站；
- 从回收站恢复；
- 永久删除。

V1 不支持知识库共享、权限管理、公开链接和多人协作。

## 6. 创建知识库

### 6.1 创建表单

包含：

- 名称；
- 描述，可选；
- 颜色或图标，可选；
- 初始文件，可选。

用户可以先创建空知识库，之后再添加文件。

### 6.2 创建结果

- 没有文件时状态为 EMPTY；
- 添加文件后进入 PREPARING；
- 至少一个文件可用且没有阻断性问题时进入 READY 或 PARTIAL；
- 创建知识库本身不调用外部 Chat 模型。

## 7. 添加文件

### 7.1 可添加条件

文件必须：

- 已成功复制到应用目录；
- 文件类型受支持；
- 不在回收站；
- 已完成文本解析；
- 能取得有效正文。

解析中或解析失败的文件可以被选择，但必须显示状态；它们在完成前不参与检索。

### 7.2 添加后的处理

文件第一次加入任意知识库时：

1. 检查解析结果；
2. 根据结构生成切片；
3. 生成 Embedding；
4. 建立或更新向量索引；
5. 建立知识库成员关系；
6. 更新知识库状态。

如果同一文件加入第二个知识库，且切片策略、Embedding 模型和版本一致，应复用文件级切片与 Embedding，不重复计算。知识库通过成员关系控制检索范围。

### 7.3 批量添加

支持一次添加多个文件：

- 展示每个文件状态；
- 合格文件进入任务队列；
- 单个文件失败不阻塞其他文件；
- 知识库可以在部分文件可用时进入 PARTIAL；
- 用户可以查看失败文件并重试。

## 8. 移除文件

从知识库移除文件时：

- 不删除文件本身；
- 不影响文件所在文件夹和标签；
- 立即从该知识库的检索范围排除；
- 保留其他知识库中的关联；
- 历史对话和学习记录保留原引用；
- 如果没有任何知识库继续引用该文件，可以将向量数据标记为可清理缓存；
- 解析正文和全文搜索索引仍保留，用于文件管理和以后重新加入。

用户需要通过明确操作才会删除原始文件。

## 9. Embedding 生成规则

### 9.1 生成时机

普通导入文件只进行：

- 文本解析；
- 结构提取；
- 本地全文搜索索引。

文件加入至少一个知识库后才生成：

- RAG 切片；
- Embedding；
- 向量索引。

### 9.2 复用条件

只有以下条件全部一致时可以复用：

- 文件内容哈希；
- 解析器版本；
- 切片策略版本；
- Embedding Provider；
- Embedding 模型；
- 向量维度；
- 必要的标准化设置。

任一关键条件变化时，文件进入 NEEDS_REINDEX。

### 9.3 生成失败

- 文件保留在知识库；
- 标记为 INDEX_FAILED；
- 不参与向量检索；
- 如果全文索引有效，可以明确标记为“仅关键词可检索”；
- 用户可重试；
- 知识库整体状态可能为 PARTIAL。

## 10. 切片策略

### 10.1 结构优先

切片优先遵循文档结构：

- PDF：页码、标题、段落；
- DOCX：标题层级、段落、列表和表格；
- PPTX：幻灯片；
- Markdown：标题层级、段落、列表和代码块；
- TXT：段落和行。

不得为了固定长度破坏明显的标题与正文关系。

### 10.2 默认大小

初始默认建议：

- 目标大小约 600 tokens；
- 合理范围约 300～800 tokens；
- 相邻切片重叠约 80 tokens；
- 过长段落允许按句子边界继续拆分；
- 极短相邻段落可以合并。

最终数值在技术实现阶段根据 Embedding 模型和测试结果调整，但必须版本化。

### 10.3 上下文信息

每个切片保存：

- chunk ID；
- file ID；
- 文件名；
- 文档类型；
- 标题路径；
- 页码、幻灯片编号或行号；
- 切片正文；
- 前后文必要摘要或父标题；
- 内容哈希；
- 切片策略版本；
- 创建时间。

### 10.4 表格与代码

- 表格尽量保持表头和行关系；
- 超长表格允许按行组拆分；
- 代码块尽量保持完整；
- 代码块过长时按函数、类或逻辑段拆分；
- 引用时标记内容类型。

## 11. 索引状态

知识库状态至少包括：

| 状态 | 含义 |
| --- | --- |
| EMPTY | 没有文件 |
| PREPARING | 正在解析、切片、Embedding 或建立索引 |
| READY | 所有可用文件已完成索引 |
| PARTIAL | 部分文件可用，部分失败或处理中 |
| FAILED | 没有可用于检索的文件 |
| NEEDS_REBUILD | 配置或模型变化，需要重建 |
| IN_TRASH | 已进入回收站 |

文件级状态必须可查看，不能只显示知识库总体状态。

## 12. 检索流程

~~~mermaid
flowchart TD
    Q["用户问题"] --> N["问题规范化"]
    N --> K["关键词检索"]
    N --> V["向量检索"]
    K --> M["候选合并去重"]
    V --> M
    M --> R["重排"]
    R --> T["证据阈值检查"]
    T -->|充分| C["组装上下文和引用"]
    T -->|不足| D["严格拒答"]
~~~

### 12.1 问题规范化

处理：

- 去除无意义空白；
- 保留原始问题；
- 在连续对话中把必要上下文转换为可检索的问题；
- 不改变专有名词、数字、编号和代码；
- 记录规范化结果用于排查，但界面仍展示原问题。

### 12.2 关键词检索

适合查找：

- 专有名词；
- 精确短语；
- 标题；
- 编号；
- 代码符号；
- 数字和日期。

搜索范围仅限当前选择的知识库或文件。

### 12.3 向量检索

用于查找：

- 语义相近表达；
- 问法与原文措辞不一致的内容；
- 概念解释；
- 相关上下文。

向量检索不得包含回收站、失效索引和不属于当前范围的文件。

### 12.4 候选合并

- 合并关键词与向量候选；
- 对相同 chunk 去重；
- 保留两类召回信号；
- 避免同一位置的高度重复切片占满上下文；
- 优先保证多个相关来源的覆盖。

### 12.5 重排

重排根据“用户问题与候选证据的相关性”重新排序。

重排实现可以是本地模型、专用模型或其他技术方案，但必须：

- 经过统一 Adapter；
- 可关闭或替换；
- 不把整库内容发送到外部服务；
- 只处理候选片段；
- 失败时允许使用合并后的候选降级，但必须记录。

### 12.6 初始候选数量

初始建议值：

- 关键词候选最多 20 条；
- 向量候选最多 20 条；
- 合并后最多 30 条；
- 重排后保留约 8 条；
- 最终上下文使用约 4～8 条。

这些值属于可调参数，最终通过质量测试确定。

## 13. 证据阈值与严格拒答

### 13.1 可以回答

只有检索结果能够支持问题核心结论时，才生成基于知识库的回答。

### 13.2 资料不足

资料不足时：

- 明确说明“当前选择的资料不足以回答”；
- 说明检索到的有限相关内容；
- 不使用模型通用知识补全；
- 不生成伪造引用；
- 提供调整问题、添加资料或扩大资料范围的建议；
- 允许用户主动切换到普通聊天，但必须作为新的模式和请求。

### 13.3 部分可回答

问题包含多个子问题时：

- 对有证据部分作答并引用；
- 对无证据部分明确说明资料不足；
- 不把局部证据扩大到整个结论。

### 13.4 阈值

相关性阈值不能只使用一个未经验证的固定分数。技术实现应结合：

- 关键词命中；
- 向量相似度；
- 重排得分；
- 来源覆盖；
- 问题类型；
- 质量测试结果。

阈值需要配置化并通过验收数据集验证。

## 14. 引用结构

### 14.1 回答中的引用

基于知识库的事实性结论应使用可点击编号，例如 [1]、[2]。

引用不能只放在整段回答结尾而无法判断支持哪项结论。应尽量靠近对应句子或段落。

### 14.2 引用信息

每个引用至少包含：

- 文件 ID；
- 文件显示名称；
- chunk ID；
- 标题路径；
- 页码、幻灯片编号或行号；
- 引用片段；
- 当前文件状态；
- 是否可打开原文。

### 14.3 引用抽屉

点击引用后显示：

- 来源文件；
- 定位信息；
- 命中片段及必要上下文；
- 打开文件详情；
- 在原文中查看；
- 来源在回收站或已删除时的状态。

### 14.4 引用失效

- 文件进入回收站：保留历史引用，标记“来源在回收站”；
- 文件恢复：重新检查定位与索引；
- 文件永久删除：保留文件名和历史定位描述，但不保留被永久删除的正文副本；
- 索引重建：历史回答引用原 chunk 时，需要通过版本信息识别是否仍可定位。

## 15. 资料冲突

检索到相互矛盾的资料时：

- 明确提示资料存在冲突；
- 分别概述不同来源的说法；
- 每种说法分别引用；
- 显示文件日期、版本或其他可比较信息；
- 不在证据不足时擅自判定哪一方正确；
- 如果用户要求判断，应说明判断依据和不确定性。

冲突不应被简单合并成一个看似确定的答案。

## 16. 多来源答案

当答案需要多个文件共同支持时：

- 综合相互补充的信息；
- 避免重复引用同一内容；
- 清楚区分各来源贡献；
- 不把一个来源的结论归到另一个来源；
- 引用数量以支撑答案为准，不追求数量。

## 17. 文件更新与索引版本

V1 的应用管理文件副本不会跟随来源路径自动变化。

用户获得新版本资料时：

- 作为新文件导入；
- 可以替换知识库中的旧文件；
- 旧文件是否进入回收站由用户决定；
- 历史对话和学习记录继续指向旧版本；
- 新文件需要重新解析、切片和生成 Embedding。

V1 不自动合并文件版本。

以下情况触发 NEEDS_REBUILD：

- 切片策略变化；
- Embedding 模型变化；
- 向量维度变化；
- 解析器发生不兼容变化；
- 内容哈希变化；
- 索引损坏或缺失。

## 18. 重建索引

### 18.1 单文件重建

用户可以从文件详情或知识库文件列表重建单个文件。

### 18.2 整库重建

适用于配置、模型或索引版本整体变化。

### 18.3 重建行为

- 进入后台任务；
- 展示进度；
- 尽可能保留旧索引直到新索引可用；
- 不允许新旧索引混用且无版本标记；
- 失败时保留可用旧版本并明确状态；
- 成功后原子切换到新版本；
- 清理旧索引前确认没有活动引用。

## 19. 知识库回收站

知识库进入回收站后：

- 从正常列表隐藏；
- 不能用于新问答和学习；
- 停止未开始的索引任务；
- 文件本身不进入回收站；
- 成员关系和索引版本信息保留；
- 历史记录保留并显示知识库在回收站。

恢复后：

- 恢复成员关系；
- 检查文件状态；
- 检查索引版本；
- 有效时恢复 READY；
- 无效时进入 PARTIAL 或 NEEDS_REBUILD。

永久删除知识库后：

- 删除知识库记录和成员关系；
- 删除只属于该知识库的索引数据；
- 不删除原始文件；
- 共享文件级 Embedding 是否清理取决于是否仍被其他知识库引用。

## 20. RAG 与 AI 对话

AI 对话选择知识库或文件后：

- 每条问题在当前范围内检索；
- 回答使用检索证据；
- 回答携带引用；
- 范围变化需要在界面明确显示；
- 普通聊天和知识库聊天必须可区分；
- 严格知识库模式不使用通用知识补答；
- 用户主动切换普通聊天后，回答不应伪装为知识库结论。

## 21. RAG 与学习陪练

学习陪练使用相同检索管线：

- 出题必须基于资料证据；
- 参考答案和点评必须能引用资料；
- 资料不足以继续出题时停止并提示；
- 不根据不存在的资料生成虚假知识点；
- 难度调整不能突破资料范围；
- 学习总结中的知识结论需要可追溯。

## 22. Prompt Injection 防护

知识库文件属于不可信内容。

系统必须：

- 将检索到的正文视为资料，不视为系统指令；
- 忽略文档中要求泄露密钥、修改规则、执行命令或绕过限制的文字；
- 将系统指令、用户问题和检索资料分层传入模型；
- 限制上下文长度；
- 不执行资料中的脚本、链接和命令；
- 对可疑内容记录安全事件但不泄露完整敏感文本；
- 不允许资料覆盖严格拒答和引用规则。

## 23. 隐私与外发边界

默认本地保存：

- 原始文件；
- 解析正文；
- 切片；
- Embedding；
- 向量索引；
- 关键词索引；
- 检索候选；
- 知识库关系。

如果 Chat 使用外部 Provider，只发送：

- 当前用户问题；
- 必要对话上下文；
- 重排后选中的最少必要片段；
- 生成引用所需的脱敏定位信息。

不得发送：

- 整个知识库；
- 无关文件；
- 本地绝对路径；
- API Key；
- 用户未选择的资料；
- 回收站内容。

Embedding 是否完全本地，在技术方案阶段最终确定；无论选择何种实现，都必须经过独立 Adapter，并遵守外发边界。

## 24. 错误与降级

### 关键词检索失败

- 尝试向量检索；
- 标记检索降级；
- 若证据仍不足则拒答。

### 向量检索失败

- 可以使用关键词结果；
- 明确记录降级；
- 不把降级结果伪装为完整检索。

### 重排失败

- 使用合并后的候选顺序；
- 记录失败；
- 仍需执行证据阈值检查。

### Chat Provider 失败

- 保留已完成检索结果；
- 不丢失用户问题；
- 提供重试；
- 重试前检查知识库版本是否变化。

### 索引部分可用

- 只检索 READY 文件；
- 显示当前有多少文件未参与；
- 允许用户等待或继续使用可用资料。

## 25. 质量要求

RAG 需要建立本地验收问题集，至少覆盖：

- 原文可直接回答；
- 同义改写；
- 专有名词和编号；
- 多文件综合；
- 资料不足；
- 资料冲突；
- 文件进入回收站；
- 文件永久删除；
- 索引部分失败；
- Prompt Injection 文本；
- 连续追问；
- 引用定位。

技术阶段需要记录：

- 召回是否包含正确证据；
- 重排后正确证据位置；
- 最终回答是否由证据支持；
- 引用是否正确；
- 拒答是否正确；
- 是否出现范围外回答。

## 26. 验收标准

### KB-AC-01

用户可以创建空知识库，并添加一个或多个已导入文件。

### KB-AC-02

普通文件导入后不自动生成 Embedding；加入知识库后才进入向量处理。

### KB-AC-03

同一文件加入多个知识库时，在配置一致的情况下复用切片和 Embedding。

### KB-AC-04

知识库检索同时使用关键词和向量结果，并执行候选重排。

### KB-AC-05

专有名词、精确编号和语义改写问题都能进入对应检索路径。

### KB-AC-06

资料不足时明确拒答，不使用模型通用知识补齐，也不生成伪造引用。

### KB-AC-07

多子问题中只有部分有依据时，只回答有依据的部分。

### KB-AC-08

回答引用可以定位到文件与页码、幻灯片、标题或行号。

### KB-AC-09

资料冲突时分别展示不同来源和引用，不静默合并。

### KB-AC-10

知识库部分文件失败时，READY 文件仍可使用，并明确提示未参与文件。

### KB-AC-11

文件从知识库移除后立即不再参与该知识库检索，但原文件不被删除。

### KB-AC-12

知识库进入回收站后不能用于新问答和学习，原文件仍保留。

### KB-AC-13

切片、Embedding 或索引配置变化后，知识库进入 NEEDS_REBUILD，而不是继续静默使用不兼容数据。

### KB-AC-14

重建失败时尽可能保留旧的可用索引，并明确显示版本状态。

### KB-AC-15

文档中出现伪装成指令的内容时，不得覆盖系统规则、泄露密钥或触发命令执行。

## 27. 本部分冻结结论

- 文件加入知识库后才生成 Embedding；
- 全部导入文件仍建立本地全文搜索索引；
- 同配置下多个知识库复用同一文件的切片和 Embedding；
- 切片结构优先，初始目标约 600 tokens、重叠约 80 tokens；
- RAG 使用关键词检索、向量检索、候选合并和重排；
- 最终上下文只使用少量高相关片段；
- 资料不足时严格拒答；
- 普通知识问答必须与知识库严格模式区分；
- 回答和学习点评使用可点击引用；
- 资料冲突时并列展示不同来源；
- 文件、模型和索引版本变化需要可追踪；
- 知识库删除不删除原始文件；
- 检索资料视为不可信内容，不能覆盖系统指令；
- 原始文件、切片、Embedding 和索引默认本地保存。
