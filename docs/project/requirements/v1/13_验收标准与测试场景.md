# 13 验收标准与测试场景

## 1. 文档目的

本文档定义 MindMate AI V1 的产品验收口径、端到端场景、异常与边界测试、AI/RAG 质量测试及发布判定。它是开发完成后判断“能否交付”的权威文件，不以“页面能打开”或“接口返回 200”代替业务验收。

## 2. 验收原则

1. 以用户可见结果和持久化状态为准；
2. 每个核心场景同时验证成功、失败、取消、重试和重启恢复；
3. AI 输出非确定，验证结构、依据、边界和质量阈值，不逐字比较；
4. 不用真实付费 API 跑自动化全量测试；
5. 真实 DeepSeek 只用于人工冒烟和小型固定评测集；
6. 所有阻塞级缺陷清零后才能发布；
7. 本文与 01–12 冲突时，先按业务源文档修正本文，不静默改变需求。

## 3. 测试级别

| 级别 | 目标 | 运行时机 |
| --- | --- | --- |
| 单元测试 | 领域规则、状态机、切片、评分、预算 | 每次提交 |
| 契约测试 | OpenAPI、DTO、错误码、SSE 事件 | 每次提交 |
| 集成测试 | SQLite、文件、向量、任务、凭据 Adapter | PR/合并前 |
| E2E | 用户核心流程 | PR/夜间/发布前 |
| AI 固定评测 | 检索、引用、拒答、出题与点评 | Prompt/模型/RAG 变更时 |
| 安全测试 | 本地 API、文件、XSS、注入、密钥 | 发布前 |
| 性能与容量 | 12 文档定义的目标 | 里程碑和发布前 |
| 安装升级测试 | 安装、升级、备份、回退、卸载 | 发布候选包 |

## 4. 测试环境与数据集

### 4.1 环境

- 推荐机：Windows 11 x64、6 核以上、16 GB、SSD；
- 最低机：Windows 11 x64、4 核、8 GB、SSD；
- 网络：正常、断网、高延迟、请求超时、429、5xx；
- 显示：1280×720、1920×1080，100%/125%/150% 缩放；
- DeepSeek：默认使用 Mock Provider，发布前执行少量真实 API 冒烟。

### 4.2 固定资料集

测试仓库必须包含：

- 正常 PDF、DOCX、PPTX、TXT、MD 各至少 3 个；
- 中英文混合、表格、标题层级、空白页和重复段落；
- 两份结论冲突的资料；
- 一份不包含指定答案的资料；
- 重复内容和同名不同内容文件；
- 50 MB 边界文件与超限文件；
- 损坏、加密、伪装扩展名和恶意文件名；
- 含 Prompt Injection、恶意 Markdown、远程图片和脚本片段的文件；
- 具备可人工标注答案与来源位置的问答集；
- 具备简单、中等、困难题目的学习评测集。

### 4.3 数据隔离

自动化测试使用临时数据目录和测试凭据存储；每条场景可独立重复。测试完成后清理临时目录，不接触开发者真实资料和 Key。

## 5. 缺陷等级

| 等级 | 定义 | 发布规则 |
| --- | --- | --- |
| Blocker | 数据丢失、密钥泄露、越权外发、任意代码执行、无法启动 | 必须清零 |
| Critical | 核心流程不可用、引用错误、恢复失败、跨库泄露 | 必须清零 |
| Major | 有替代路径但明显影响主要功能 | 原则上清零；否则书面豁免 |
| Minor | 文案、局部样式、低频便利性问题 | 可进入已知问题 |

## 6. 通用用例格式

每个正式测试用例至少记录：用例 ID、关联需求、优先级、前置条件、测试数据、步骤、期望结果、实际结果、证据、执行人、日期和缺陷 ID。

## 7. 安装与首次运行

### AC-INSTALL-001 正常首次启动

**前置条件**：干净 Windows 11 用户环境。

**步骤**：安装应用；启动；查看首页；关闭并再次启动。

**期望**：安装不要求持续管理员权限；只监听回环地址；自动创建版本化数据目录；首页可操作；第二次启动读取同一数据；无示例 Key 和真实用户数据。

### AC-INSTALL-002 重复实例

**步骤**：应用运行时再次启动。

**期望**：聚焦已有实例或给出明确提示；不产生两个写进程；数据库无锁损坏。

### AC-INSTALL-003 运行时或权限缺失

**步骤**：模拟 WebView/目录写权限/磁盘空间不足。

**期望**：启动前明确指出缺失项和修复方法；不创建半成品数据库；诊断信息不含敏感内容。

### AC-INSTALL-004 卸载保留数据

**步骤**：导入资料并产生历史；默认卸载；重新安装。

**期望**：默认保留用户数据；重新安装后可读取；显式选择彻底删除时才清除数据和凭据。

## 8. 全局框架与首页

### AC-GLOBAL-001 五个核心入口

**步骤**：逐一点击首页、学习、AI 对话、知识库、文件。

**期望**：选中状态、标题和内容一致；历史为辅助入口；任务为全局按钮/抽屉，不增加一级导航。

### AC-GLOBAL-002 首页数据准确

**步骤**：分别创建文件、知识库、对话、学习记录和后台任务；返回首页。

**期望**：统计和最近活动与真实数据一致；空状态与有数据状态切换正确；快捷入口到达正确上下文。

### AC-GLOBAL-003 全局任务抽屉

**步骤**：开始解析或索引；切换多个页面；打开任务抽屉；取消任务。

**期望**：任务状态持续可见；页面切换不丢失；阶段、进度和失败原因清楚；取消后状态最终一致。

### AC-GLOBAL-004 路由恢复

**步骤**：刷新详情页或重启应用后访问原 URL。

**期望**：有效资源恢复；已删除/不存在资源显示专用状态，不出现白屏。

## 9. 文件管理

### AC-FILE-001 支持格式导入

**步骤**：同批导入 PDF、DOCX、PPTX、TXT、MD。

**期望**：立即创建任务；逐个显示状态；成功文件产生托管副本、解析文本和元数据；原文件后续移动不影响应用副本。

### AC-FILE-002 限制与部分成功

**步骤**：导入 21 个文件、单个超 50 MB、批次超 500 MB，并混入损坏文件。

**期望**：前后端同时校验；超限请求被清楚拒绝；合法批次中单个文件失败不回滚其他成功文件。

### AC-FILE-003 重复文件处理

**步骤**：再次导入完全相同内容；分别选择复用、独立记录和跳过。

**期望**：系统识别内容重复；不重复上传字节；三个选择产生符合 04 文档的结果；幂等重试不额外创建记录。

### AC-FILE-004 文件整理

**步骤**：创建文件夹/标签；移动、重命名、批量加标签、搜索和筛选。

**期望**：列表、详情、搜索和统计同步；同名与非法名称规则一致；批量操作返回逐项结果。

### AC-FILE-005 删除、恢复、永久删除

**步骤**：将已加入知识库的文件移入回收站；查看知识库；恢复；再次删除并永久删除。

**期望**：软删除后不参与新检索；依赖处显示失效；30 天规则正确；恢复后关系和索引按规则恢复；永久删除清理托管文件、文本和索引映射。

### AC-FILE-006 恶意和异常文件

**步骤**：导入伪装扩展、恶意文件名、加密、损坏、包含外链的文档。

**期望**：不执行内容、不访问外链、不越界写入；错误可理解；主进程和其他任务稳定。

## 10. 知识库与 RAG

### AC-KB-001 创建并建立索引

**步骤**：创建知识库；选择已解析文件；保存；观察任务。

**期望**：成员关系立即保存；索引状态从待处理到可用；只有新版本成功后才激活；可查看成功、失败和跳过数量。

### AC-KB-002 增量更新

**步骤**：向可用知识库增加一个文件、移除一个文件。

**期望**：只处理受影响内容；构建期间旧索引仍可查询；新索引原子激活；移除内容不再被检索。

### AC-KB-003 基于资料回答

**步骤**：提问固定问答集中的可回答问题。

**期望**：答案结论由选中资料支撑；引用可点击并定位到正确文件/页码或段落；不引用范围外文件。

### AC-KB-004 严格拒答

**步骤**：询问资料中不存在的事实。

**期望**：明确说明资料不足；不使用模型常识补全；可建议调整问题或补充资料；无伪造引用。

### AC-KB-005 资料冲突

**步骤**：询问两份资料结论冲突的问题。

**期望**：回答指出冲突并分别引用；不擅自合并成唯一事实；来源位置正确。

### AC-KB-006 索引不可用

**步骤**：模拟模型缺失、索引损坏、文件解析失败。

**期望**：状态明确；不伪装成可查询；提供重试、重建或查看失败文件；本地数据不丢失。

## 11. AI 对话

### AC-CHAT-001 普通聊天

**步骤**：新建普通聊天；连续发送问题；停止一次生成并重试。

**期望**：不执行 RAG、不显示本地引用；流式输出；停止后保留已接收内容并标记未完成；重试不会重复用户消息。

### AC-CHAT-002 知识库聊天

**步骤**：选择知识库；提问；点击引用；追问。

**期望**：模式和范围始终可见；每轮重新检索；追问保留必要上下文；引用定位正确；范围外内容不进入回答。

### AC-CHAT-003 切换范围

**步骤**：在会话中切换知识库或文件范围，再发问题。

**期望**：消息流插入范围变更标记；只影响后续消息；旧回答保留原范围快照。

### AC-CHAT-004 编辑历史问题

**步骤**：编辑中间一条用户消息并确认重新生成。

**期望**：后续旧分支归档而非静默覆盖；从修改点产生新结果；刷新后历史一致。

### AC-CHAT-005 Provider 异常

**步骤**：模拟未配置 Key、401、429、5xx、断网、超时和中途断流。

**期望**：映射为可理解错误；用户问题保留；不泄露响应体秘密；有限重试；不会自动换 Provider；可手动重试。

### AC-CHAT-006 草稿与恢复

**步骤**：输入未发送草稿；切换页面并重启。

**期望**：草稿本地恢复；发送后清除；草稿不进入 Provider 或历史消息。

## 12. 学习陪练

### AC-LEARN-001 开始学习

**步骤**：选择资料、主题、目标、难度和题量；开始。

**期望**：验证资料可用；生成可保存的学习计划；先讲解、再练习；讲解带依据。

### AC-LEARN-002 一题一反馈

**步骤**：回答一道题并提交。

**期望**：提交前可编辑；提交后答案锁定；先显示结论、依据、改进建议，再允许重试/下一题；不提前展示完整参考答案。

### AC-LEARN-003 提示与重试

**步骤**：请求不同级别提示；答错后重试。

**期望**：提示逐步增加但不立即泄底；记录提示次数和每次作答；重试不覆盖旧尝试；最终点评可追溯。

### AC-LEARN-004 自适应难度

**步骤**：连续正确、连续错误，并手动调整难度。

**期望**：系统按已定义规则升降；变化有说明；手动选择优先；不会超出允许等级。

### AC-LEARN-005 暂停与恢复

**步骤**：答题中暂停或强制退出；重启后继续。

**期望**：恢复到最近已提交状态；未提交输入按草稿规则恢复；不重复计分或重复生成已完成题目。

### AC-LEARN-006 总结与复习

**步骤**：完成或主动结束学习。

**期望**：保存完成度、正确情况、薄弱点、引用和下一步；生成 1/3/7/14/30 天基础复习计划并按表现调整；今日待复习数量正确。

### AC-LEARN-007 资料不足

**步骤**：选择过窄资料并要求超范围主题。

**期望**：出题或点评拒绝编造；提示扩大资料或修改主题；已完成学习记录仍保存。

## 13. 历史记录与后台任务

### AC-HISTORY-001 统一历史

**步骤**：产生对话和学习历史；按类型、日期、关键词筛选。

**期望**：结果准确；可进入原上下文；软删除进入回收站；恢复后可再次访问。

### AC-TASK-001 并发限制

**步骤**：连续提交 3 个重任务，其中 2 个需要 Embedding。

**期望**：最多 2 个重任务运行，最多 1 个 Embedding/向量写任务；其余排队；UI 不阻塞。

### AC-TASK-002 失败重试

**步骤**：使解析或索引阶段失败；修复原因后重试。

**期望**：保留阶段和错误码；重试从安全检查点开始；不重复成功副作用；成功后状态闭合。

### AC-TASK-003 重启恢复

**步骤**：任务运行时强制结束应用并重启。

**期望**：任务转为中断或可恢复；旧索引仍可用；不自动重发付费 AI 请求；用户可继续或重试。

### AC-TASK-004 记录清理

**步骤**：制造成功、取消和失败任务并推进保留时间。

**期望**：成功/取消记录 7 天、失败记录 30 天；业务结果不随任务记录清理而删除。

## 14. 设置、凭据与隐私

### AC-PRIV-001 首次外发同意

**步骤**：未同意时尝试 AI；阅读提示并同意；再次调用。

**期望**：同意前不发请求；提示说明发送内容和本地内容；记录版本；同意后按最小数据调用。

### AC-PRIV-002 API Key 生命周期

**步骤**：输入、保存、连接测试、重启、更换、删除 Key。

**期望**：Key 仅在系统凭据存储；前端不可回读；日志/DB/备份不存在；删除后立即无法调用。

### AC-PRIV-003 外发最小化

**步骤**：抓取测试 Provider 收到的请求。

**期望**：只含问题、必要上下文、选中证据和指令；不含原文件、全库、向量、Key、绝对路径或其他会话。

### AC-PRIV-004 离线能力

**步骤**：断网后浏览、整理、搜索文件，打开历史并尝试 AI。

**期望**：本地功能可用；AI 明确提示网络不可用；不破坏已有数据。

## 15. 备份、恢复与升级

### AC-BACKUP-001 完整备份

**步骤**：存在文件、知识库、对话和学习记录时创建备份。

**期望**：生成 manifest 和哈希；不含 API Key；过程中不阻塞只读使用；失败不留下可误用备份。

### AC-BACKUP-002 完整恢复

**步骤**：在空数据目录恢复合法备份。

**期望**：校验后原子切换；对象数量、关系和内容一致；索引可用或可重建；要求重新配置 Key。

### AC-BACKUP-003 损坏或不兼容备份

**步骤**：篡改文件、manifest、schema_version。

**期望**：恢复前拒绝；原数据不改变；错误说明具体且不暴露敏感正文。

### AC-UPGRADE-001 向前升级

**步骤**：使用上一受支持版本数据启动新版本。

**期望**：先备份/恢复点；迁移成功；核心数据计数一致；关键 E2E 通过。

### AC-UPGRADE-002 迁移失败

**步骤**：注入迁移失败。

**期望**：不进入可写状态；旧数据仍可恢复；提示导出诊断或回退，不循环破坏。

## 16. 安全与非功能验收

必须完整执行 12_非功能与安全要求.md 第 23 节安全清单，以及性能、容量、资源、无障碍和 Windows 兼容测试。任何发布门禁失败均为 Blocker 或 Critical。

## 17. AI/RAG 固定评测方法

### 17.1 评测集

至少准备 50 个基于资料的问答：

- 30 个明确可回答；
- 10 个需要多片段或多文件综合；
- 5 个资料冲突；
- 5 个资料不足必须拒答。

学习评测至少 20 个主题，每个主题人工标注知识点、允许难度和核心依据。

### 17.2 指标与门槛

| 指标 | 发布门槛 |
| --- | --- |
| 检索 Recall@10 | ≥ 0.85 |
| 引用存在率（需要引用的回答） | 100% |
| 引用定位正确率 | ≥ 0.95 |
| 关键事实有依据比例 | ≥ 0.90 |
| 资料不足拒答召回率 | ≥ 0.90 |
| 跨范围引用 | 0 |
| 虚构来源 ID | 0 |
| 学习题目可由资料作答 | ≥ 0.95 |
| 点评与提交答案一致 | ≥ 0.95 |
| 结构化输出 Schema 成功率（含一次修复） | ≥ 0.98 |

任何模型、Prompt、切片、Embedding、重排或上下文预算变更都必须重跑相关评测，并保存版本对比。

## 18. 核心 E2E 发布套件

发布候选包必须通过以下最小闭环：

1. 首次启动与本地隐私说明；
2. 配置测试 Key；
3. 导入 5 类文件并等待解析；
4. 建立知识库并完成索引；
5. 可回答问题＋正确引用；
6. 不可回答问题＋严格拒答；
7. 普通聊天流式停止与重试；
8. 新建学习、讲解、答题、点评、总结；
9. 暂停重启后继续；
10. 文件删除、依赖失效、恢复；
11. 备份、清空测试目录、恢复；
12. 卸载保留数据并重新安装。

## 20. 发布判定

发布需要同时满足：

- 核心 E2E 100% 通过；
- Blocker/Critical 为 0；
- Major 为 0 或具有明确临时豁免、规避方法和修复版本；
- AI/RAG 指标达到门槛；
- 安全门禁通过；
- 安装、升级、备份恢复通过；
- 最终决策表与实际实现一致；
- 生成测试报告、已知问题和版本说明。

## 21. 本部分冻结结论

V1 验收以“导入资料—建立知识库—有依据问答—逐题学习—历史恢复—备份恢复”的完整闭环为核心。AI 质量采用固定评测集和阈值判定；安全、数据丢失、跨范围引用和密钥泄露均无豁免。
