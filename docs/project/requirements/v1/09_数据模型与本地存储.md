# 09 数据模型与本地存储

## 1. 文档目的

本文档定义 MindMate AI V1 的核心数据实体、实体关系、本地数据库、应用数据目录、托管文件、解析正文、切片、Embedding、向量索引、全文索引、软删除、永久删除、数据迁移、备份恢复和密钥隔离规则。

本文件描述稳定的数据契约和存储边界。具体 ORM、迁移框架、向量引擎和打包实现将在 15_技术架构与开发约束.md 最终冻结。

## 2. 本轮开发基线

| 项目 | V1 基线 |
| --- | --- |
| 业务数据库 | SQLite |
| 全文搜索 | SQLite FTS5 |
| 数据库模式 | 单用户、单本地数据库 |
| 数据库并发 | WAL 模式、外键启用、后端统一访问 |
| 原始文件 | 导入后复制到应用数据目录，由应用管理 |
| 文件去重 | SHA-256 内容哈希；物理内容可复用，逻辑记录可独立 |
| 解析正文与切片 | 本地保存并版本化 |
| Embedding 与向量 | 默认本地保存，通过 VectorStore Adapter 访问 |
| 向量引擎 | 在技术架构阶段确定，不写入业务层接口 |
| 标识符 | 后端生成 UUIDv7 字符串 |
| 时间 | 数据库存 UTC 毫秒；界面按本地时区显示 |
| API Key | 不进入 SQLite、配置文件、日志和备份；使用操作系统安全凭据存储 |
| 业务删除 | 软删除进入回收站，默认 30 天后清理 |
| 备份 | 本地手动全量备份与全量恢复；默认排除 API Key 和可重建缓存 |

## 3. 设计目标

数据层需要同时满足：

- 单用户本地运行；
- 无公网服务器；
- 文件、历史、学习记录和索引在应用重启后保留；
- 支持 RAG 引用定位；
- 支持中断任务恢复；
- 支持 30 天回收站；
- 支持未来替换 Chat Provider、Embedding Provider 和向量引擎；
- 支持数据库升级；
- 支持本地备份与恢复；
- 不把 API Key 混入普通业务数据。

## 4. 数据分类

### 4.1 权威业务数据

必须保留且不能通过模型重新猜测：

- 文件、文件夹和标签记录；
- 物理内容对象与内容哈希；
- 知识库及成员关系；
- 对话、消息、回答版本和引用快照；
- 学习计划、题目、作答、点评、总结；
- 掌握度和复习计划；
- 后台任务状态与检查点；
- 用户可见设置；
- 软删除和恢复信息；
- 数据模式版本。

### 4.2 历史可追溯数据

需要在引用有效期间保留：

- 解析正文结构；
- 文本块；
- RAG 切片；
- 文件、解析器、切片与索引版本；
- 引用位置；
- 题目出题依据；
- 生成结果使用的 Provider、模型和 Prompt 版本标识。

### 4.3 可重建数据

损坏或丢失后可由权威数据重新生成：

- FTS5 搜索索引；
- 向量索引文件；
- 缩略图与预览缓存；
- 临时上传文件；
- 任务临时产物；
- 页面缓存；
- 部分派生统计。

可重建不代表可以随意删除。删除前仍需确认当前没有任务正在使用，并更新业务状态。

### 4.4 敏感秘密

独立于业务数据库保存：

- Provider API Key；
- 未来可能存在的代理凭据；
- 备份加密密码，如以后实现。

## 5. 本地数据根目录

### 5.1 默认位置

Windows 默认使用当前用户的本地应用数据目录，例如：

~~~text
%LOCALAPPDATA%\MindMateAI\
~~~

不得默认写入安装目录、项目仓库、用户桌面或系统公共目录。

其他平台如果未来支持，应使用平台标准的用户应用数据目录，不在代码中硬编码 Windows 路径。

### 5.2 路径配置

- V1 可以由安装或首次启动流程选择数据目录；
- 修改数据目录属于迁移操作，不能只修改一个字符串；
- 应用保存规范化后的绝对路径；
- 界面通常只显示友好路径；
- 外部 Provider 请求不得包含该绝对路径。

### 5.3 建议目录

~~~text
MindMateAI/
├── database/
│   ├── mindmate.db
│   ├── mindmate.db-wal
│   └── mindmate.db-shm
├── objects/
│   └── sha256-prefix/content-hash
├── parsed/
│   └── file-id/parse-version/
├── vectors/
│   └── embedding-config-id/index-version/
├── previews/
│   └── file-id/
├── tasks/
│   └── task-id/
├── backups/
├── logs/
├── cache/
└── config/
    └── app-config.json
~~~

真实目录名可在技术实现中微调，但职责必须隔离。

### 5.4 路径规则

- 文件名不直接作为磁盘唯一标识；
- 用户文件名只能作为元数据；
- 物理对象路径由内容哈希或内部 ID 生成；
- 禁止路径穿越；
- 禁止把未校验的用户输入拼接成磁盘路径；
- 临时文件必须位于明确的任务目录；
- 删除只能作用于已解析并确认属于数据根目录的目标。

## 6. SQLite 配置

### 6.1 必需设置

- 启用 foreign_keys；
- 使用 WAL 日志模式；
- 设置合理 busy timeout；
- 使用事务；
- 启动时执行快速完整性检查；
- 正常退出或备份前执行适当 WAL checkpoint；
- 数据库连接只能由本地后端管理。

### 6.2 前端访问

前端不得直接打开 SQLite 文件。所有读写通过本地后端的业务接口完成。

### 6.3 单写入者原则

SQLite 允许多读，但业务层需要控制写入：

- 后台任务不各自持有无限写事务；
- 长文件处理在事务外完成计算；
- 最终状态和索引版本通过短事务提交；
- 高并发写入通过后端队列协调；
- 不在模型调用期间保持数据库事务。

### 6.4 JSON 字段

JSON 只用于：

- 结构随类型变化但仍有明确 schema 的快照；
- 模型结构化输出的原始校验结果；
- 低频、非搜索主路径配置。

可查询、关联或约束的重要字段必须拆为普通列，不把整个业务对象塞进 JSON。

## 7. 标识符与通用字段

### 7.1 主键

- 所有核心实体使用 UUIDv7 字符串；
- ID 由本地后端生成；
- 前端不得自行决定可信主键；
- 数据库不使用文件名、标题或哈希作为业务主键。

### 7.2 时间

通用时间字段使用 UTC Unix 毫秒整数：

- created_at；
- updated_at；
- deleted_at；
- purge_after；
- started_at；
- completed_at。

复习到期同时保存：

- due_at_utc；
- due_local_date；
- timezone_id。

这样可以按用户本地日期展示，同时避免跨时区解释不清。

### 7.3 乐观并发

可编辑实体包含 revision 或 row_version。

更新时携带当前版本；版本不一致返回冲突，不静默覆盖用户较新的内容。

### 7.4 通用软删除字段

需要进入回收站的实体包含：

- deleted_at；
- purge_after；
- deleted_reason；
- original_parent_id 或恢复位置；
- deletion_batch_id，可选。

未删除记录 deleted_at 为 NULL。

## 8. 文件与目录模型

### 8.1 ContentObject

表示应用管理的一份物理字节内容。

| 字段 | 说明 |
| --- | --- |
| content_object_id | UUIDv7 |
| sha256 | 完整内容哈希，唯一 |
| byte_size | 文件字节数 |
| detected_mime_type | 检测到的类型 |
| storage_relative_path | 相对数据根目录路径 |
| storage_state | STAGING、READY、MISSING、CORRUPTED |
| reference_count | 可缓存值，真实值仍需关系校验 |
| created_at | 创建时间 |
| verified_at | 最近完整性校验时间 |

同一 SHA-256 内容只保存一份物理对象，除非完整性校验发现异常。

### 8.2 File

表示用户看到的逻辑文件记录。

| 字段 | 说明 |
| --- | --- |
| file_id | UUIDv7 |
| content_object_id | 指向物理内容 |
| display_name | 用户看到的文件名 |
| extension | 规范化扩展名 |
| document_type | PDF、DOCX、PPTX、TXT、MARKDOWN |
| folder_id | 当前文件夹 |
| status | 文件业务状态 |
| source_name | 导入时原文件名 |
| source_path_hint | 默认不保存完整原路径；如保留必须可清除 |
| content_hash | 冗余 SHA-256，便于查询 |
| byte_size | 冗余大小 |
| parse_revision_id | 当前有效解析版本 |
| created_at | 导入时间 |
| updated_at | 更新时间 |
| last_opened_at | 最近打开 |
| deleted_at | 软删除时间 |
| purge_after | 到期清理时间 |
| row_version | 乐观并发版本 |

多个 File 可以指向同一个 ContentObject，以支持“相同内容另存独立记录”。

### 8.3 Folder

| 字段 | 说明 |
| --- | --- |
| folder_id | UUIDv7 |
| parent_folder_id | 父文件夹，可为空 |
| name | 当前层名称 |
| normalized_name | 用于同级唯一性检查 |
| sort_order | 可选排序 |
| created_at | 创建时间 |
| updated_at | 更新时间 |
| deleted_at | 软删除时间 |
| purge_after | 清理时间 |

约束：

- 同一未删除父文件夹下 normalized_name 唯一；
- 不允许形成循环；
- 系统根目录不允许删除；
- 移动时检查目标不是自身后代。

### 8.4 Tag

| 字段 | 说明 |
| --- | --- |
| tag_id | UUIDv7 |
| name | 显示名称 |
| normalized_name | 唯一匹配名称 |
| color | 可选颜色 |
| created_at | 创建时间 |
| updated_at | 更新时间 |

标签删除为直接删除关系，不进入回收站。

### 8.5 FileTag

复合唯一约束：

~~~text
(file_id, tag_id)
~~~

标签关系删除不影响文件。

## 9. 文件导入与原子提交

### 9.1 导入阶段

1. 在任务临时目录创建 staging 文件；
2. 流式复制并同时计算 SHA-256；
3. 校验大小与文件类型；
4. 查询相同内容对象；
5. 用户确认复用或创建独立逻辑记录；
6. 必要时原子移动为正式内容对象；
7. 短事务创建 ContentObject、File 和任务结果；
8. 排队解析。

### 9.2 崩溃安全

- 数据库记录不得指向尚未提交的临时路径；
- 正式文件移动和数据库提交使用可恢复的顺序；
- 启动时清理超期 staging 文件；
- 如果物理文件存在但数据库提交失败，作为孤儿对象处理；
- 如果数据库存在但文件缺失，标记 MISSING，不伪装 READY。

### 9.3 原来源路径

导入后应用不依赖原来源路径。

默认只保存原文件名，不保存完整来源路径。若未来为了“显示导入来源”保存路径，必须：

- 明确属于本地元数据；
- 可由用户清除；
- 不发送到 Provider；
- 不作为打开文件的唯一依据。

## 10. 解析数据模型

### 10.1 ParseRevision

每次解析产生不可覆盖的版本。

| 字段 | 说明 |
| --- | --- |
| parse_revision_id | UUIDv7 |
| file_id | 文件 |
| content_hash | 解析的内容哈希 |
| parser_name | 解析器 |
| parser_version | 版本 |
| status | PENDING、RUNNING、READY、FAILED |
| language_hint | 可选 |
| page_count | 可选 |
| slide_count | 可选 |
| extracted_char_count | 正文字符数 |
| structure_manifest_path | 外部结构文件相对路径，可选 |
| error_code | 脱敏错误 |
| created_at | 创建时间 |
| completed_at | 完成时间 |

File.parse_revision_id 只在新版本完整成功后原子切换。

### 10.2 TextBlock

保存可定位的结构化正文。

| 字段 | 说明 |
| --- | --- |
| text_block_id | UUIDv7 |
| parse_revision_id | 解析版本 |
| sequence_number | 文档顺序 |
| block_type | TITLE、PARAGRAPH、LIST、TABLE、CODE 等 |
| heading_path | 标题路径 |
| page_number | PDF 页码，可空 |
| slide_number | PPTX 幻灯片，可空 |
| line_start | 文本行起点，可空 |
| line_end | 文本行终点，可空 |
| content | 规范化正文 |
| content_hash | 块哈希 |
| metadata_json | 类型特有信息 |

### 10.3 正文存储

V1 可以把中小型 TextBlock 正文存入 SQLite。特别大的结构清单可以保存为数据目录文件，但必须：

- 使用相对路径；
- 有哈希和版本；
- 纳入备份；
- 不把临时文件当正式数据；
- 数据库记录仍是权威索引。

技术阶段根据数据库体积测试决定阈值。

## 13. 向量存储边界

### 13.1 Adapter 约束

业务层只依赖：

- upsert embeddings；
- delete by config or scope；
- search；
- health check；
- build version；
- activate version；
- compact；
- close。

不得让页面、对话模块和学习模块直接调用某个向量库 SDK。

### 13.2 本地存储

- 向量文件位于 vectors 目录；
- 目录按 Embedding 配置和索引版本隔离；
- 只保存必要向量与映射；
- 不包含 API Key；
- 回收站对象不参与新检索；
- 索引损坏时可以由 Chunk 与 Embedding 配置重建。

### 13.3 引擎未冻结

本文件不指定 sqlite-vec、LanceDB、Chroma 或其他具体实现。

最终选择需要在 15 文档比较：

- Windows 打包；
- 无服务运行；
- 增量写入；
- 过滤；
- 删除；
- 索引重建；
- 内存占用；
- 依赖体积；
- 许可证；
- 备份恢复。

## 14. 全文搜索模型

### 14.1 FTS5 范围

建立本地全文索引：

- 文件名、摘要和解析正文；
- 知识库名称与描述；
- 对话标题、用户消息和 AI 回答；
- 学习主题、题目、答案、点评和总结。

### 14.2 FTS 内容表

建议使用分域 FTS 表或统一搜索文档表。无论实现方式如何，每个搜索项必须能映射回：

- object_type；
- object_id；
- location_type；
- location_id；
- source_revision；
- deleted 状态。

### 14.3 索引更新

- 业务事务提交后排队索引更新；
- 软删除立即从正常搜索排除；
- 恢复后重建相关条目；
- 索引不一致时支持全量重建；
- FTS 损坏不导致业务数据丢失。

## 22. 事务边界

### 22.1 文件导入提交

同一事务写入：

- ContentObject 引用；
- File；
- 初始任务结果；
- 必要审计事件。

物理文件准备在事务外完成，但正式路径和事务之间使用可恢复协议。

### 22.2 AI 消息

用户消息先落库，再发起 Provider 请求。

AI 完成时同一事务写入：

- 最终消息状态；
- AnswerVersion；
- Citations；
- Token 使用；
- 请求结果。

流式中间内容按节流检查点保存。

### 22.3 学习点评

同一事务写入：

- LearningFeedback；
- Citation；
- Attempt 最终状态；
- MasteryRecord 变化；
- ReviewSchedule 变化；
- 会话进度。

点评失败时不得部分更新掌握度。

### 22.4 索引激活

新索引完全就绪后，同一事务：

- 标记新 IndexVersion READY；
- 更新对象 active_index_version_id；
- 将旧版本标记 RETIRED；
- 更新对象状态。

向量文件本身使用临时目录到正式目录的原子切换。

## 23. 软删除

### 23.1 适用对象

进入回收站：

- 文件；
- 文件夹；
- 知识库；
- 对话；
- 学习记录。

### 23.2 不进入回收站

- 标签；
- 标签关系；
- 已完成任务记录；
- 草稿中的临时空内容；
- 可重建缓存；
- 无引用临时文件。

这些对象删除仍需要遵守相应确认和安全规则。

### 23.3 软删除事务

删除时：

- 设置 deleted_at；
- 设置 purge_after 为 30 天后；
- 记录恢复位置；
- 从正常搜索排除；
- 从 RAG 范围排除；
- 取消或阻塞相关任务；
- 保留关系用于恢复；
- 不立即删除物理文件。

### 23.4 文件夹删除

根据用户选择：

- 文件夹与内容作为同一 deletion_batch 进入回收站；
- 或先移动内容，再删除空文件夹。

批量恢复时优先恢复原层级。原父目录不存在时恢复到默认位置并提示。

## 24. 永久删除与级联

### 24.1 文件

永久删除 File：

- 删除文件标签关系；
- 删除知识库活跃成员关系或保留必要历史墓碑；
- 失效当前解析、Chunk 和 Embedding；
- 删除全文索引；
- 删除无其他 File 引用的 ContentObject；
- 删除无历史需要的解析产物；
- 清理向量引用；
- Citation.file_id 置空并移除 excerpt；
- 保留历史文件名和位置快照。

### 24.2 知识库

永久删除 KnowledgeBase：

- 删除成员关系；
- 删除只属于该知识库的索引版本；
- 不删除 File；
- 不删除仍被其他知识库使用的 Embedding；
- 历史对话与学习保留知识库名称快照。

### 24.3 对话

级联删除：

- Message；
- AnswerVersion；
- ConversationScope；
- ConversationEvent；
- ConversationSummary；
- Draft；
- Conversation 所属 Citation；
- 会话级诊断记录。

不删除文件、知识库和索引。

### 24.4 学习记录

级联删除：

- LearningPlan 与 PlanItem；
- LearningQuestion；
- LearningAttempt；
- LearningFeedback；
- LearningSummary；
- 会话所属 Citation；
- 该会话独有掌握信号。

MasteryRecord 和 ReviewSchedule 需要基于剩余会话重新计算，不能盲目级联全部删除。

### 24.5 标签

标签删除级联 FileTag，不删除 File。

### 24.6 物理清理

- 先在数据库标记待清理；
- 后台任务解析明确对象；
- 再删除文件；
- 成功后提交清理结果；
- 删除失败保留可重试记录；
- 禁止对数据根目录执行宽泛递归删除。

## 25. 引用与删除兼容

### 25.1 引用双重结构

Citation 同时保存：

- 可导航关系；
- 历史显示快照。

这样可以在来源存在时打开原文，在来源永久删除后仍说明原回答曾引用什么位置。

### 25.2 正文最小化

永久删除来源后：

- 不保留完整 Chunk；
- Citation.excerpt 清空；
- 可以保留文件名、标题路径、页码或行号；
- 历史 AI 回答和点评保留；
- 界面标记“来源已永久删除”。

### 25.3 索引重建

新 Chunk ID 不覆盖旧 ID。历史 Citation 继续指向旧版本或通过显式映射迁移。

无法可靠映射时显示定位失效，不伪造新的定位。

## 26. 数据迁移

### 26.1 SchemaMigration

保存：

- version；
- name；
- checksum；
- applied_at；
- app_version；
- status。

迁移文件一旦发布不得修改内容，应创建新的迁移。

### 26.2 启动流程

1. 读取数据库 schema version；
2. 比较应用支持版本；
3. 创建安全备份或恢复点；
4. 执行迁移；
5. 校验外键和关键计数；
6. 更新版本；
7. 启动应用。

### 26.3 迁移失败

- 停止正常写入；
- 保留原数据库和迁移前备份；
- 记录脱敏错误；
- 不继续以不兼容 schema 运行；
- 提供恢复或导出诊断入口；
- 不自动清空重建数据库。

### 26.4 大数据迁移

需要长时间重建索引时：

- 数据库结构迁移与派生索引重建分离；
- 业务数据先保持可读；
- 索引标记 NEEDS_REBUILD；
- 后台任务逐步重建；
- 不在启动界面无限阻塞。

## 27. 完整性检查与修复

### 27.1 启动快速检查

- SQLite quick_check；
- schema version；
- 数据根目录可写；
- ContentObject 抽样存在；
- 活动索引路径存在；
- 未完成任务扫描；
- WAL 状态。

### 27.2 深度检查

用户触发或故障恢复时检查：

- SQLite integrity_check；
- 外键；
- 文件哈希；
- ContentObject 引用计数；
- 孤儿文件；
- Chunk 与解析版本；
- Embedding 映射；
- 索引版本；
- Citation 关系；
- 任务临时目录。

### 27.3 自动修复边界

可以自动：

- 重建 FTS；
- 重建向量索引；
- 重算引用计数；
- 清理过期临时文件；
- 标记缺失文件；
- 恢复中断任务。

不得自动：

- 删除无法识别的用户文件；
- 覆盖损坏数据库；
- 用模型重写历史内容；
- 将来源失效引用指向相似但不同文件；
- 清空全部数据。

## 28. 备份

### 28.1 V1 备份范围

手动全量备份包含：

- 一致性 SQLite 快照；
- 托管 ContentObject；
- 必要解析结构与正文；
- 非秘密配置；
- 备份 manifest；
- 应用版本与 schema 版本。

默认排除：

- API Key；
- WAL 和 SHM 临时文件；
- 可重建预览缓存；
- 任务临时目录；
- 普通日志；
- FTS 索引，可在恢复后重建；
- 向量索引，可选择排除并重建。

### 28.2 备份格式

建议使用单个带版本的备份包，例如：

~~~text
mindmate-backup-YYYYMMDD-HHMM.mindmate-backup
~~~

包内 manifest 至少包含：

- backup_format_version；
- app_version；
- schema_version；
- created_at；
- file_count；
- total_size；
- entry hashes；
- 是否包含向量索引；
- 是否包含解析产物；
- 明确不包含 secrets。

### 28.3 一致性

备份时：

- 暂停冲突写入；
- 执行 WAL checkpoint 或 SQLite 在线备份 API；
- 固定 ContentObject 清单；
- 逐项校验哈希；
- 写入临时备份；
- 完成后原子重命名；
- 失败时删除不完整包或标记 incomplete。

### 28.4 隐私提示

V1 备份包包含用户文件和学习历史，默认视为敏感文件。

如果 V1 未实现可靠的密码加密：

- 明确提示备份未加密；
- 建议保存在受保护磁盘；
- 不上传云端；
- 不在包中包含 API Key。

密码加密备份可列入后续版本，不能自创不安全加密方案。

## 29. 恢复

### 29.1 V1 恢复模式

V1 只支持“完整恢复”，不支持把两个备份合并。

原因：

- 文件、知识库、历史和掌握度关系复杂；
- 合并需要冲突处理；
- 小型个人版优先保证可预测性。

### 29.2 恢复前校验

- 备份格式；
- manifest；
- entry hash；
- schema 兼容性；
- 应用版本要求；
- 可用磁盘空间；
- 数据目录可写；
- 包内路径安全。

### 29.3 恢复流程

1. 停止新任务和 AI 写入；
2. 创建当前数据恢复点；
3. 解包到独立临时目录；
4. 校验数据库与文件；
5. 执行必要迁移；
6. 原子切换数据目录；
7. 重建 FTS；
8. 检查或重建向量索引；
9. 扫描中断任务；
10. 完成后重新打开应用。

### 29.4 恢复失败

- 保持原数据可用；
- 不删除当前数据；
- 清理恢复临时目录；
- 显示失败阶段；
- 保留脱敏诊断；
- 允许重新选择备份。

### 29.5 API Key

备份不包含 API Key。恢复后如果当前系统没有对应安全凭据，ProviderProfile 显示“需要重新配置密钥”。

## 30. 数据导出边界

V1 的备份用于完整恢复，不等同于用户可读导出。

V1 可以提供：

- 单个文件打开或另存；
- 对话复制；
- 学习总结查看。

以下不作为 V1 必需功能：

- 全量对话 Markdown 导出；
- 学习记录 CSV 导出；
- 知识库打包导出；
- 与其他产品互导。

这些能力记录在 17_版本规划与需求待办.md。

## 31. 磁盘空间

### 31.1 导入前

- 检查目标磁盘可用空间；
- 大文件复制前估算；
- 空间不足时不开始或安全失败；
- 不留下假 READY 记录。

### 31.2 索引前

Embedding 与索引任务需要预估临时空间。

空间不足时：

- 保留原文件；
- 停止新索引；
- 清理可重建缓存建议；
- 不自动删除用户业务数据。

### 31.3 存储统计

可以展示：

- 托管原始文件大小；
- 解析数据大小；
- 向量索引大小；
- 缓存大小；
- 回收站大小；
- 备份大小。

V1 不要求复杂存储分析图表。

## 32. 缓存与临时文件

### 32.1 Cache

包括：

- 预览；
- 缩略图；
- UI 临时缓存；
- 可重新下载或生成的模型辅助文件。

清理缓存不能删除业务数据。

### 32.2 Task Temp

- 每个任务独立目录；
- 目录名使用 task_id；
- 保存 owner metadata；
- 任务终态后延迟清理；
- 启动时清理超过期限且无活动任务引用的目录；
- 不根据模糊文件名删除。

### 32.3 Orphan

检测到无数据库记录的物理文件时：

- 先移动到隔离区或标记；
- 进行二次引用检查；
- 记录发现时间；
- 达到安全期限后清理；
- 不立即永久删除。

## 33. 加密与本地隐私

### 33.1 数据库和文件

V1 不要求应用层对整个 SQLite 和托管文件目录加密。

安全边界为：

- 当前操作系统用户账户；
- 文件系统权限；
- 可选的设备磁盘加密；
- 应用仅监听本机；
- 不主动上传文件。

界面需要说明“本地保存”不等于“磁盘自动加密”。

### 33.2 密钥

API Key 必须使用系统安全凭据存储，是 V1 强制要求。

### 33.3 外发

只由 AI 能力层按请求发送最少必要文本。存储层不得自动同步、上传或备份到云端。

## 34. 容量与可扩展性

数据结构至少应能支持个人规模：

- 数千个逻辑文件；
- 数万个对话消息；
- 数万个学习 Attempt；
- 数十万级 Chunk；
- 多个索引版本；
- 数 GB 至数十 GB 的托管文件。

这些是设计量级，不是未经测试的性能承诺。正式容量与响应时间指标在 12_非功能与安全要求.md 定义并通过测试验证。

数据库查询不得依赖一次加载所有记录。

## 35. 数据清理顺序

到期回收站清理按以下顺序：

1. 解析明确待清理对象；
2. 检查恢复状态和 purge_after；
3. 检查引用；
4. 标记 PURGING；
5. 删除或脱敏历史引用正文；
6. 清理关系与派生索引；
7. 清理无引用物理对象；
8. 提交业务删除；
9. 记录清理结果；
10. 失败项进入可重试任务。

用户在清理开始前恢复对象，应取消清理。进入不可逆提交阶段后界面不得再显示可以恢复。

## 36. V1 不做

- 多用户数据库；
- 云数据库；
- 云同步；
- 跨设备实时同步；
- 前端直接访问 SQLite；
- 业务模块直接绑定某个向量 SDK；
- 把 API Key 保存进数据库或明文配置；
- 把 API Key 放入备份；
- 自动上传备份；
- 两个备份的数据合并；
- 无边界保存全部 Provider 原始响应；
- 自动保留用户来源绝对路径；
- 应用自创弱加密算法；
- 依赖来源文件原路径继续运行；
- 永久保留所有旧索引和任务临时文件。

## 37. 验收标准

### DATA-AC-01

结构化业务数据使用 SQLite，全文搜索使用 FTS5，前端不能直接打开数据库。

### DATA-AC-02

SQLite 启用外键和 WAL，长任务不持有跨模型调用或文件处理的长写事务。

### DATA-AC-03

文件导入后复制到应用数据目录，删除或移动来源文件不影响应用内文件。

### DATA-AC-04

相同 SHA-256 内容可以复用一份 ContentObject，同时允许多个独立 File 记录。

### DATA-AC-05

导入中断不会产生指向不存在正式文件的 READY 记录，启动后可以识别孤儿和缺失对象。

### DATA-AC-06

解析、切片、Embedding 和索引都保存版本，兼容条件不满足时不会静默复用。

### DATA-AC-07

新解析或索引只有完整成功后才原子切换为活动版本，失败时旧版本可以继续保留。

### DATA-AC-08

向量业务访问经过 VectorStore Adapter，具体向量引擎可替换，不暴露给页面和业务模块。

### DATA-AC-09

对话和学习的每条引用同时保存可导航关系与历史快照。

### DATA-AC-10

来源永久删除后清除引用正文，但保留文件名和位置说明，并标记来源已删除。

### DATA-AC-11

知识库删除不删除原始文件；逻辑文件删除只有在无其他引用时才清理物理 ContentObject。

### DATA-AC-12

学习点评、掌握度更新和复习计划变更在同一事务完成；点评失败不更新掌握度。

### DATA-AC-13

API Key 不存在于 SQLite、app-config.json、日志、任务参数和备份包中。

### DATA-AC-14

Windows 上 API Key 使用系统安全凭据存储；安全存储不可用时不降级为明文持久化。

### DATA-AC-15

文件、文件夹、知识库、对话和学习记录软删除后设置 30 天 purge_after，并从正常搜索和 RAG 排除。

### DATA-AC-16

标签删除只删除标签关系，不删除文件，也不进入回收站。

### DATA-AC-17

永久删除通过明确对象 ID 和引用检查执行，不使用未经验证的宽泛递归路径。

### DATA-AC-18

数据库迁移具有版本、校验和与迁移前恢复点；迁移失败不会清空数据库或继续以不兼容 schema 运行。

### DATA-AC-19

FTS 和向量索引损坏时可以由权威数据重建，不需要丢弃文件、对话或学习记录。

### DATA-AC-20

手动备份包含一致性数据库快照、托管文件和 manifest，默认不包含 API Key 与普通缓存。

### DATA-AC-21

备份过程中发生失败不会留下被误认成完整备份的文件。

### DATA-AC-22

恢复前验证格式、哈希、schema、磁盘空间和路径安全；失败时保留当前数据。

### DATA-AC-23

V1 恢复采用完整恢复，不尝试合并两个数据集；恢复后缺失的 API Key 需要重新配置。

### DATA-AC-24

任务临时目录和孤儿文件经过引用检查与安全期限后清理，不直接删除无法识别的用户数据。

### DATA-AC-25

数据目录默认位于用户本地应用数据目录，不写入安装目录或代码仓库。

### DATA-AC-26

本地保存说明明确指出 V1 不对整个数据目录自动加密，并建议使用操作系统账户与磁盘加密保护。

## 38. 本部分冻结结论

- V1 使用 SQLite 保存结构化业务数据；
- 本地全文搜索使用 SQLite FTS5；
- SQLite 启用外键、WAL 和事务；
- 前端不直接访问数据库；
- 核心对象使用 UUIDv7；
- 时间以 UTC 毫秒保存，复习同时保存本地日期和时区；
- 导入文件复制到应用数据目录；
- 物理内容按 SHA-256 去重，逻辑文件记录可以独立；
- 默认不保留完整来源绝对路径；
- 解析正文、切片、Embedding 和索引全部版本化；
- 新索引成功后原子切换；
- 向量访问必须经过独立 VectorStore Adapter；
- 具体向量引擎在技术架构阶段确定；
- 原始文件、解析正文、Embedding 和向量默认本地保存；
- FTS、向量索引、预览和缓存属于可重建数据；
- 引用同时保存关系和必要快照；
- 来源永久删除后清除引用正文，但保留定位说明；
- 文件、文件夹、知识库、对话和学习记录进入 30 天回收站；
- 标签删除不进入回收站；
- API Key 使用操作系统安全凭据存储；
- API Key 不进入数据库、配置、日志和备份；
- 迁移失败不清库；
- V1 提供本地手动全量备份和全量恢复；
- 备份默认排除 secrets 与可重建缓存；
- V1 不支持备份合并；
- V1 不对整个数据目录自动加密；
- 存储层不执行任何自动云同步。
