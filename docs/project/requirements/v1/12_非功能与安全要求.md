# 12 非功能与安全要求

## 1. 文档目的

本文档把 MindMate AI V1 的“本地可用、安全可控、长期不丢数据”转化为可开发、可测试、可验收的非功能要求。其约束对象包括前端、本地 API、数据库、文件系统、文档解析、向量索引、AI Provider、安装包和升级流程。

本文档中的 `MUST` 为发布阻塞要求，`SHOULD` 为默认实现要求，`MAY` 为允许但不强制的增强项。

## 2. 适用基线

| 项目 | V1 基线 |
| --- | --- |
| 使用者 | 单用户 |
| 部署 | 用户个人 Windows 电脑，无公网服务器 |
| 正式支持系统 | Windows 11 x64，仍处于 Microsoft 支持期的版本 |
| Windows 10 | 尽力兼容，不作为发布阻塞项 |
| 数据 | 原始文件、数据库、Embedding 和索引默认本地保存 |
| 外部网络 | 仅 AI 生成时访问 DeepSeek API；模型首次下载和手动更新检查除外 |
| 监听地址 | 仅 `127.0.0.1` 或 `::1`，不得绑定局域网或公网地址 |
| 身份模型 | 不做账号、登录、角色和多人权限 |
| 安全边界 | 防止应用自身、恶意文档和网页来源造成泄露；不承诺抵御已控制操作系统的管理员或恶意软件 |

Windows 10 已于 2025-10-14 结束常规支持，因此 V1 以 Windows 11 为正式支持平台。若 Windows 10 用户参加测试，应在启动诊断中显示安全提示，但不得故意阻止运行。

## 3. 质量优先级

出现冲突时按以下优先级处理：

1. 不泄露 API Key 和本地资料；
2. 不丢失已提交数据；
3. 不把未被用户允许的内容发送到外部；
4. 结果可追溯且不伪造引用；
5. 失败可恢复；
6. 核心操作响应清晰；
7. 性能优化；
8. 视觉动效和非必要便利功能。

## 4. 支持环境

### 4.1 正式支持矩阵

| 项目 | 最低环境 | 推荐环境 |
| --- | --- | --- |
| 操作系统 | Windows 11 x64 受支持版本 | Windows 11 当前稳定版 |
| CPU | 4 核 x64 | 6 核及以上 x64 |
| 内存 | 8 GB | 16 GB 及以上 |
| 可用磁盘 | 5 GB＋用户导入数据空间 | SSD，20 GB 以上可用空间 |
| 显示分辨率 | 1280×720 | 1920×1080 |
| 网络 | 仅在 AI 调用和模型下载时需要 | 稳定宽带 |
| GPU | 不要求 | 不要求 |

### 4.2 桌面 Web 运行时

- V1 页面以 Chromium 内核为验收基线；
- 若采用系统浏览器，正式支持当前稳定版 Edge 和 Chrome；
- 若采用 WebView2 桌面壳，安装程序必须检测 Evergreen Runtime；
- 缺少运行时时必须显示可执行的安装或修复指引；
- 不支持 Internet Explorer 模式；
- 不以 Firefox、Safari、移动端浏览器作为 V1 发布门槛。

### 4.3 显示与缩放

- 必须支持 Windows 100%、125%、150% 显示缩放；
- 1280×720 下核心操作不得被永久遮挡；
- 1024 px 以下可进入紧凑布局，但不承诺完整移动端体验；
- 200% 页面缩放下不得出现无法关闭的弹窗或无法提交的表单。

## 5. 安装、启动与卸载

### 5.1 安装

- SHOULD 使用当前用户级安装，正常安装和运行不要求管理员权限；
- MUST 明示应用数据目录和预计模型体积；
- MUST 检查磁盘空间、运行时和数据目录写权限；
- MUST 不修改系统代理、不安装浏览器扩展、不添加不必要的开机启动；
- MUST 不把 API Key、调试密钥或固定端口令牌打入安装包；
- 正式发布包 SHOULD 提供代码签名和 SHA-256 校验值。

### 5.2 启动

- 单用户同一数据目录只允许一个可写实例；
- 重复启动时应聚焦已有窗口或提示“应用已在运行”；
- 后端端口冲突时优先安全选择新的随机可用端口，不得绑定非回环地址；
- 启动失败必须生成不含敏感内容的诊断信息；
- 数据迁移失败时不得进入可写状态。

### 5.3 卸载

- 默认卸载程序只删除应用，不删除用户数据；
- “同时删除全部本地数据”必须单独勾选并二次确认；
- API Key 应从系统凭据存储单独移除；
- 卸载后保留数据时，应告知其位置与清理方式。

## 6. 性能目标

### 6.1 测试口径

性能测试在推荐环境执行 3 轮，取稳定轮次；P95 为 95% 请求不超过目标。外部 Provider 的网络和生成时间单独记录，不混入本地应用开销。

### 6.2 交互与页面

| 编号 | 场景 | 目标 |
| --- | --- | --- |
| NFR-PERF-001 | 冷启动至可操作首页 | 推荐环境 P95 ≤ 8 秒；最低环境 ≤ 15 秒 |
| NFR-PERF-002 | 热启动至可操作首页 | 推荐环境 P95 ≤ 4 秒 |
| NFR-PERF-003 | 点击、输入、选择后的可见反馈 | ≤ 100 ms |
| NFR-PERF-004 | 常规本地 API（非搜索、非任务） | P95 ≤ 300 ms |
| NFR-PERF-005 | 2,000 个文件的分页列表 | P95 ≤ 1 秒 |
| NFR-PERF-006 | 本地全文搜索 | P95 ≤ 2 秒 |
| NFR-PERF-007 | 打开已存在对话或学习记录 | P95 ≤ 2 秒 |
| NFR-PERF-008 | 任务状态刷新或 SSE 推送 | 状态变化后 1 秒内可见 |
| NFR-PERF-009 | 取消可取消任务 | 点击后 2 秒内进入取消中或已取消 |

### 6.3 RAG 与 AI

| 编号 | 场景 | 目标 |
| --- | --- | --- |
| NFR-PERF-010 | 10 万 Chunk 范围内混合检索与重排 | 推荐环境 P95 ≤ 3 秒 |
| NFR-PERF-011 | 本地检索完成至发起 Provider 请求 | P95 ≤ 500 ms |
| NFR-PERF-012 | 收到首个 Token 至页面显示 | P95 ≤ 200 ms |
| NFR-PERF-013 | 流式输出期间 | 页面滚动和停止按钮保持可操作 |
| NFR-PERF-014 | 长任务开始 | 创建任务后 2 秒内显示阶段和进度 |

Provider 首 Token、完整响应时长和限流不设硬性秒数，但必须显示等待状态、允许停止，并在超时后提供可恢复错误。

### 6.4 资源预算

- 无任务空闲 5 分钟后 CPU 平均占用 SHOULD < 2%；
- 未加载 Embedding 模型时进程内存 SHOULD < 600 MB；
- 加载本地 Embedding 模型后总内存 SHOULD < 2 GB；
- 同时最多运行 2 个重任务，其中 Embedding 或向量写入最多 1 个；
- 日志默认总量上限 100 MB；
- 临时文件在任务完成、失败或取消后应清理；
- 磁盘空间不足时停止新写入，不继续生成不完整索引。

## 7. 容量基线

V1 应在下列数据量内保持功能正确：

| 数据 | 验收容量 |
| --- | --- |
| 文件记录 | 2,000 个 |
| 托管原始文件 | 10 GB |
| 单文件 | 最大 50 MB |
| 单次导入 | 最大 20 个、合计最大 500 MB |
| Chunk | 500,000 个 |
| 知识库 | 100 个 |
| 对话 | 2,000 个 |
| 消息 | 50,000 条 |
| 学习会话 | 2,000 个 |
| 学习作答 | 50,000 条 |
| 标签 | 1,000 个 |

容量超出时不得静默损坏数据。应用可以变慢并提示建议拆分、清理或备份，但仍须支持导出、删除和修复。

## 8. 可靠性与数据完整性

### 8.1 已提交数据

- API 返回成功前，关键业务事务必须持久化；
- 已提交的用户消息、作答、文件元数据和知识库成员关系不得因进程退出而丢失；
- 文件复制采用临时文件＋完整性校验＋原子重命名；
- 数据库启用外键、WAL、事务和迁移版本；
- 向量新版本必须构建完成后原子激活；
- 旧索引在新索引成功激活前不得删除。

### 8.2 异常退出

- 启动时检测未正常退出标记；
- 对 SQLite 执行轻量完整性检查；
- 将 `RUNNING` 任务恢复为 `INTERRUPTED` 或按检查点恢复；
- 清理确认无引用的临时文件；
- 不自动重发可能产生费用的 AI 请求；
- 恢复完成前显示只读或修复状态。

### 8.3 恢复目标

| 项目 | 目标 |
| --- | --- |
| 已提交业务数据 RPO | 0 |
| 普通异常退出后的可启动时间 | 推荐环境 60 秒内 |
| 索引损坏 | 可由原文件与 Chunk 重建 |
| Provider 故障 | 本地文件、历史、搜索仍可用 |
| Embedding 模型不可用 | 不丢数据，索引任务阻塞并可重试 |

## 9. 威胁模型

V1 必须考虑：

- 恶意 PDF、DOCX、PPTX 或伪装扩展名；
- 路径穿越、符号链接、硬链接和 Windows reparse point；
- 超大文件、压缩炸弹、解析耗时或内存耗尽；
- Markdown/模型输出中的 XSS、恶意链接和远程图片；
- 本地网页跨站请求、DNS rebinding、恶意站点访问本地 API；
- Prompt Injection 诱导泄露系统提示词、其他资料或执行操作；
- API Key 出现在日志、数据库、备份、崩溃报告或前端；
- Provider 请求过量、重复提交和费用失控；
- 第三方依赖或模型文件被篡改；
- 备份文件被他人读取。

V1 不承诺防御：已获得当前用户权限或管理员权限的恶意软件、内存抓取、被破解的操作系统、用户主动复制并外发的数据。

## 10. 本地 API 防护

### 10.1 网络边界

- MUST 仅监听回环地址；
- MUST 在启动测试中证明局域网 IP 无法访问；
- MUST 校验 `Host`、`Origin` 和 CORS allowlist；
- MUST 拒绝 `null` Origin 和未允许来源的浏览器写请求；
- MUST 防御 DNS rebinding；
- MUST 使用每次启动随机生成的本地会话令牌或等效机制；
- 令牌不得写入 URL、日志或持久数据库；
- 页面和 API 响应涉及敏感信息时使用 `Cache-Control: no-store`。

### 10.2 请求保护

- 所有输入执行类型、长度、枚举和业务校验；
- 上传采用流式读取并在解析前执行大小限制；
- 反序列化不得实例化任意类型；
- SQL 只使用参数化查询；
- 破坏性操作使用资源 ID 和版本校验，不接受任意路径；
- 幂等键和 `request_id` 防止重复 AI 计费与重复导入；
- SSE 连接数、请求体和并发任务必须有限制。

## 11. 前端与内容渲染安全

- 模型回答、文件文本和 Markdown 一律视为不可信输入；
- 禁止使用未经清洗的 `innerHTML`；
- Markdown 渲染器必须禁用脚本、事件属性、iframe、object、embed 和危险 URL scheme；
- 默认不加载模型回答中的远程图片、字体或媒体；
- 外部链接必须显式打开，并使用 `noopener noreferrer`；
- 使用严格 Content Security Policy，禁止 `eval` 和不必要的内联脚本；
- 文件预览失败时回退到安全纯文本或系统打开，不尝试执行内容；
- 前端不得直接获得 API Key、系统提示词、数据库路径或真实托管文件路径。

## 12. 文件导入与解析安全

### 12.1 文件验证

- 同时校验扩展名、MIME 和文件签名；
- V1 只接受 PDF、DOCX、PPTX、TXT、MD；
- 拒绝加密、损坏或无法识别的文件，并给出原因；
- 文件名只作展示，内部使用 UUID 路径；
- 清理控制字符、保留设备名和尾随点空格；
- 不跟随导入路径中的符号链接或 reparse point；
- 不允许路径逃逸托管目录。

### 12.2 解析隔离

- 文档解析器不得执行宏、脚本、公式代码或嵌入对象；
- 不主动请求文档中的外链、远程图片或外部模板；
- 解析任务设置时间、内存、页数和输出文本上限；
- 解析器 SHOULD 在受限子进程运行，崩溃不带走主服务；
- 子进程只获得当前输入和隔离临时目录；
- 解析结束后删除临时文件；
- 单文件失败不得导致同批其他文件回滚。

## 13. Prompt Injection 与 AI 安全

### 13.1 信任边界

系统指令、应用状态、用户问题和检索资料必须用结构化边界分隔。资料中的“忽略之前指令”“上传文件”“执行命令”等文本只作为资料内容，不得提升为系统指令。

### 13.2 强制要求

- V1 AI 不具备 shell、文件写入、网页访问、邮件发送或任意工具执行能力；
- 模型不得选择额外知识库或扩大资料范围；
- 不把 API Key、内部错误堆栈、系统提示词或绝对路径放入模型上下文；
- 引用由服务端依据已检索证据生成并校验，不接受模型虚构的来源 ID；
- 结构化输出必须通过 Schema 校验，失败时有限次数修复或安全降级；
- 知识库证据不足时严格拒答，不切换为通用知识；
- 模型输出中的操作建议不会自动执行；
- 不向用户展示或持久化模型隐藏推理过程，只保存必要回答和可解释摘要。

### 13.3 注入测试集

发布测试至少覆盖：要求泄露系统提示词、要求跨知识库检索、伪造引用、要求执行本地命令、要求读取 API Key、资料中嵌套指令、Markdown 恶意链接和超长注入文本。

## 14. 外发数据与隐私

### 14.1 默认原则

- 原始文件、整个知识库、向量、Embedding、数据库和日志不得发送给 Provider；
- 仅发送当前任务必要的问题、有限对话上下文和选中证据片段；
- 首次使用外部 AI 前必须展示外发说明并记录本地同意版本；
- 未同意、未配置 Key 或离线时，外部 AI 功能保持禁用；
- 不默认启用遥测、广告标识、崩溃自动上传或使用分析；
- 不在后台静默调用 AI；
- 发送前显示当前模式和资料范围；
- 用户删除消息或资料后，不再用于新的 Provider 请求。

### 14.2 敏感数据提示

V1 不做自动数据分级或可靠脱敏。界面必须提示用户：若资料不允许任何片段离开本机，只可使用文件整理、全文搜索和本地检索，不应启用 AI 生成。

## 15. API Key 与凭据

- API Key 必须存入 Windows Credential Manager 或操作系统等效安全凭据存储；
- 数据库只保存 Provider 类型、Key 引用和脱敏后四位；
- 前端只知道“已配置/未配置”，不得读取完整 Key；
- 日志、错误对象、备份、导出和诊断包不得包含 Key；
- Key 输入框默认遮蔽，保存后不可再次明文显示；
- 连接测试在本地后端执行；
- 更换或删除 Key 后，内存中的旧值应尽快清除；
- 正式构建不得存在测试 Key、默认 Key或示例真实 Key。

## 16. Provider 通信安全与费用保护

- 仅允许 HTTPS，并验证证书和主机名；
- 不提供“忽略 TLS 错误”开关；
- Base URL 修改属于高级本地配置，必须校验为 HTTPS；
- 连接、首 Token、空闲流和总请求分别设置超时；
- 对 429、临时 5xx 进行有限指数退避；
- 非幂等失败不无限自动重试；
- 每次请求记录本地估算 Token、真实 usage（若有）、模型和结束原因；
- 支持单次上下文上限、单次输出上限、每日预算提醒和超额阻断；
- 不自动切换 Provider 或模型；
- Provider 返回内容不可信，必须经过同样的渲染与结构校验。

## 17. 本地模型与供应链安全

### 17.1 Embedding 模型

- 模型名称和 revision 固定在配置中；
- 下载后校验文件清单与哈希；
- 优先使用 `safetensors` 或 ONNX，不加载不可信 pickle；
- `trust_remote_code` 必须为 `false`；
- 模型缓存目录与业务数据分离；
- 下载中断不得产生可被加载的半成品；
- 模型升级必须产生新的 `embedding_config_id` 并触发重建，不覆盖旧索引。

### 17.2 依赖

- 前后端依赖必须锁版本并提交 lockfile；
- CI 生成 SBOM 和许可证清单；
- 禁止从任意脚本地址执行安装命令；
- 正式构建必须通过依赖漏洞扫描；
- 存在已知可利用的 Critical 漏洞时阻止发布；High 漏洞需修复或记录明确豁免。

## 18. 数据库、备份与恢复安全

- 数据库连接不暴露网络端口；
- 所有查询参数化；
- 迁移前创建恢复点或备份；
- 迁移失败回到旧版本只读状态，不继续写入；
- 备份不包含 API Key；
- 备份包含 manifest、schema_version 和 SHA-256 校验；
- 恢复在隔离临时目录完成校验后原子切换；
- 禁止备份路径穿越与覆盖应用目录外任意文件；
- 普通备份默认不加密时必须显示“备份含私人资料”的提示；
- V1 不声称实现静态数据加密，建议用户使用 BitLocker 或受保护磁盘。

## 19. 日志与诊断

### 19.1 允许记录

- 时间、级别、模块、事件码、request_id、task_id；
- 状态码、耗时、重试次数、Token 数、文件大小和计数；
- 脱敏 Provider、模型和错误分类；
- 不含正文的对象 ID。

### 19.2 禁止记录

- API Key 和 Authorization；
- 用户问题、模型完整回答、文档正文和 Chunk；
- 未脱敏文件绝对路径；
- Cookie、本地会话令牌；
- 系统提示词和结构化模型原始响应；
- 备份内容。

### 19.3 保留

- 默认滚动保留 30 天或 100 MB，先达到者生效；
- 用户可以清除日志；
- 诊断包必须在本地生成、预览内容并由用户主动导出；
- 不自动上传诊断或崩溃报告。

## 20. 可用性与无障碍

V1 以 WCAG 2.2 AA 相关桌面 Web 要求为目标：

- 所有主要功能可仅用键盘完成；
- 不存在键盘陷阱；
- 焦点顺序与视觉顺序一致且清晰可见；
- 表单字段有可读标签和错误关联；
- 不仅依赖颜色表达状态；
- 正文和关键控件达到 AA 对比度；
- 支持 200% 缩放和文本换行；
- 动画尊重 `prefers-reduced-motion`；
- 任务进度、Toast 和流式完成状态通过 ARIA live 适度播报；
- 图标按钮必须有无障碍名称；
- 弹窗打开后聚焦，关闭后焦点回到触发控件。

## 21. 可维护性与可测试性

- 领域层不得依赖 UI、数据库驱动或 DeepSeek SDK；
- Provider、Embedding、VectorStore、Parser 和 CredentialStore 均通过 Adapter；
- OpenAPI 是前后端契约来源；
- 数据库变更只通过迁移；
- Prompt 有版本号和回归样例；
- 关键状态机和费用规则必须有单元测试；
- 关键模块语句覆盖率目标 ≥ 80%，安全与数据迁移关键路径 ≥ 90%；
- 时间、UUID、Provider、文件系统和任务调度可注入替身；
- 测试不得调用真实付费 API，真实 API 仅用于显式标记的手动冒烟测试。

## 22. 发布质量门禁

以下任一情况阻止发布：

1. 服务可从局域网访问；
2. API Key 出现在前端、日志、数据库或备份；
3. 已提交数据在崩溃测试中丢失；
4. 路径穿越、任意文件读取或任意命令执行；
5. 恶意 Markdown 可执行脚本；
6. Prompt Injection 能扩大资料范围、泄露 Key 或触发工具执行；
7. 引用指向未检索资料或错误位置；
8. 迁移失败仍继续写入；
9. 备份恢复无法通过校验；
10. 存在未处置的可利用 Critical 依赖漏洞；
11. OpenAPI 契约测试或核心 E2E 失败；
12. Windows 11 推荐环境无法完成安装、首次启动和卸载。

## 25. 验收标准

- NFR-ACC-001：Windows 11 x64 推荐环境可完成安装、首次启动、配置 Key、导入、问答、学习、备份和卸载；

- NFR-ACC-004：异常结束后已提交数据无丢失，未完成任务状态可解释；
- NFR-ACC-005：局域网、跨站请求、路径穿越和恶意 Markdown 测试全部通过；
- NFR-ACC-006：Key 不出现在前端、数据库、日志、备份和诊断包；
- NFR-ACC-007：未经同意或离线时不产生 Provider 请求；

- NFR-ACC-009：Prompt Injection 不能扩大范围、泄露秘密或自动执行操作；
- NFR-ACC-010：键盘操作、焦点、对比度和 200% 缩放通过核心页面检查；
- NFR-ACC-011：备份校验、完整恢复和迁移失败保护通过；
- NFR-ACC-012：发布门禁无未关闭阻塞项。

## 26. 本部分冻结结论

V1 正式支持 Windows 11 x64，以本地优先、回环监听、最小外发、操作系统凭据存储、安全解析和无工具执行为安全边界。性能以个人电脑和单用户容量为目标，不引入服务器级高可用设计。Windows 10 仅尽力兼容；全盘加密、企业 DLP、多人权限和完全离线大模型不进入 V1。
