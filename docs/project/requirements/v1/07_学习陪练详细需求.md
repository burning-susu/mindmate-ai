# 07 学习陪练详细需求

## 1. 文档目的

本文档定义 MindMate AI V1 学习陪练的学习目标、开始学习配置、学习计划、讲解、逐题训练、难度调整、提示、作答、点评、重试、掌握度、间隔复习、暂停恢复、结束总结和异常处理规则。

学习陪练是 V1 的产品重心。文件管理、知识库、RAG 和 AI 对话均为该模块提供基础能力。

本模块的资料检索、证据阈值、引用定位、资料冲突和严格拒答统一复用 05_知识库与RAG详细需求.md，不得另建行为不一致的检索管线。

## 2. 本轮决策基线

本轮没有收到用户对三个选项的单独选择，因此为避免需求阶段继续阻塞，先采用推荐方案作为开发基线。进入最终总冻结前仍可修改；正式开发后变更需要评估学习记录与复习数据迁移。

| 决策项 | 当前基线 |
| --- | --- |
| 默认学习流程 | 先讲解，再练习，最后总结 |
| 难度变化 | 根据连续答题表现自动调整，并允许用户手动修改 |
| 复习节奏 | 简化间隔复习：1、3、7、14、30 天，并按表现调整 |
| 核心学习目标 | 理解与记忆兼顾 |
| 训练形式 | 一次只展示一道题，提交后点评，再进入下一题 |
| 资料边界 | 出题、参考答案和知识性点评必须基于当前资料 |
| 保存位置 | 学习计划、作答、点评、掌握度与复习计划默认保存在本地 |

## 3. 产品目标

学习陪练应帮助个人用户完成以下闭环：

1. 选择学习资料；
2. 明确学习主题和目标；
3. 获得基于资料的简短讲解；
4. 一次回答一道题；
5. 获得有依据的点评和解释；
6. 对薄弱点重试或获得提示；
7. 根据表现调整后续题目；
8. 主动结束或完成计划；
9. 查看本次总结与下一次复习安排；
10. 中断后继续学习。

V1 的重点是形成可靠的小型个人学习闭环，不追求课程平台、考试系统或复杂教务功能。

## 4. 核心原则

### 4.1 学习优先

界面应优先呈现当前知识点、当前题目和下一步动作，避免被文件管理、模型参数和内部检索细节打断。

### 4.2 一题一反馈

默认一次展示一道题。用户提交后先获得点评，再决定重试、提问或进入下一题。

### 4.3 先理解后记忆

默认流程先提供不直接泄露全部答案的主题概览，再通过主动回忆、解释和应用题检查理解与记忆。

### 4.4 资料可追溯

出题依据、参考答案和知识性点评都必须能够定位到当前资料。

### 4.5 不伪装掌握

掌握度只代表应用内部基于有限练习得到的学习信号，不等同于真实考试成绩或专业认证。

### 4.6 用户可控

用户可以暂停、结束、重试、请求提示、调整难度和查看依据。系统不得为了完成计划强迫用户继续。

## 5. 页面与入口

### 5.1 学习首页

建议路径：/learning

展示：

- 今日待复习数量；
- 继续学习主卡片；
- 开始新的学习；
- 最近学习记录；
- 最近学习主题；
- 需要复习的知识点摘要；
- 进入学习历史的入口。

“继续学习”优先级高于“开始新的学习”。没有历史记录时展示引导空状态。

### 5.2 开始学习

建议路径：/learning/new

由于需要选择资料、主题、目标、题量和难度，V1 使用独立开始页面，不塞入小型弹窗。

页面采用一个短表单或分步区域，避免复杂向导。用户可以在提交前返回修改所有选项。

### 5.3 学习会话

建议路径：/learning/session/:id

这是 V1 核心页面，包含：

- 学习主题和进度；
- 当前资料范围；
- 讲解卡；
- 当前题目；
- 作答区；
- AI 点评；
- 引用；
- 提示、重试、下一题、暂停和结束操作。

### 5.4 学习总结

建议路径：/learning/session/:id/summary

展示本次概览、题目表现、知识点掌握状态、薄弱点、资料引用、下次复习日期和继续操作。

### 5.5 其他入口

用户还可以从以下位置开始学习：

- 首页快捷操作；
- 首页继续学习卡片；
- 知识库详情的“基于此知识库学习”；
- 文件详情的“学习此文件”；
- 学习历史；
- 学习总结的“重新练习薄弱点”。

## 6. 开始学习配置

### 6.1 必填项

开始学习至少需要：

- 有效资料范围；
- 学习主题；
- 学习目标或目标类型；
- 题量；
- 初始难度。

### 6.2 资料范围

支持以下互斥范围：

- 一个知识库；
- 一个或多个已完成兼容 RAG 索引的文件。

文件范围建议最多 10 个文件。超过时引导创建知识库。

文件必须满足：

- 不在回收站；
- 文本解析成功；
- RAG 索引可用；
- 版本兼容；
- 用户当前可以打开。

尚未索引的文件不能直接进入学习会话，应引导加入知识库。学习模块不得暗中创建另一套临时索引。

### 6.3 学习主题

用户可以：

- 手动输入主题；
- 从知识库目录或候选知识点中选择；
- 使用整个资料范围，由系统生成主题建议。

主题必填，建议长度 1～200 个字符。系统生成的主题只是建议，用户可编辑。

### 6.4 学习目标

V1 提供三个目标倾向：

- 理解与记忆，默认；
- 理解优先；
- 记忆优先。

三者共享同一学习流程，只改变题型比例、讲解深度和复习权重，不产生三套独立功能。

用户可以补充自由文本目标，例如：

- 理解第三章的核心概念；
- 记住术语与定义；
- 为明天的面试做准备；
- 能用自己的话解释流程。

### 6.5 题量

V1 提供：

- 5 题；
- 10 题，默认；
- 15 题；
- 自定义 1～30 题。

题量是计划目标，不是强制结束条件。资料不足时可以提前结束，用户也可以随时结束。

### 6.6 初始难度

提供：

- 基础；
- 标准，默认；
- 进阶。

难度含义：

| 难度 | 主要要求 |
| --- | --- |
| 基础 | 识别、回忆定义、单一事实和直接关系 |
| 标准 | 用自己的话解释、比较、归纳和简单应用 |
| 进阶 | 多来源综合、条件变化、案例应用和辨析 |

进阶题仍必须由资料支撑，不能通过引入资料之外的专业知识制造难度。

### 6.7 可选项

可以提供：

- 题型偏好；
- 是否优先复习历史薄弱点；
- 是否显示预估学习时长；
- 备注。

V1 默认折叠可选项，避免首次使用过于复杂。

## 7. 创建学习会话

### 7.1 创建前校验

系统检查：

- 资料范围是否存在；
- 至少一个文件是否可用；
- 索引版本是否兼容；
- 学习主题是否可以在资料中找到相关证据；
- 计划题量是否可能由资料支持；
- Provider 是否已配置。

### 7.2 主题证据检查

如果主题与资料几乎无关：

- 不直接创建空洞的学习计划；
- 提示“当前资料中没有找到足够的主题内容”；
- 推荐修改主题、扩大范围或补充资料；
- 不使用模型通用知识生成课程。

如果资料只能支撑少量题目：

- 显示可支持的大致范围；
- 允许用户降低题量后开始；
- 或按原题量开始，但明确可能提前结束。

### 7.3 延迟创建

打开开始学习页面不创建会话。

用户提交有效配置并进入准备阶段后创建学习会话。即使准备失败，也保留可重试的失败记录，避免配置丢失。

## 8. 学习会话状态

| 状态 | 含义 |
| --- | --- |
| PREPARING | 正在检查资料并生成学习计划 |
| READY | 计划已就绪，尚未正式开始 |
| IN_PROGRESS | 正在学习 |
| PAUSED | 用户主动暂停 |
| INTERRUPTED | 应用异常关闭或生成中断 |
| COMPLETED | 已完成计划或用户结束并生成总结 |
| SOURCE_INVALID | 资料范围失效，不能继续生成 |
| FAILED | 准备或关键处理失败 |
| IN_TRASH | 学习记录进入回收站 |

状态变化必须持久化，应用重启后不能把所有未完成会话当作已完成。

## 9. 学习计划

### 9.1 计划内容

学习计划至少包含：

- 学习主题；
- 学习目标；
- 资料范围快照；
- 计划知识点；
- 知识点之间的建议顺序；
- 目标题量；
- 初始难度；
- 题型组合；
- 已存在的历史薄弱点；
- 计划版本；
- 生成依据。

### 9.2 生成规则

计划应先从资料中识别可学习的知识点，再安排讲解和题目。

不得：

- 只根据文件名猜测知识点；
- 使用未选资料；
- 把目录标题直接当作全部学习内容；
- 生成资料中没有参考答案的问题；
- 为凑题量重复改写同一问题。

### 9.3 计划可见性

用户开始前看到简化计划：

- 将学习哪些知识点；
- 预计题量；
- 初始难度；
- 预计时间，仅作为估计；
- 资料可用情况。

V1 不要求用户逐项编辑完整计划，但允许返回修改主题、目标、题量和难度。

### 9.4 计划动态调整

系统可以根据作答结果调整：

- 后续知识点顺序；
- 同一知识点的题目数量；
- 难度；
- 题型；
- 是否插入补充讲解；
- 是否安排重试。

调整不得改变用户选定的资料范围和总体目标。

## 10. 默认学习流程

~~~mermaid
flowchart TD
    A["选择资料与目标"] --> B["生成学习计划"]
    B --> C["主题概览与讲解"]
    C --> D["逐题作答"]
    D --> E["点评与引用"]
    E --> F{"继续学习？"}
    F -->|重试或下一题| D
    F -->|结束| G["总结与复习计划"]
~~~

### 10.1 主题概览

正式出题前展示简短主题概览：

- 本次目标；
- 关键知识点；
- 学习顺序；
- 必要前置概念；
- 资料范围。

概览应帮助建立理解框架，但不能直接展示所有待考题的完整答案。

### 10.2 知识点讲解

每个知识点第一次进入时，可以先显示简短讲解：

- 核心概念；
- 关键关系；
- 一个资料内例子；
- 可点击引用。

讲解长度应适合阅读，不把整段资料复制到页面。用户可以展开“查看更多依据”。

### 10.3 逐题训练

每次只展示当前题。提交后才能进入点评状态。

用户未作答时，参考答案、判定标准和直接揭示答案的引用片段默认隐藏。

### 10.4 结束总结

达到计划题量、资料不足或用户主动结束后进入总结。

## 11. 题型

### 11.1 V1 支持题型

| 题型 | 主要用途 |
| --- | --- |
| 简答题 | 主动回忆事实、概念和关系 |
| 自我解释题 | 检查是否真正理解，要求用自己的话说明 |
| 单项选择题 | 快速辨析相近概念 |
| 判断题 | 检查关键边界和常见误解 |
| 填空题 | 记忆术语、步骤、名称或数值 |
| 简单应用题 | 在资料支持范围内应用规则或流程 |

### 11.2 默认题型比例

理解与记忆模式的初始建议：

- 简答与自我解释约 50%；
- 单选与判断约 25%；
- 填空约 15%；
- 简单应用约 10%。

比例是生成目标，不要求每个小会话精确满足。

理解优先时增加自我解释和应用题；记忆优先时增加简答、填空和快速判断。

### 11.3 题目结构

每道题至少保存：

- question_id；
- knowledge_point_id；
- 题型；
- 题干；
- 选项，如适用；
- 当前难度；
- 参考答案；
- 可接受要点；
- 判定规则；
- 出题依据；
- 引用映射；
- Prompt 版本；
- 生成时间；
- 资料和索引版本。

参考答案、判定规则和依据在用户提交前不得发送到不必要的前端可见字段。

### 11.4 出题质量

题目必须：

- 表意清楚；
- 在当前资料中存在可验证答案；
- 与学习主题相关；
- 难度符合定义；
- 不依赖用户无法看到的隐含背景；
- 不把资料中的错误指令当成出题要求；
- 避免答案直接出现在题干；
- 避免只有措辞差异的重复题。

### 11.5 语义去重

系统需要比较本次会话已出题目，避免：

- 相同问题只替换少量同义词；
- 同一事实连续重复；
- 选择题和判断题实际考查完全相同内容；
- 用户已经稳定掌握的简单问题反复出现。

为了间隔复习，可以在不同日期以不同题型再次考查同一知识点，但应记录为复习而不是新知识点。

## 12. 作答

### 12.1 作答方式

- 简答、自我解释、填空和应用题使用文本输入；
- 单项选择题选择一个选项；
- 判断题选择正确或错误；
- V1 不要求语音输入、手写识别或图片作答。

### 12.2 提交规则

- 空答案不可提交；
- 文本题支持多行；
- 输入法候选确认期间 Enter 不提交；
- 文本题默认使用 Ctrl+Enter 或明确按钮提交，避免长回答误发送；
- 选择题选择后仍需点击提交，避免误触直接判分；
- 提交后原答案保留。

### 12.3 作答草稿

- 当前题未提交答案自动保存在本地；
- 刷新、暂停或切换页面后可恢复；
- 提交后清空该题草稿；
- 同一会话只保留当前未提交题目的草稿。

### 12.4 提交后的锁定

答案提交后进入点评流程，原答案不可直接覆盖。

用户选择重试时创建新的 Attempt，不修改前一次作答。所有尝试均保留，便于正确计算学习过程。

## 13. 提示

### 13.1 提示层级

每题最多提供三级提示：

1. 方向提示：提醒关注哪个概念，不泄露答案；
2. 结构提示：给出回答框架、步骤或部分条件；
3. 接近答案提示：提供关键要点，但仍要求用户完成回答。

用户也可以选择“直接看答案”，该操作视为本题未独立掌握。

### 13.2 提示依据

提示必须基于当前题的资料依据，不使用范围外知识补充。

### 13.3 提示对掌握度的影响

- 无提示独立答对是最强正向信号；
- 使用方向提示后答对仍计为成功，但信号较弱；
- 使用结构或接近答案提示后答对不直接判定为已掌握；
- 直接看答案不记为答对；
- 提示次数和层级完整保存。

## 14. 点评

### 14.1 点评结果

每次作答使用以下结果之一：

- CORRECT：正确；
- PARTIAL：部分正确；
- INCORRECT：错误；
- UNGRADABLE：无法可靠判断。

不得为了鼓励用户而把明显错误判为正确。

### 14.2 点评内容

点评至少包含：

- 结果；
- 做得好的要点；
- 缺失或错误的要点；
- 简短参考解释；
- 可点击引用；
- 下一步建议。

点评应针对用户实际答案，不只重复参考答案。

### 14.3 评分依据

系统比较：

- 题目要求；
- 用户答案；
- 可接受要点；
- 资料证据；
- 题目难度；
- 是否使用提示；
- 是否为重试。

模型不得仅凭关键词命中判定复杂答案，也不得用资料之外的观点否定用户。

### 14.4 无法可靠判断

出现以下情况时可判为 UNGRADABLE：

- 资料本身冲突且题目没有唯一结论；
- 用户答案过于含糊；
- 题目生成有歧义；
- Provider 输出不符合判定结构；
- 引用或证据无法验证。

此时：

- 不更新掌握度；
- 说明无法判定原因；
- 允许重新表述答案；
- 允许跳过并将题目标记为需复核；
- 必要时废弃问题并生成替代题。

### 14.5 点评引用

事实性点评和参考解释必须引用资料。

点击引用打开来源抽屉，展示文件名、标题路径、页码或行号、片段及必要上下文。

## 15. 重试与跳过

### 15.1 重试

点评后用户可以重试当前题。

重试规则：

- 保留首次答案与点评；
- 默认不给出完整参考答案后再要求同题原样重试；
- 如果已经显示完整答案，重试应更换问法或延后再次考查；
- 同一道题建议最多即时重试 2 次；
- 超过后建议进入下一题并安排后续复习；
- 所有 Attempt 都保存。

### 15.2 跳过

用户可以跳过当前题：

- 记录 SKIPPED；
- 可以选择查看答案；
- 跳过不记为正确；
- 该知识点进入需要复习；
- 后续可用更基础问题再次检查。

### 15.3 追问

点评后提供“我不理解”或“继续解释”的追问入口。

追问属于当前题解释，不计为新的答题 Attempt。解释必须基于资料并带引用。

用户结束追问后返回当前题操作区，可选择重试或下一题。

## 16. 难度调整

### 16.1 自动调整

系统根据最近表现调整后续题目，不改变已经生成并展示的当前题。

初始规则：

- 同一知识点连续 2 次独立答对，可提高一级；
- 连续 2 次错误或部分正确，降低一级；
- 频繁使用二级或三级提示时保持或降低难度；
- 重试后答对不立即提高难度；
- 单次结果不跨越两个难度等级；
- 难度范围始终为基础、标准、进阶。

### 16.2 用户手动调整

用户可以在会话菜单中选择：

- 简单一点；
- 保持当前；
- 难一点。

手动设置至少影响接下来 2 道题。系统不得在下一题立即反向覆盖用户选择，除非资料无法支持该难度，并需说明原因。

### 16.3 难度不是冷门程度

提高难度应通过：

- 增加解释深度；
- 要求比较或归纳；
- 引入资料内案例；
- 合并多个已学知识点；
- 减少提示。

不得通过选择资料中的边缘句子、模糊措辞或未定义术语制造困难。

## 17. 掌握度

### 17.1 记录粒度

掌握度以“资料版本范围内的知识点”为主要粒度，不只按整份文件或整次会话统计。

同名知识点在不同知识库中如果证据和含义明显不同，不应强行合并。

### 17.2 掌握状态

| 状态 | 含义 |
| --- | --- |
| NEW | 尚未作答 |
| LEARNING | 已练习但表现不足或不稳定 |
| FAMILIAR | 能较稳定地独立回答，但延迟复习证据不足 |
| MASTERED | 在至少两次延迟复习中独立答对，且其中一次间隔不少于 7 天 |
| NEEDS_REVIEW | 曾经熟悉或掌握，但最近复习失败或逾期 |

### 17.3 作答信号

每次 Attempt 形成四级学习信号：

| 信号 | 条件 |
| --- | --- |
| 3 | 无提示独立答对 |
| 2 | 使用轻提示后答对，或重试后答对 |
| 1 | 部分正确 |
| 0 | 错误、跳过或直接看答案 |

UNGRADABLE 不产生信号。

### 17.4 状态变化原则

- 一次答对不能直接成为 MASTERED；
- 重试答对表明当前已理解，但不等于长期记住；
- 多次同日重复的信号不能代替延迟复习；
- 难题答对是更强信号，但不能跳过延迟复习条件；
- 错题不会永久锁定低状态；
- 用户可以查看状态依据；
- 用户可以手动标记“我仍不熟悉”，但不能手动伪造系统评价为已掌握。

### 17.5 展示方式

界面显示状态文字和简短原因，例如：

- 学习中：本次部分正确；
- 熟悉：两次独立答对，待延迟复习；
- 需要复习：7 天复习未通过。

避免只显示缺少解释的百分比。

如果需要整体进度百分比，只作为汇总展示，并可查看状态分布。

## 18. 简化间隔复习

### 18.1 复习阶梯

V1 使用五级复习间隔：

1. 1 天；
2. 3 天；
3. 7 天；
4. 14 天；
5. 30 天。

该规则是轻量个人学习安排，不是完整的记忆科学预测模型。

### 18.2 调整规则

- 无提示独立答对：进入下一级；
- 使用一级提示后答对：保持当前级，下一次间隔不延长；
- 使用二级或三级提示、重试后答对：回到或保持较短间隔；
- 部分正确：降低一级，最低回到 1 天；
- 错误、跳过或直接看答案：回到 1 天；
- 连续在 30 天级别成功：保持 30 天周期；
- 用户主动标记不熟悉：回到 1 天。

### 18.3 到期时间

复习到期日按用户本地日期计算。

V1 只在应用内显示到期提醒：

- 学习首页“今日待复习”；
- 首页继续学习卡片；
- 学习总结；
- 学习历史。

V1 不要求操作系统通知、邮件或云端推送。

### 18.4 逾期

逾期本身不自动判定为忘记，但状态可以显示 NEEDS_REVIEW。

逾期后完成复习时根据实际表现调整，不因逾期天数直接惩罚用户。

### 18.5 复习题生成

复习题应：

- 考查同一知识点；
- 尽量更换题型或问法；
- 仍使用当前可用资料验证；
- 避免只要求识别上一次答案；
- 记录与原知识点和旧 Attempt 的关系。

## 19. 下一题选择

系统综合以下因素选择下一题：

- 学习计划顺序；
- 当前知识点是否已完成最低练习；
- 最近答题表现；
- 提示和重试情况；
- 历史薄弱点；
- 到期复习项；
- 题型重复；
- 当前难度；
- 剩余题量；
- 资料证据可用性。

初始优先顺序：

1. 当前知识点必要的补救题；
2. 学习计划中的下一个知识点；
3. 本次主题下到期复习的薄弱点；
4. 综合应用题；
5. 结束总结。

系统必须记录选择原因，便于调试，但界面只需显示简短说明，例如“巩固刚才答错的概念”。

## 20. 资料范围与版本

### 20.1 会话范围固定

学习会话创建后资料范围默认固定，避免中途更换资料导致计划、答案和掌握度失去一致性。

这与 AI 对话允许留痕切换范围不同。学习会话如需更换资料，应结束当前会话并基于新范围创建新会话。

### 20.2 历史快照

每个计划、问题、点评和引用保存：

- 资料范围；
- 文件版本；
- 索引版本；
- Prompt 版本；
- Provider 与模型标识。

不得保存 API Key。

### 20.3 资料变化

如果会话进行中发生：

- 知识库进入回收站；
- 文件进入回收站；
- 文件永久删除；
- 索引失效；
- 知识库成员关系变化；
- 不兼容重建；

则：

- 已有题目、答案和点评仍可查看；
- 不继续生成新题；
- 会话进入 SOURCE_INVALID；
- 显示具体失效原因；
- 提供恢复资料、结束会话或基于新范围重新开始；
- 不静默切换到剩余资料。

### 20.4 文件恢复

资料恢复后检查：

- 原文件 ID 与版本；
- 知识库成员关系；
- 索引兼容性；
- 引用定位。

全部有效时允许继续；否则要求重建索引或创建新会话。

## 21. 严格基于资料

### 21.1 出题

每道题必须先取得足够证据，才能生成题干、参考答案和判定要点。

不能先由模型自由出题，再事后寻找勉强匹配的引用。

### 21.2 讲解

主题概览、知识点讲解和追问解释中的事实性结论必须有资料依据。

### 21.3 点评

对用户答案的知识性判断必须依据：

- 当前问题的证据；
- 必要时重新检索的补充证据；
- 明确的可接受要点。

### 21.4 资料不足

资料不足时：

- 停止生成该题；
- 尝试本主题下其他有依据的知识点；
- 没有足够内容时提前结束；
- 总结中说明因资料不足实际完成题数少于计划；
- 不使用模型通用知识凑题。

### 21.5 资料冲突

资料存在冲突时：

- 不生成只有一个正确答案却未声明前提的题；
- 可以生成“不同来源分别如何表述”的比较题；
- 点评时分别引用不同来源；
- 不擅自判定某份资料绝对正确；
- 无法公平评分时判为 UNGRADABLE 并替换题目。

## 22. 引用

### 22.1 展示时机

- 主题讲解直接展示引用；
- 题目出题依据在提交前隐藏，避免泄露答案；
- 提交后在点评和参考解释中展示引用；
- 学习总结展示关键知识点引用；
- 用户可随时查看当前资料范围，但不能在答题前直接看到隐藏答案片段。

### 22.2 引用结构

复用 05 文档定义的引用结构，至少包含：

- 文件 ID 与文件名；
- chunk ID；
- 标题路径；
- 页码、幻灯片或行号；
- 引用片段；
- 文件和索引版本；
- 来源状态。

### 22.3 引用失效

历史学习记录保留引用元数据。来源进入回收站或永久删除后的展示遵循 05 文档，不保留用户已永久删除的正文副本。

## 23. 学习会话交互

### 23.1 页面头部

展示：

- 学习主题；
- 当前状态；
- 已完成题数和计划题量；
- 当前知识点；
- 当前难度；
- 资料范围；
- 暂停；
- 结束学习；
- 更多操作。

### 23.2 主区域

根据阶段展示：

- 讲解卡；
- 当前题目；
- 作答区；
- 提示；
- 点评；
- 引用；
- 重试和下一题。

### 23.3 进度

进度以“已完成题数／目标题量”为主，同时显示当前知识点。

资料不足或用户提前结束时，进度不强制变为 100%，总结应区分“计划完成”和“主动结束”。

### 23.4 防止误离开

存在未提交答案时离开：

- 自动保存草稿；
- 可直接离开，不弹出阻断性确认；
- 返回后恢复。

AI 正在生成题目或点评时离开：

- 请求可以在本地后台继续；
- 如果应用关闭导致中断，恢复为 INTERRUPTED；
- 不重复生成同一业务步骤。

## 24. 暂停、继续与结束

### 24.1 暂停

用户点击暂停后：

- 保存当前状态和草稿；
- 停止继续自动生成；
- 会话状态变为 PAUSED；
- 返回学习首页；
- 首页显示“继续学习”。

### 24.2 继续

继续时恢复：

- 当前知识点；
- 当前题目；
- 未提交草稿；
- 已使用提示；
- 最近点评；
- 计划和进度；
- 资料有效性检查。

### 24.3 主动结束

结束学习前显示确认：

- 已完成题数；
- 未完成计划；
- 当前草稿不会作为答案提交；
- 将生成本次总结。

确认后：

- 保存当前进度；
- 未提交题目标记为未完成，不记为错误；
- 生成总结；
- 会话状态变为 COMPLETED，结束原因为 USER_ENDED。

### 24.4 自动结束

以下情况自动进入总结：

- 达到目标题量；
- 计划知识点已完成且没有必要继续；
- 资料不足以继续出题；
- Provider 多次失败后用户选择结束。

自动结束必须显示原因。

## 25. 学习总结

### 25.1 总结内容

至少包含：

- 学习主题和目标；
- 使用的资料范围；
- 开始与结束时间；
- 结束原因；
- 计划题量与实际完成题量；
- 正确、部分正确、错误、跳过和无法判定数量；
- 使用提示和重试情况；
- 已练习知识点；
- 表现较好的知识点；
- 需要复习的知识点；
- 掌握状态变化；
- 下一次复习日期；
- 关键引用；
- 推荐下一步。

### 25.2 总结生成

结构化统计在本地计算，不能依赖模型猜测。

AI 只负责把已有结构化结果整理成易读说明。AI 总结失败时仍展示统计、知识点状态和复习计划。

### 25.3 重新学习

总结页提供：

- 复习薄弱点；
- 按相同主题重新学习；
- 调整难度后重新学习；
- 返回学习首页；
- 查看完整题目记录。

重新学习创建新会话，并引用原会话 ID，不覆盖原记录。

### 25.4 不设独立错题本

V1 不建立一级导航或独立模块“错题本”。

错误、部分正确、跳过和使用较强提示的题目统一通过：

- 学习总结；
- 需要复习知识点；
- 学习历史；
- 今日待复习；

进行查看和再次训练。

## 26. 学习历史

学习记录至少展示：

- 主题；
- 资料范围；
- 状态；
- 目标类型；
- 已完成题数；
- 知识点数量；
- 最近学习时间；
- 下次复习日期；
- 结束原因；
- 资料是否失效。

支持按标题和学习内容搜索，点击后：

- 未完成会话进入学习会话；
- 已完成会话进入总结；
- 资料失效会话先显示问题说明。

完整历史页面和后台任务的统一行为在 08_历史记录与后台任务.md 中进一步定义。

## 27. 删除与回收站

### 27.1 删除学习记录

删除前需要确认。删除后：

- 会话、作答和总结进入回收站；
- 从学习首页、正常历史和待复习列表隐藏；
- 保留 30 天；
- 不影响文件、知识库和索引；
- 不影响独立 AI 对话。

### 27.2 恢复

恢复后：

- 恢复原学习记录；
- 恢复题目、Attempt、点评和总结；
- 恢复复习项；
- 重新检查资料和引用状态；
- 不自动重新生成任何 AI 内容。

### 27.3 永久删除

永久删除清理：

- 学习会话；
- 计划；
- 题目；
- Attempt；
- 点评；
- 会话总结；
- 会话产生的掌握信号；
- 仅由该会话创建且没有其他记录依赖的复习项。

如果同一知识点还有其他学习记录，重新计算其剩余掌握状态，不直接删除全部历史结果。

## 28. Provider 与调用边界

学习陪练通过本地后端的统一 Chat Adapter 调用模型。

允许发送：

- 当前学习目标；
- 当前题目或待生成步骤；
- 必要的近期学习上下文；
- 重排后的最少必要资料片段；
- 用户当前答案；
- 结构化输出约束；
- 引用所需的脱敏定位信息。

不得发送：

- 整个知识库；
- 无关历史记录；
- 本地绝对路径；
- API Key；
- 用户未选择的资料；
- 回收站正文；
- 其他会话的私人内容；
- 完整内部数据库。

Provider 原始响应需要经过结构校验后才能保存为题目或点评。

V1 不自动跨 Provider 切换。失败后提供重试或结束，不静默将资料发送到其他服务。

## 29. 结构化输出校验

### 29.1 题目校验

生成结果必须校验：

- 题型合法；
- 题干非空；
- 选项数量和正确答案合法；
- 参考答案非空；
- 可接受要点存在；
- 引用存在且可定位；
- 难度在允许范围；
- 知识点属于计划；
- 没有重复题；
- 没有明显泄露答案。

### 29.2 点评校验

点评结果必须校验：

- 判定值属于允许枚举；
- 解释与判定一致；
- 引用真实存在；
- 没有引用当前范围之外资料；
- 没有把用户答案篡改后再评分；
- UNGRADABLE 不更新掌握度。

### 29.3 校验失败

- 最多进行有限次数的本地修复或重新生成；
- 仍失败时显示错误；
- 不把无效结果作为正式题目或点评；
- 保留用户答案；
- 允许重试、跳过或结束。

## 30. 错误与恢复

### 30.1 学习计划生成失败

- 保留用户配置；
- 会话标记 FAILED；
- 显示失败类别；
- 允许重试；
- 重试不创建重复会话；
- 允许返回修改范围或主题。

### 30.2 题目生成失败

- 不增加已完成题数；
- 保持当前进度；
- 允许重试；
- 可尝试计划中的下一个知识点；
- 多次失败后允许结束并生成已有部分总结。

### 30.3 点评生成失败

- 保留用户答案；
- Attempt 标记 PENDING_REVIEW 或 REVIEW_FAILED；
- 不更新掌握度；
- 允许重试点评；
- 重试不得要求用户重复输入答案；
- 用户可以暂时离开并稍后处理。

### 30.4 Provider 超时或限流

- 区分超时、限流、余额不足、鉴权失败和网络不可达；
- 不展示密钥和敏感响应；
- 显示可执行的下一步；
- 不自动切换收费 Provider；
- 重试使用业务幂等 ID，避免重复题目和重复 Attempt。

### 30.5 应用异常退出

重启后：

- 恢复学习会话；
- 恢复当前题和草稿；
- 恢复已提交但未点评的 Attempt；
- 对未完成请求标记 INTERRUPTED；
- 提供继续处理；
- 不把中断题误判为错误。

## 31. 安全要求

- 资料内容视为不可信数据，不能覆盖学习规则；
- 文档中的“忽略系统要求”“泄露密钥”等内容不能成为执行指令；
- 题目和点评中的 Markdown 需要安全渲染；
- 代码只显示，不自动运行；
- 链接不自动打开；
- 不因用户答题内容触发系统命令；
- 不将 API Key、路径、内部 Prompt 或错误堆栈放入题目、点评和总结；
- 不把模型输出未经校验地写入掌握度；
- 不通过资料外常识强行判错；
- 永久删除后不继续保留被删除的资料正文副本。

## 32. 可访问性与易用性

- 正确、错误和部分正确不能只用颜色表示；
- 题目、输入区、提示和点评具有清晰的键盘焦点顺序；
- 单选和判断题支持键盘选择；
- 引用编号具有可读标签；
- 屏幕阅读器能读出当前题号、状态和结果；
- 长文本和代码块不撑破布局；
- 移动宽度下主要操作保持可见，但 V1 不承诺原生手机应用；
- 提示按钮与直接看答案明确区分；
- 结束学习按钮不应与下一题按钮紧邻导致误触。

## 34. 非功能要求

### 34.1 性能

- 打开进行中会话优先加载当前题和最近点评；
- 历史题目按需加载；
- 提交答案后立即显示已提交状态；
- Provider 处理期间显示正在点评；
- 今日复习数量由本地数据快速计算；
- 学习首页不加载所有 Attempt 正文。

### 34.2 一致性

- Attempt、Feedback、学习信号和掌握度更新需要事务性处理；
- 点评失败时不能先更新掌握度；
- 重新点评不得重复增加学习信号；
- 同一请求重试不得生成重复题目；
- 删除和恢复后待复习数量同步更新；
- 题目、答案、点评和引用使用一致资料版本。

### 34.3 本地可靠性

- 关键状态自动保存；
- 草稿节流保存；
- 应用关闭后不丢失已提交答案；
- 数据库升级需要保留历史 Attempt；
- 无网络时允许查看已有学习记录和总结，但不能生成新题或点评。

### 34.4 可观测性

本地诊断可以记录：

- 请求 ID；
- 学习会话、题目和 Attempt 内部 ID；
- Provider 与模型；
- 处理阶段；
- 耗时和 Token 用量；
- 结构校验结果；
- 检索是否降级；
- 脱敏错误类型。

默认不记录完整资料片段、完整 Prompt、API Key 和不必要的用户答案正文。

## 35. V1 不做

- 独立错题本一级模块；
- 教师端和学生端；
- 班级、课程发布和作业布置；
- 排行榜、积分商城和社交分享；
- 正式考试监考；
- 证书；
- 语音口语陪练；
- 图片和手写作答；
- 多人共同学习；
- 云端复习推送；
- 邮件提醒；
- 操作系统通知；
- 完整 SM-2、FSRS 等复杂记忆算法；
- AI 自动修改原始学习资料；
- 资料外自由出题；
- 会话中途静默更换资料范围；
- 自动跨 Provider 切换。

## 36. 验收标准

### LEARN-AC-01

用户可以从学习首页、知识库详情或已索引文件进入开始学习，并看到资料范围、主题、目标、题量和难度配置。

### LEARN-AC-02

未索引文件不能直接开始学习，系统引导加入知识库，不创建行为不同的临时索引。

### LEARN-AC-03

主题在资料中缺乏证据时不生成空洞计划，并提供修改主题、扩大范围或补充资料的选项。

### LEARN-AC-04

默认流程依次包含主题概览、知识点讲解、逐题作答、点评和总结。

### LEARN-AC-05

学习会话一次只展示一道题，参考答案和直接泄露答案的依据在提交前保持隐藏。

### LEARN-AC-06

每道正式题目都具有资料依据、参考答案、判定要点和可定位引用。

### LEARN-AC-07

用户提交答案后得到正确、部分正确、错误或无法判定之一，并看到针对实际答案的点评。

### LEARN-AC-08

无法可靠判断时不更新掌握度，用户可以重述、跳过或更换题目。

### LEARN-AC-09

用户可以获得三级提示或直接看答案，提示层级会影响学习信号。

### LEARN-AC-10

重试创建新的 Attempt，不覆盖首次答案；显示完整答案后不立即原样重问。

### LEARN-AC-11

系统根据连续答题表现自动调整难度，单次变化不跨越两个等级，用户可以手动要求简单或困难。

### LEARN-AC-12

一次答对不会直接显示为已掌握；MASTERED 至少需要两次延迟复习成功，并包含一次不少于 7 天的间隔。

### LEARN-AC-13

复习计划使用 1、3、7、14、30 天阶梯，并根据独立答对、提示、部分正确或错误调整。

### LEARN-AC-14

学习首页显示今日待复习和最近学习记录；V1 不依赖云端或系统通知。

### LEARN-AC-15

出题、参考答案和知识性点评严格基于资料；资料不足时提前结束或切换知识点，不使用模型通用知识凑题。

### LEARN-AC-16

资料冲突时不生成未声明前提的唯一答案题；无法公平评分时判为无法判断。

### LEARN-AC-17

学习会话资料范围创建后固定；资料失效时已有记录可看，但不能继续生成新题。

### LEARN-AC-18

用户可以暂停并恢复学习，当前题、草稿、提示、进度和最近点评保持一致。

### LEARN-AC-19

应用异常退出后，已提交但未点评的答案仍保留，并可重新处理，不会被误判为错误。

### LEARN-AC-20

用户可随时结束学习；总结区分完成计划、主动结束、资料不足和处理失败。

### LEARN-AC-21

总结中的题目统计由结构化数据计算，即使 AI 文字总结失败也能显示核心结果和复习日期。

### LEARN-AC-22

错误和薄弱题通过总结、历史和待复习列表查看，V1 不创建独立错题本。

### LEARN-AC-23

Provider 失败时保留配置、题目、答案和进度；重试不会重复创建会话、题目或 Attempt。

### LEARN-AC-24

学习记录删除后进入 30 天回收站，不影响文件、知识库和 AI 对话；恢复不自动重新生成内容。

### LEARN-AC-25

永久删除某次学习记录后，其独有数据被清理；仍有其他记录支持的知识点掌握状态可以重新计算。

### LEARN-AC-26

系统不会自动跨 Provider 切换，也不会把完整知识库、API Key 或本地绝对路径发送到外部模型。

### LEARN-AC-27

资料中的伪装指令不能修改学习规则、泄露密钥、执行代码或绕过引用要求。

## 37. 本部分冻结结论

- 学习陪练是 V1 的产品重心；
- 默认使用“先讲解、再逐题练习、最后总结”的流程；
- 目标兼顾理解与记忆，并可选择理解优先或记忆优先；
- 开始学习使用独立配置页；
- 资料范围为一个知识库或一组已索引文件；
- 未索引文件先加入知识库，不建立隐式临时索引；
- 题量默认 10 题，可选 5、10、15 或自定义 1～30；
- 难度为基础、标准和进阶，并根据连续表现自动调整；
- 用户可手动要求简单或困难；
- V1 支持简答、自我解释、单选、判断、填空和简单应用题；
- 一次只展示一道题，提交后点评；
- 提示分三级，提示、重试和直接看答案会影响学习信号；
- 点评结果为正确、部分正确、错误或无法判定；
- 无法判定不更新掌握度；
- 重试保留所有 Attempt，不覆盖首次答案；
- 掌握状态为 NEW、LEARNING、FAMILIAR、MASTERED 和 NEEDS_REVIEW；
- 一次答对不能直接成为已掌握；
- 简化间隔复习采用 1、3、7、14、30 天；
- V1 只提供应用内复习提醒；
- 学习会话创建后资料范围固定；
- 出题、参考答案和点评严格基于资料并可引用；
- 资料不足不使用通用知识凑题；
- 学习记录、草稿、掌握度和复习安排默认本地保存；
- 学习可暂停、恢复、主动结束和异常恢复；
- 总结统计由本地结构化数据计算；
- V1 不设独立错题本，通过总结、历史和待复习整合薄弱内容；
- V1 不做复杂记忆算法、云端提醒、正式考试和自动跨 Provider 切换。
