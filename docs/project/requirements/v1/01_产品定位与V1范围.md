# 01 产品定位与 V1 范围

## 1. 文档目的

本文档确定 MindMate AI V1 的目标用户、核心问题、产品定位、使用场景、功能边界和成功标准。

本文档确认后，产品定位和 V1 范围冻结。后续页面、功能、数据和技术设计必须服务于本文件，不得在开发过程中随意扩大范围。

## 2. 已确认决策

| 决策项 | 最终选择 | 影响 |
| --- | --- | --- |
| 产品重心 | 学习陪练优先 | 首页、对话和知识库最终都要服务于学习流程 |
| 文件整理深度 | 文件夹＋标签 | V1 支持目录、标签、搜索、筛选和必要的批量操作 |
| 学习目标 | 理解与记忆兼顾 | 陪练同时包含解释、逐题练习、纠错、重试和总结 |
| 用户范围 | 单用户 | V1 不设计注册、登录、角色和多人数据隔离 |
| 使用形态 | Web 优先、本地运行 | 应用在个人电脑使用，不依赖公网服务器 |
| 数据原则 | 本地优先 | 原始文件、业务数据、索引和向量默认保存在本地 |

## 3. 产品定位

MindMate AI 是一款面向个人用户的本地 AI 知识学习助手。

用户可以把分散在电脑中的学习资料和工作资料导入应用，通过文件夹与标签完成整理，将相关文件组成知识库，再使用 AI 进行可溯源问答和逐题学习陪练。

产品不是单纯的文件管理器，也不是只有聊天框的通用 AI 工具。它的核心价值是把以下过程连接起来：

~~~text
导入资料
→ 整理文件
→ 建立知识库
→ 基于资料问答
→ 逐题学习与纠错
→ 保存学习记录与总结
~~~

其中，“学习陪练”是 V1 的产品重心；文件整理、知识库和 AI 对话是学习陪练的基础能力。

## 4. 目标用户

### 4.1 主要用户

主要用户是需要根据个人资料进行持续学习的个人学习者，包括：

- 自学编程、语言、考试课程或专业知识的学习者；
- 需要阅读大量 PDF、Word、Markdown、笔记和课程材料的用户；
- 希望 AI 根据自己的资料逐题提问、点评和总结的用户；
- 希望资料和向量数据主要保存在个人电脑中的用户；
- 不希望搭建服务器或维护复杂基础设施的个人开发者和学习者。

### 4.2 次要用户

次要用户是需要管理和检索个人资料的知识工作者，包括：

- 需要从项目文档中快速查找答案的工程师；
- 需要整理研究资料、会议材料和技术文档的用户；
- 希望回答带有来源引用，而不是只获得无法验证的 AI 结论的用户。

### 4.3 V1 不服务的用户

V1 不面向以下使用场景：

- 需要组织级知识库的企业团队；
- 需要多人协作、审批和权限管理的团队；
- 需要云端同步和多设备实时一致性的用户；
- 需要面向公众提供在线 AI 服务的运营者；
- 需要完整教学管理系统的学校或培训机构。

## 5. 用户当前面临的问题

### 5.1 文件分散且难以整理

个人资料散落在不同文件夹中，文件名、目录和分类方式不统一。用户知道资料存在，但难以快速找到相关内容，也难以判断文件是否已经处理或加入知识库。

### 5.2 通用 AI 不了解个人资料

普通聊天工具缺少用户自己的学习材料。用户需要反复上传或复制内容，而且回答可能脱离原文，无法确认信息来源。

### 5.3 知识库只能回答，不能带着用户学习

很多知识库产品只支持检索问答。用户获得答案后仍然缺少练习、反馈、纠错和阶段总结，难以判断自己是否真正掌握。

### 5.4 学习过程缺少连续性

用户关闭聊天后，之前学习到哪里、回答过什么、哪些地方理解错误，往往无法延续。再次学习时需要从头开始。

### 5.5 个人项目不适合复杂部署

用户只希望在自己的电脑上使用，不需要公网服务器、多用户系统和复杂运维，但又需要安全保存文件、索引、历史和 API Key。

## 6. 产品目标

### 6.1 总体目标

让用户能够使用自己的资料完成“整理—检索—理解—练习—总结”的完整个人学习闭环。

### 6.2 V1 具体目标

#### GOAL-01：资料可整理

用户能够导入常见文档，通过文件夹、标签、搜索和筛选管理资料，并清楚看到文件的处理状态。

#### GOAL-02：资料可形成知识库

用户能够把多个文件加入一个知识库，系统完成解析、切片、Embedding 和索引，并展示处理进度和失败原因。

#### GOAL-03：回答可溯源

用户能够基于知识库或指定文件提问，回答展示引用来源。资料不足或资料冲突时，系统必须明确提示，不能伪造依据。

#### GOAL-04：AI 能逐题陪练

用户能够选择资料和学习目标，由 AI 逐题提问。每次回答后获得点评、解释和来源，再决定继续、重试或结束。

#### GOAL-05：学习过程可延续

系统保存对话、学习过程和结束总结。用户重新打开应用后可以查看和继续已有记录。

#### GOAL-06：个人数据本地优先

原始文件、业务数据、索引和向量默认保存在本机。只有生成回答或点评所必需的文本上下文可以发送给外部模型。

#### GOAL-07：个人用户可直接运行

应用不依赖公网服务器。完成首次本地安装和模型 API 配置后，用户可以在个人电脑上使用。

## 7. 核心使用场景

### SCENE-01：整理新获取的学习资料

用户将课程 PDF、技术文档或个人笔记导入应用，放入指定文件夹并添加标签。系统解析文件并显示处理状态，用户随后将资料加入知识库。

### SCENE-02：从资料中快速查找答案

用户选择一个知识库后提问。系统检索相关内容，生成回答并显示来源文件和引用片段。用户可以打开来源核对原文。

### SCENE-03：围绕一个主题逐题学习

用户选择知识库或文件，输入学习目标并开始陪练。AI 每次只提出一道问题；用户作答后，AI 进行点评、解释并引用资料，然后生成下一题。

### SCENE-04：针对不理解的内容追问

用户在陪练或普通问答中继续追问某个概念。系统结合当前上下文与资料回答，同时保持引用可追溯。

### SCENE-05：中断后继续学习

用户结束或暂时离开后，系统保存学习记录。用户再次进入时可以查看上次进度、回答和总结，并继续学习。

### SCENE-06：处理失败任务

文件解析、Embedding 或索引失败时，用户可以看到失败步骤和原因，并在修正条件后重新处理，而不必重复导入整个文件。

## 10. V1 产品原则

### 10.1 学习优先

文件和知识库功能不能独立膨胀成复杂网盘。它们首先要支持资料问答和学习陪练。

### 10.2 来源优先

基于资料生成的回答和点评应尽可能附带来源。无法从资料中获得依据时，应明确说明。

### 10.3 一次只推进一步

陪练采用逐题方式。系统提出一题、等待用户回答、完成点评后再继续，避免一次生成大量题目。

### 10.4 本地优先

可以本地完成的存储、索引和业务处理优先在本机完成。外部模型只接收当前任务必需的内容。

### 10.5 状态可见

文件解析、Embedding、索引和 AI 生成等耗时操作必须让用户看到状态，不能长时间无反馈。

### 10.6 失败可恢复

后台任务失败后应给出可理解的原因和重试入口。单步失败不应迫使用户重做全部流程。

### 10.7 控制 V1 规模

不因为某项功能“以后可能有用”就加入 V1。延期内容统一记录到版本规划中。

## 11. 成功标准

V1 达到以下条件，即认为产品核心目标成立：

### SUCCESS-01：完成资料导入闭环

用户可以导入一个支持的文件，把它放入文件夹、添加标签，并看到解析与索引结果。

### SUCCESS-02：完成知识库问答闭环

用户可以创建知识库、加入文件、等待索引完成并提出问题，回答能够显示可核对的来源。

### SUCCESS-03：完成学习陪练闭环

用户可以基于选定资料开始陪练，完成至少一轮“出题—作答—点评—继续”，并在结束时获得学习总结。

### SUCCESS-04：完成历史恢复闭环

用户关闭并重新打开应用后，仍能查看之前的文件、知识库、对话和学习记录。

### SUCCESS-05：完成失败恢复闭环

文件处理或模型调用失败时，界面显示明确状态和原因，并提供合理的重试或恢复入口。

### SUCCESS-06：满足本地隐私边界

原始文件、业务数据和向量默认保存在本地；前端和仓库中不存在真实 API Key。

### SUCCESS-07：无需服务器即可使用

用户可以在个人 Windows 电脑上启动前端和本地后端，完成核心功能，不依赖自建公网服务器。

### P0：没有就无法形成 V1

- 文件导入和处理；
- 文件夹与标签；
- 知识库创建和索引；
- 基于资料的 AI 对话；
- 引用溯源；
- 逐题学习陪练；
- 对话和学习历史；
- 本地数据保存；
- API Key 安全；
- 基础错误和任务状态。

### P1：提升完整度

- 批量文件操作；
- 文件摘要；
- 全局搜索；
- 智能难度调整；
- 资料冲突提示；
- 索引重建；
- 首页统计和快捷入口。

### P2：后续版本候选

- AI 自动分类和命名；
- 内容级重复检测；
- 独立错题本；
- 云同步；
- 多端使用；
- 团队协作；
- 插件和自动化工作流。

## 13. 约束

- 首版只支持单用户；
- 运行环境以 Windows 个人电脑为主要目标；
- 产品 Web 优先；
- 不依赖公网服务器；
- 前端不能直接访问外部模型密钥；
- 外部模型调用必须经过本地后端；
- 原始文件和向量数据默认不上传；
- Provider、Embedding、向量库和具体技术框架在技术方案阶段集中确定；
- V1 必须优先保证完整闭环，避免为了高级功能拖延开发。

## 14. 本部分冻结结论

本部分已确认：

- MindMate AI 是学习陪练优先的个人 AI 知识学习助手；
- 文件管理采用文件夹与标签组合；
- 学习目标兼顾理解和记忆；
- V1 为单用户、本地运行、Web 优先；
- 文件整理、知识库、AI 对话和学习陪练构成一条完整产品链；
- 不纳入 V1 的内容已经明确；
- 成功标准以核心业务闭环能否完成为主。

后续文档可以细化功能，但不得无记录地改变以上产品定位和范围。
