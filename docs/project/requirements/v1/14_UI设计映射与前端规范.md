# 14 UI 设计映射与前端规范

## 1. 文档目的

本文档将现有设计稿模板与 02–08 的页面和交互要求映射为前端实现规范。设计稿提供视觉方向，不覆盖已冻结业务规则；设计稿缺失状态由本文补齐。

## 2. 设计实现原则

1. 学习任务优先于装饰；
2. 当前模式、资料范围、索引状态和外发边界始终可见；
3. 相同业务状态使用相同组件和文案；
4. 长任务不阻塞页面；
5. 危险操作可撤销优先，无法撤销才二次确认；
6. 不因设计稿缺少空态、错误态或加载态而省略；
7. 先实现桌面端 1280–1920 px，不扩展完整移动端产品。

## 4. 应用壳

### 4.1 桌面布局

| 区域 | 展开尺寸 | 紧凑尺寸 | 规则 |
| --- | --- | --- | --- |
| 左侧导航 | 232 px | 64 px | 用户可折叠并本地记忆 |
| 顶部栏 | 56 px | 56 px | 页面标题、主操作、任务入口 |
| 主内容最大宽度 | 1440 px | 自适应 | 数据密集页可全宽 |
| 内容边距 | 24 px | 16 px | 小于 1280 px 使用紧凑值 |
| 右侧抽屉 | 420 px | 最大 90vw | 引用、任务、详情通用 |

### 4.2 导航顺序

固定一级入口顺序：

1. 首页；
2. 学习；
3. AI 对话；
4. 知识库；
5. 文件。

辅助区依次为历史、回收站、设置。任务入口位于顶部栏，不作为导航项。

### 4.3 页面标题区

包含：面包屑（需要时）、标题、简短说明、状态徽标、主操作和次操作。一个页面只保留一个视觉主按钮。

## 5. 响应式规则

| 视口 | 布局 |
| --- | --- |
| ≥ 1440 px | 展开侧栏，内容宽松，双/三栏可用 |
| 1280–1439 px | 展开侧栏，缩小间距 |
| 1024–1279 px | 默认折叠侧栏，次面板改抽屉 |
| 768–1023 px | 单主栏，表格隐藏次要列 |
| < 768 px | 仅保证可查看和基本操作，不作为 V1 完整验收平台 |

不得通过纯 hover 才能完成核心操作；横向溢出的数据表提供滚动，不压缩到不可读。

## 6. 设计 Token

前端必须通过语义 Token 使用颜色、字号、间距和阴影，不在页面散落魔法值。

### 6.1 颜色语义

| Token | 用途 |
| --- | --- |
| `color-bg-canvas` | 应用背景 |
| `color-bg-surface` | 卡片、面板 |
| `color-bg-subtle` | 次级区域 |
| `color-text-primary` | 正文和标题 |
| `color-text-secondary` | 说明 |
| `color-border` | 普通边框 |
| `color-primary` | 主操作和选中态 |
| `color-success` | 完成、可用 |
| `color-warning` | 等待、部分可用、将到期 |
| `color-danger` | 失败、永久删除 |
| `color-info` | 一般信息 |

状态不得只依赖颜色，必须同时使用文字或图标。

### 6.2 字体与字号

- 字体栈：系统 UI 字体优先；
- 正文 14 px，行高 1.6；
- 辅助文本 12 px，不低于 12 px；
- 页面标题 24 px；区块标题 18 px；卡片标题 16 px；
- 长文阅读区可使用 16 px 正文；
- 代码和 ID 使用等宽字体。

### 6.3 间距与圆角

- 间距采用 4 px 基数：4/8/12/16/24/32/40；
- 普通控件高度 36–40 px；
- 主要触控目标至少 24×24 px，常用按钮建议不小于 32×32 px；
- 卡片圆角统一，弹窗与抽屉不自行创建新风格；
- 动画 120–240 ms，并支持 reduced motion。

## 7. 通用组件清单

必须抽象并复用：

- AppShell、Sidebar、Topbar、Breadcrumb；
- PageHeader、EmptyState、ErrorState、LoadingState；
- Button、IconButton、Input、Textarea、Select、Checkbox、Radio；
- Dialog、Drawer、Popover、Tooltip、Toast；
- DataTable、Pagination/CursorLoader、FilterBar、SearchInput；
- StatusBadge、ProgressBar、Skeleton、InlineAlert；
- FilePicker、FolderTree、TagPicker、KnowledgeScopePicker；
- TaskStatusButton、TaskDrawer、TaskItem；
- MessageList、MessageBubble、Composer、CitationChip；
- LearningQuestion、AnswerEditor、FeedbackPanel、MasteryBadge；
- ConfirmDangerDialog、UndoToast；
- MarkdownRenderer、CodeBlock、SourcePreview。

页面不得重复实现状态徽标、引用、任务进度和危险确认。

## 8. 状态语言

### 8.1 文件/知识库状态

统一显示：等待处理、处理中、可用、部分可用、失败、已中断、在回收站。内部枚举不得直接显示给用户。

### 8.2 AI 状态

统一显示：准备中、检索资料、正在生成、正在停止、已停止、已完成、生成失败。流式光标只用于“正在生成”。

### 8.3 任务状态

排队中、运行中、取消中、已取消、已完成、失败、已中断。每个任务显示当前阶段而非伪造百分比；无法估算时使用不定进度。

## 9. 表单规范

- 标签在输入框上方，不用 placeholder 代替标签；
- 必填项明确标识；
- 保存前执行前端即时校验，后端仍是权威；
- 错误显示在字段附近并聚焦第一个错误；
- 长表单有未保存离开提醒；
- 保存按钮请求中禁用，幂等提交；
- 成功保存后反馈对象和下一步；
- 高级设置默认折叠；
- API Key 保存后只显示已配置状态和后四位。

## 10. 列表、搜索与批量操作

- 默认使用服务端游标分页或增量加载；
- 搜索输入 250–400 ms 防抖；
- 筛选条件反映在 URL 或可恢复页面状态中；
- 空搜索与无数据空态使用不同文案；
- 选中项跨页规则必须明确，V1 默认只选择当前已加载项；
- 批量操作先显示数量和影响；
- 部分成功时逐项列出成功与失败；
- 行菜单可键盘访问，不把关键操作藏在 hover 中。

## 11. 文件页面规范

### 11.1 文件列表

左侧目录树，右侧文件表格。核心列：名称、类型、状态、标签、知识库数、更新时间。窄屏依次隐藏知识库数、标签和类型说明，但保留名称、状态和操作。

### 11.2 导入交互

- 支持选择和拖放；
- 投放区显示格式、单文件和批次限制；
- 选择后先展示待导入清单和前置错误；
- 提交后关闭弹窗不影响任务；
- 重复文件使用专用决策对话框；
- 不使用只有“失败”两个字的错误。

### 11.3 文件详情

顶部显示名称、状态、操作；主体包含概览、文本预览、所在知识库和处理记录。原始文件与解析文本区分，预览不可用时不影响元数据管理。

## 12. 知识库页面规范

- 列表卡片显示名称、状态、文件数、Chunk 数、最近更新；
- 详情页顶部持续显示索引状态和当前激活版本；
- 成员文件页明确区分可用、处理中、失败和已删除；
- 建库与编辑使用相同 Scope Picker；
- 构建中允许继续查看旧索引内容；
- “开始对话”“开始学习”只在范围满足最低条件时可用，并说明禁用原因；
- 测试检索属于高级诊断，不占据主操作。

## 13. AI 对话界面规范

### 13.1 布局

宽屏为左侧会话列表＋中间消息区；来源详情使用右抽屉。会话列表可折叠。输入框固定在消息区底部，但不能遮住最后一条消息。

### 13.2 模式和范围

- 新建时先选择普通聊天或知识库聊天；
- 消息区顶部显示模式条；
- 知识库模式显示范围名称、状态和切换按钮；
- 范围变化在消息流插入不可编辑的系统事件；
- 不用颜色暗示一个实际未生效的范围。

### 13.3 消息

- 用户、助手和系统事件视觉区分；
- 消息操作在聚焦或悬停时出现，但可通过键盘到达；
- 未完成、停止、失败和已重生成均有标签；
- 助手回答的引用使用连续编号，点击打开来源抽屉；
- 代码块提供复制，不默认执行；
- 长回答保留标题层级并支持选择复制。

### 13.4 输入区

- Enter 发送、Shift+Enter 换行，可在设置中关闭 Enter 发送；
- 生成中主按钮变为停止；
- 显示当前模式、范围和估算上下文风险；
- 未配置 Key、范围不可用或预算阻断时，禁用发送并给出直接修复入口。

## 14. 学习陪练界面规范

### 14.1 专注布局

学习会话减少非必要导航干扰，但保留退出、暂停、进度和资料范围。主体一次只强调当前阶段：讲解、题目、点评或总结。

### 14.2 题目与作答

- 题干、题型、难度和进度清楚；
- 主观题使用可扩展文本区；
- 选择题选项整行可点且有键盘状态；
- 提交后锁定本次答案；
- 提示分级展开并记录次数；
- 点评顺序为结论、做得好的、需改进、依据、下一步；
- “重试”和“下一题”视觉层级取决于点评建议，但用户都可选择。

### 14.3 总结

不使用单一夸张分数代表掌握。展示完成题数、首次正确、提示/重试、知识点表现、薄弱点、资料依据和下次复习时间，并注明掌握度是应用内估算。

## 15. 引用与来源抽屉

- 引用标签显示序号、文件简称和位置；
- 点击定位到对应页码、幻灯片、标题路径或文本区间；
- 抽屉显示引用片段及前后必要上下文；
- 冲突资料分别显示；
- 来源失效时保留引用快照标识并提示当前文件状态；
- 不显示本机绝对路径；
- “在文件中查看”只调用受控后端能力。

## 16. 加载、空状态与错误状态

每个异步页面必须设计：

| 状态 | 要求 |
| --- | --- |
| 首次加载 | 骨架屏或明确加载，不闪空态 |
| 局部刷新 | 保留旧数据并显示轻量进度 |
| 无数据 | 说明价值和首个操作 |
| 搜索无结果 | 显示清除筛选/修改关键词 |
| 可重试错误 | 原因、重试、诊断 ID |
| 无法恢复错误 | 返回安全页面、保留已提交数据 |
| 部分可用 | 明确哪些成功、哪些受限 |
| 离线 | 保留本地功能，外部 AI 标为不可用 |

## 17. 确认、撤销与通知

- 可恢复的删除默认进入回收站并提供撤销 Toast；
- 永久删除、清空数据、覆盖恢复需要危险对话框；
- 危险对话框明确对象、数量、依赖影响和不可撤销性；
- 不使用模糊的“确定/取消”，主按钮写具体动作；
- Toast 只反馈已完成结果，不代替需要用户处理的错误；
- 多个相同进度通知合并，避免 Toast 风暴。

## 18. 无障碍细则

- HTML 语义元素优先，ARIA 只补足语义；
- 跳转主内容链接可用；
- 对话列表、目录树、标签页和弹窗遵守对应键盘模式；
- 焦点不被流式更新抢走；
- 自动滚动只在用户位于底部时发生；
- 新消息和任务完成适度播报，不逐 Token 播报；
- 颜色对比、焦点可见和 200% 缩放满足 12 文档；
- 图表或掌握度视觉同时提供文字值。

## 19. 前端状态管理边界

| 状态 | 存放位置 |
| --- | --- |
| 服务端实体 | 查询缓存，以 API 为权威 |
| 当前表单 | 组件/表单状态 |
| UI 偏好 | 本地设置，如侧栏折叠 |
| 草稿 | 后端持久化草稿接口 |
| 任务状态 | SSE＋查询补偿 |
| 流式消息 | AI Operation 状态，完成后回写查询缓存 |
| API Key | 不进入前端状态 |

不得复制一套长期存在的前端业务数据库，也不得用 LocalStorage 保存敏感正文、Key 或完整对话。

## 20. 前端代码约束

- TypeScript 严格模式；
- 页面组件不直接拼接 API URL；
- API 客户端由 OpenAPI 生成类型或进行契约校验；
- 所有网络错误进入统一错误映射；
- Markdown 只走统一安全渲染器；
- 日期、文件大小、状态文本统一格式化；
- 组件 props 使用领域 ID，不传任意文件路径；
- 测试选择器使用稳定 `data-testid`，不依赖样式类；
- 核心页面至少有加载、成功、空、错误、禁用状态的组件测试。

## 21. 设计稿缺失与冲突处理

1. 业务规则优先于设计稿静态画面；
2. 设计稿缺少状态时按本文通用状态补齐；
3. 设计稿出现 V1 外功能时不实现，记录到 17；
4. 设计稿字段与数据模型冲突时采用 09 和 11；
5. 视觉细节缺失时复用现有 Token 和组件，不创建新风格；
6. 只有会改变用户流程、数据或安全边界的冲突才停止询问；
7. 普通像素差异由实现者按一致性自行修正。

## 22. UI 验收清单

- UI-ACC-001：全部路由与页面清单一致；
- UI-ACC-002：五个一级入口顺序固定且选中态正确；
- UI-ACC-003：核心页面具备加载、空、错误、部分成功状态；
- UI-ACC-004：模式、范围、任务和索引状态不隐藏；
- UI-ACC-005：流式输出、停止、重试和恢复状态明确；
- UI-ACC-006：引用可定位且不显示绝对路径；
- UI-ACC-007：危险操作说明影响并使用具体动词；
- UI-ACC-008：1280×720 和 200% 缩放仍能完成核心流程；
- UI-ACC-009：核心流程仅键盘可完成；
- UI-ACC-010：无未清洗 HTML 和前端 Key；
- UI-ACC-011：前端刷新后从 API 恢复权威状态；
- UI-ACC-012：设计稿未覆盖状态按本文一致实现。

## 23. 本部分冻结结论

V1 采用桌面优先的左侧导航应用壳，以统一 Token、组件和状态语言实现现有设计方向。前端不承担业务真相、文件访问或 Provider 密钥；模式、资料范围、引用和长任务始终透明。设计稿缺失的空态、错误态、安全确认和无障碍状态按本文补齐。
