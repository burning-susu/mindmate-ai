# CHG-20261010-PPTX-RENDERING

状态：`LOCAL RENDER PASS / 应用服务重启待完成 / 正式安装包属于阶段 10`

日期：2026-10-10

## 来源与问题

用户查看 `01_springboot基础篇.pptx` 时，详情页显示 62 张幻灯片的抽取文本卡片；用户需要看到幻灯片实际排版、图片和图表。当前 PPTX 预览行为来自第八十三批的“结构化文本阅读”方案，与本次最新明确目标不符。

## 用户故事

作为文件工作台用户，我希望打开 PPTX 详情时能看到每一张幻灯片的视觉页面，以便按原文件的版面阅读，而不是逐条阅读被拆散的文本块。

## 验收要求

1. 当用户打开已解析的 PPTX 详情时，系统应使用本机 LibreOffice 将原文件离线转换为 PDF，并通过现有浏览器 PDF 查看能力展示完整页序。
2. 当源文件内容未变化且转换结果已缓存时，系统应复用转换结果，不重复运行转换器。
3. 当缩略图/转换器不可用或转换失败时，系统应明确显示失败原因及“打开原文”；不得把抽取文本卡片伪装成幻灯片画面。文本提取可作为独立的辅助阅读内容保留。
4. 转换必须使用应用托管的原始 PPTX 副本；不得修改、覆盖或重新保存源文件。
5. 转换过程必须设置独立 LibreOffice 用户配置目录、超时和输出大小上限；临时文件完成后应清理，缓存写入应避免暴露半成品。
6. 本地转换不得调用云转换服务，不新增数据库迁移；生成的 PDF 只作为可重建派生预览，不进入搜索或知识库索引。
7. 开发环境可从明确配置或 PATH 定位 LibreOffice；正式 one-folder 安装包应携带经版本、许可和哈希核验的 LibreOffice 运行时。

## 技术方案

- 后端新增受限 LibreOffice 转 PDF Adapter 和只读 PPTX 视觉预览 API。
- 以源 `ContentObject` 内容哈希作为派生 PDF 缓存键；使用每次转换独立的工作目录和 LibreOffice profile，成功后原子发布缓存文件。
- 前端在 PPTX 详情优先嵌入派生 PDF；现有文本提取视图移至辅助入口。PDF 继续复用当前浏览器 PDF 预览样式和缩放行为。
- 转换失败时返回可区分的安全错误状态，页面保留“打开原文”及文本提取入口。
- 文件规模、进程超时、输出大小、清理方式、缓存寿命及打包路径需在实现和真实样本验证中落实；禁止依赖临时目录之外的用户文件。
- 视觉结果是 LibreOffice 的 PDF 渲染；因字体和 PowerPoint 专属效果差异，不承诺与 Microsoft PowerPoint 像素级一致。
