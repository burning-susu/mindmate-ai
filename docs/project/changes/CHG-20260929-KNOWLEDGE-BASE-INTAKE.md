# CHG-20260929-KNOWLEDGE-BASE-INTAKE

状态：`IMPLEMENTED_LOCAL`

日期：2026-09-29

## 来源与范围

本变更执行外部控制提示词《第七十七批_知识库内直接导入文件与建库闭环》要求的知识库入口补全。附件中的历史 SHA、用户复测和浏览器证据只作为待核对材料，不改写为当前会话的新用户消息；当前仓库事实以进场 Git、源码、测试和本报告为准。

范围是知识库建库和详情页的资料衔接：建库时选择已有文件、上传本地文件，详情页从当前库上传文件，复用既有文件导入/重复决策/成员准入/索引状态任务。空库创建、文件可复用语义、Mock Provider 和现有索引重建边界保持不变。

## 基线与变更对象

- `KEEP`：`POST /api/v1/knowledge-bases`、`POST /api/v1/knowledge-bases/{id}/files`、文件导入任务、三种重复决策、解析 Worker、索引状态和受控重建 API；没有新增数据库迁移或 OpenAPI 字段。
- `REVALIDATE`：知识库建库页和详情页的文件选择、重复决策展示、任务 ID、刷新恢复、部分失败文案和重复提交保护。
- `ADD`：建库页混合初始资料入口；详情页“上传新文件”入口；前端文件导入类型/API 辅助；知识库上下文任务 ID 的浏览器本地恢复记录；相应前后端回归测试和阶段报告。
- `FIX`：文件导入上下文下选择 `REUSE_EXISTING` 时，服务端现在会把复用的源文件恢复/加入当前知识库成员关系；向回收站知识库上传会被拒绝。直接导入只更新知识库为 `PREPARING`，不额外递增 `row_version`，以保持现有恢复契约。

## 行为契约

1. 建库页先创建唯一知识库，再按固定顺序提交已有文件成员任务、上传本地文件任务；提交按钮同步锁和持久幂等键避免双击产生第二个知识库或重复请求。
2. 本地上传携带 `knowledge_base_id`，继续使用文件工作台的格式/大小/哈希/解析/重复决策边界。重复决策在知识库详情中完成：复用已有文件会加入当前库，另存记录会建立独立资料记录，跳过不会建立成员关系。
3. 详情页上传结果按文件显示真实导入、解析和重复状态，并保留导入任务 ID。任务完成后刷新成员、知识库和索引状态查询；已完成任务的 ID 从本地恢复记录中清理，运行中任务可在刷新后继续读取。
4. 本地 `File` 对象不写入浏览器存储。建库页明确提示刷新会丢失尚未提交的本地选择；已提交任务的服务端状态仍可恢复。
5. 成员加入后继续使用现有索引工作台的受控重建入口，不自动重复入队；页面明确提示“成员加入不代表索引可用”。模型缺失时沿用离线安全提示，不下载模型、不调用真实 Provider。

## 数据与安全边界

- 文件仍是独立资料，同一源文件可以被多个知识库复用；知识库上传不会删除、移动或复制出第二份源内容。
- 不允许回收站知识库接收新导入；回收站文件和托管内容缺失的文件不会进入选择列表。解析失败、等待解析的文件保留真实状态并可按既有契约加入成员，但不显示为可问答。
- 没有写入 Key、Token、真实文件、模型缓存、数据库或外部 Provider 请求。
