## 1. 文档定位和状态

本文档是面向产品、设计、开发和测试共同使用的 V1.0 Approved PRD。它定义产品目标、范围、用户、页面、业务流程、业务规则、状态、异常、隐私、安全、非功能和验收要求。

本文档不定义数据库表、类名、函数名、具体框架、Provider 名称、向量数据库、正式 API 路径、流式协议、URL 字符串或 Design Token。上述内容按 TBD 保留给后续技术和 UI 阶段。

本 PRD 继承以下已确认约束：

- 本地单用户 MVP，不实现真实注册登录；
- 保留 userId 或等价资源归属字段，服务层必须校验资源归属；
- 模型和 Embedding 使用外部 Provider，经本地后端 Provider Adapter 调用；
- 原始文件、业务数据、解析结果和向量数据默认本地保存；
- V1 提供轻量本地导出/备份和恢复，不提供云同步或远程备份；
- 本地使用不等于完全离线，只发送完成任务所必需的文本和上下文；
- 模块化单体、内部异步任务、V1 不采用微服务；
- API 方向为 REST + OpenAPI；
- V1 不包含设置页、独立错题本、OCR、真实登录、多用户协作、管理后台和云服务器部署；
- 五个一级页面壳、详情页嵌套、学习陪练保留在 AI 对话模式中。

## 3. 项目背景和产品定位

个人学习资料分散在 PDF、Word、Markdown 和 TXT 文件中，用户难以快速定位内容，也难以判断自己是否真正掌握。普通模型回答缺少用户资料出处，阅读资料和主动练习之间没有连续闭环。

Mindmate 是一个本地单用户 Web AI 工具，将用户资料整理为个人知识库，支持基于资料问答、真实引用和逐题学习陪练。它不是多智能体平台、工作流平台、企业知识中台或在线考试系统。

## 4. 产品目标与成功条件

### 4.1 V1 目标

1. 用户能创建知识库并上传支持的文本型资料。
2. 文件经过异步解析、摘要、切片和索引后进入可使用状态。
3. 用户能限定知识库或文件提问，并查看真实引用。
4. 资料不足时，系统明确拒答或提示补充资料，不把通用常识冒充为资料结论。
5. 用户能在同一 AI 对话页进入学习陪练，一次回答一道题并获得资料依据和反馈。
6. 用户能恢复历史会话、模式和知识库范围。

### 4.2 V1 成功条件

- 至少四种支持格式可上传并显示完整处理状态。
- 指定知识库问答能够展示可展开的真实引用。
- 资料不足场景能够拒答或提示补充资料。
- 用户能够完成至少三道连续陪练题并获得点评。
- 历史会话能够恢复消息、模式和资料范围。
- 核心流程不存在阻断使用的严重缺陷。

## 5. 目标用户和使用场景

### 5.1 目标用户

- 学生和备考者：按课程或考试主题整理资料并复习。
- 自学者：理解新知识、追问和检查掌握情况。
- 初级开发者：限定技术资料回答并查看原文出处。
- 知识工作者：集中管理个人文档并快速查找信息。

### 5.2 核心场景

1. 技术资料查询：上传 Vue、React 或其他技术资料，询问具体概念并查看来源。
2. 项目文档理解：把需求或架构资料放入知识库，限定范围查询规则和边界。
3. 资料驱动陪练：选择主题、难度和数量，逐题回答并获得反馈。
4. 回到过去的学习：从历史会话恢复原来的模式、知识库范围和消息。

## 6. V1 范围

### 6.1 功能范围

- 首页/工作台；
- AI 对话页的自由对话、资料问答、学习陪练三种模式；
- 知识库创建、列表、搜索、排序、重命名、详情和删除；
- 文件上传、批量进度、解析、摘要、标签、文本预览、失败重试和删除；
- 文档切片、Embedding 和索引状态；
- 引用查看、原文位置和失效引用提示；
- 历史会话搜索、继续、重命名和删除；
- 基础事件和必要运行日志。

### 6.2 非 V1 范围

- 设置页；
- 独立错题本；
- 真实注册和登录；
- 多用户协作、团队、角色、计费和管理后台；
- 多智能体、工作流编排和插件市场；
- OCR、扫描版 PDF、联网搜索、语音陪练；
- 知识图谱、长期学习计划和复杂掌握度算法；
- 微服务、云服务器部署和完整多 Provider 动态路由；
- 复杂统计分析后台和大规模压力测试；
- 原模板品牌、颜色和文案直接继承。

## 7. 信息架构和页面树

V1 固定为五个一级页面壳：

1. 首页/工作台；
2. AI 对话页；
3. 知识库管理页；
4. 文件管理页；
5. 历史会话页。

页面层级：

- 知识库详情是知识库管理页的嵌套页面；
- 文件详情是文件管理页的嵌套页面；
- 学习陪练是 AI 对话页的模式，不新增一级页面；
- 引用查看可以在 AI 对话页右侧栏或嵌套详情中展开；
- 设置页和独立错题本不产生 V1 页面。

最终 URL 字符串、路由命名、组件拆分和 Design Token 为 TBD，留到后续 UI/技术阶段。

## 8. 核心用户流程

### 8.1 文件入库

1. 用户进入知识库管理页并创建知识库。
2. 用户进入知识库详情，选择或拖拽文件。
3. 系统校验格式、大小、数量、MIME 和实际内容。
4. 系统保存原始文件并创建处理记录。
5. 文件依次进入上传中、解析中、索引中。
6. 系统生成摘要和建议标签；元数据失败不自动修改原文件。
7. 切片、Embedding 和索引成功后文件进入可使用。
8. 失败时保留原因和重试入口，不把文件标记为可使用。

### 8.2 资料问答

1. 用户进入 AI 对话页并选择资料问答。
2. 用户必须选择一个知识库，可进一步限定一个或多个文件。
3. 用户输入问题并发送。
4. 系统只在当前用户和当前资料范围内检索。
5. 证据充分时生成回答并绑定引用。
6. 用户可展开引用查看文件名、页码/段落和原文片段。
7. 证据不足时明确说明资料不足，并建议换问法或补充文件。
8. 用户切换知识库时，系统提示是否新建会话以避免上下文污染。

### 8.3 学习陪练

1. 用户在 AI 对话页切换到学习陪练。
2. 用户选择知识库、文件或主题、难度、题型和题目数量。
3. 系统生成一题并记录资料依据。
4. 用户提交回答前，系统不自动进入下一题。
5. 系统反馈正确内容、遗漏/错误、参考回答和资料依据。
6. 用户可以继续、追问、重试本题或结束。
7. 结束时系统给出完成题数、结果数量和建议复习内容。

### 8.4 历史会话

用户从历史会话页打开会话后，系统恢复消息、模式、知识库范围和必要陪练状态。已删除文件的引用显示来源文件已删除，不跳转到错误原文。

### 8.5 删除和重试

- 删除知识库：二次确认，删除其文件、片段和索引；V1 默认不可恢复。
- 删除文件：二次确认，删除片段和索引；历史消息保留，引用失效。
- 删除会话：删除消息、引用关联和陪练记录，不影响知识库文件。
- 解析或索引失败：保留失败原因，用户可重试；具体自动重试策略为 G8/G9 TBD。

## 10. 业务规则和状态模型

### 10.1 文件和任务状态

文件业务状态为待上传、上传中、解析中、索引中、可使用、失败。只有可使用文件可进入资料问答和学习陪练。待上传可移除或开始上传，上传中可取消，失败可查看原因、重试或删除。

摘要、Embedding 和索引是文件入库过程中的任务阶段。具体任务是否独立持久化、自动重试次数、取消后的后台行为和幂等规则为 TBD，最晚在 G8/G9 确认。

### 10.2 会话和消息状态

- Message：GENERATING、COMPLETED、STOPPED、FAILED。
- Conversation：ACTIVE、ARCHIVED；V1 可只使用 ACTIVE。
- PracticeSession：CONFIGURING、RUNNING、COMPLETED。

状态变化必须可观察，不能只在内部发生而不更新用户界面。

### 10.3 删除和恢复

V1 删除默认不可恢复。知识库删除级联文件、片段和索引；文件删除片段和索引但保留历史消息并使引用失效；会话删除消息、引用和陪练记录但不影响知识库文件。V1 提供轻量本地导出/备份和恢复，不提供云同步或远程备份。备份格式、内容、加密、覆盖、索引重建和失败恢复规则为 G6/G8/G10 技术 TBD。

## 11. AI 与 RAG 需求

- 自由对话不自动读取个人知识库，并提示通用知识可能有误。
- 资料问答必须限定当前用户、知识库和可选文件范围。
- 系统优先从指定资料检索证据，再生成回答。
- 回答中的引用由系统绑定到实际文件和片段，不允许模型自由伪造引用。
- 文档内容不能覆盖系统规则，必须隔离提示注入。
- 资料不足时明确拒答或提示补充资料。
- 资料冲突时分别展示来源。
- 摘要和建议标签是 AI 生成元数据，不是新的原文。
- 对话模型和 Embedding 使用外部 Provider，但只发送任务必要文本和上下文；Provider 名称、模型和 Embedding 模型为 TBD。
- Provider 不可用、超时、限流、Key 错误和 Embedding 失败需要用户可观察反馈；具体错误码、重试算法和降级实现留到 G8/G9。

## 15. 验收标准

### 15.1 核心闭环

- AC-001：Given 用户创建知识库，When 输入合法名称并提交，Then 知识库创建成功并进入知识库详情。
- AC-002：Given 用户选择四种支持格式之一且满足 20MB/5 文件限制，When 开始上传，Then 文件显示上传、解析、索引和最终状态。
- AC-003：Given 文件处理成功，When 文件进入可使用，Then 可从知识库或文件详情进入资料问答和学习陪练。
- AC-004：Given 资料问答选择了知识库，When 用户发送问题，Then 回答只能使用当前用户和指定范围的资料，并显示可展开引用。
- AC-005：Given 资料不足，When 用户提出问题，Then 系统明确提示资料不足，不生成伪造文件、页码或原文。
- AC-006：Given 学习陪练已开始，When 用户未提交当前题回答，Then 系统不自动进入下一题。
- AC-007：Given 用户提交回答，When 反馈生成，Then 显示正确内容、遗漏/错误、参考回答和资料依据。
- AC-008：Given 用户结束陪练，When 总结生成，Then 显示本次题数、结果数量和建议复习内容，不推断长期掌握度。
- AC-009：Given 用户从历史会话打开记录，When 会话加载完成，Then 恢复消息、模式和知识库范围。

### 15.2 文件和异常

- AC-010：Given 文件格式、大小或数量不符合 V1 规则，When 用户选择文件，Then 上传被阻止并显示原因。
- AC-011：Given 文件解析或索引失败，When 用户查看详情，Then 显示失败原因、当前状态和重试入口。
- AC-012：Given Provider 超时或不可用，When 生成失败，Then 保留用户输入，结束加载状态并提供重试/配置提示；具体错误分类在 G8/G9 定义。
- AC-013：Given 用户确认删除文件，When 删除完成，Then 片段和索引被清理，历史引用显示来源文件已删除。

### 15.3 页面和安全

- AC-014：Given 任一一级页面首次无数据，When 页面加载完成，Then 显示空状态和下一步操作。
- AC-015：Given 请求加载或任务失败，When 页面仍可访问，Then 显示可理解的错误和恢复操作。
- AC-016：Given 用户访问不属于自己的资源标识，When 服务层处理请求，Then 不返回资源内容。
- AC-017：Given 构建产物、前端代码或日志被检查，Then 不包含 Provider API Key、完整文件正文或完整敏感对话。
- AC-018：Given 文档内容含有系统命令，When 文档参与问答，Then 文档命令不能覆盖系统规则。

### 15.4 非功能

- AC-019：普通页面在声明的测试环境中达到 NFR-01 的可见反馈目标。
- AC-020：对话生成达到 NFR-02 的生成状态和首字延迟目标，或记录未达标原因。
- AC-021：20MB 文件上传显示持续进度，处理刷新后可恢复状态。
- AC-022：核心测试覆盖正常、边界、失败、重试、删除、引用失效和 Provider 异常。
