# 版心与网格规范
> 文档类型：Capability
> Capability ID：CAP-UI-LAYOUT-GRID
> 文档版本：V2.0
> 文档状态：通用基线
> 适用阶段：G5.5、G9.1、G10、G11
> 激活条件：项目需要统一容器、栅格、卡片和图片比例，或 UI 验收要求可测量的布局基线

## 0. Capability 元数据
- **目标**：建立可复用的版心、边距、栅格、卡片与图片比例基线，并把“测得的值”转化为项目唯一变量。
- **输入**：页面类型、终端范围、设计稿/参考站实测值与项目 UI Contract。
- **输出**：项目在当前 Capability 下可执行的方案、规则、检查项与 Evidence。
- **治理方式**：本文件不是全项目无条件生效的全局规则。是否启用由 v3.2 的 `PROJECT_PROFILE`、`ASSESSMENT`、`CAPABILITY ACTIVATION` 与具体 REQ/Spec 决定。
- **项目化位置**：具体框架、平台、Provider、路径、版本、阈值和团队约定写入项目自身的 Profile / Spec / ADR / Rule，不在这里写死。

## 0.1 定位

本文档回答一个必须在**动手写码之前**拍定的问题：整站内容横向占多宽、一行放几个卡片、卡片之间间距多少、不同板块之间怎么保证左右边缘对齐。

它与 `主题配色清单.md` 是同一体裁的**开工前置基线文档**：配色定"用什么颜色"，本文档定"东西摆在哪、多大"。两者都属于 ``设计稿转代码流程` Capability` 第5.1节的硬性前置关口，缺任何一份就开工，返工几乎必然发生。

**经验来源**：实际项目复盘。项目开工时未定版心与网格，导致同一页面内"同样是一行3个卡片，一会大一会小，大标题与大标题之间也没有对齐"，最终只能在开发后期指定某个板块为基准、其余板块反向对齐它，属于典型的高成本返工。

## 1. 核心概念

| 概念 | 定义 | 一句话判据 |
|---|---|---|
| 版心（content container） | 页面内容的最大有效宽度，超出部分留白 | 所有板块的左右边缘必须落在同一条竖线上 |
| 栅格（grid） | 版心内横向切分的列数 | 一行放几个卡片，由列数除得，不能凭视觉估 |
| 水槽（gutter） | 相邻卡片之间的固定间距 | 同一栅格内水槽必须恒定，不能靠 `space-between` 自适应 |
| 外边距（margin） | 版心到浏览器视口边缘的最小留白 | 小屏时先吃掉外边距，再考虑压缩版心 |

## 2. 硬性规则（写码前必须完成，不可后补）

1. **全站唯一版心**：整站只允许存在一个主版心宽度值，定义为一个 CSS 变量或一个容器类，所有板块复用它。禁止某个板块自己写死一个宽度。
2. **版心值必须在开工前写进该 REQ 的 `spec.md`**，与配色方案并列声明。声明格式见第4节。
3. **同类卡片尺寸恒定**：同一栅格下的卡片，宽度由"（版心 − 水槽总和）÷ 列数"算出，不允许由内容长度反向决定卡片宽度。**内容多寡影响的是卡片内部的截断/换行策略，不是卡片本身的尺寸。**
4. **禁止用视觉对齐替代栅格对齐**：不能靠肉眼调 padding 让两个板块"看起来齐了"，必须让它们共用同一个版心容器。
5. **一行几个必须显式声明**：每类卡片列表都要明确写出"桌面端一行N个、平板M个、移动端1个"，缺声明视为未完成设计。
6. **图片类卡片必须先定宽高比**：同一组卡片内图片统一比例（如 16:9 / 4:3 / 1:1），图片以"填充+居中裁剪"方式适配，不允许某张图因原始尺寸不同而把卡片撑高或让图片贴在卡片下沿。
7. **定了变量就必须只用变量，正文禁止硬编码同类数值**。这条是源码实测补上的：真实项目定版源码里 `:root` 已经定义了 `--maxw:1240px`，但全文只引用 2 次，正文硬编码 `max-width:1320px` 达 16 次，另有 1180/1080/1680 并存，全站 `max-width` 共 17 种取值。**定义变量本身不产生一致性，只有"正文再也不出现裸数值"才产生一致性。** 自查方法：全局搜 `max-width:` 后跟数字的写法，命中数应当接近 0（响应式 `@media` 查询条件除外）。

## 3. 推荐基线值（门户网站类，可直接采用）

| 项 | 推荐值 | 说明 |
|---|---|---|
| 主版心宽度 | `1200px`（内容密集型）或 `1400px`（视觉展示型） | 门户网站首选 1200，图片/大屏轮播多的选 1400 |
| 最小外边距 | `24px`（桌面）/ `16px`（移动） | 版心达到上限后，两侧至少保留该留白 |
| 栅格列数 | 12 列 | 便于 2/3/4/6 等分，是通用惯例 |
| 卡片水槽 | `24px`（桌面）/ `16px`（移动） | 同一页面内保持统一 |
| 卡片一行数量 | 桌面 3 个 / 平板 2 个 / 移动 1 个 | 图文卡片默认值；纯图标类可到 4 个 |
| 板块上下留白 | `80px`（桌面）/ `48px`（移动） | 保证板块节奏一致 |

上表是**默认起点**，不是必须照抄。若参考站有明确的版心数值，优先采用参考站的值，但仍必须落成唯一变量。

**实测参照（真实项目定版源码，2026-09-07 实测）**：某实际项目的源码实测曾得到主版心约 **1320px**、圆角 **6px**，并大量使用 `repeat(N,1fr)` 栅格。该数字仅作为案例证据，不作为通用默认值。不同视觉类型的项目可能存在不同合理版心，默认值仅作为起点，最终必须以项目基线或参考站实测值为准。

**但该源码同时是反面样本**：版心虽有实测值，却分散成 17 种 `max-width` 取值，且已定义的 `--maxw` 变量基本闲置（见第2节第7条）。**测得出统一值 ≠ 落实了统一值。**

## 4. 声明模板（复制进该 REQ 的 `spec.md`，与配色声明并列）

```markdown
### 版心与网格声明
- 主版心宽度：1200px（变量名 `--container-max`）
- 最小外边距：桌面 24px / 移动 16px
- 栅格列数：12 列，卡片水槽 24px
- 卡片一行数量：桌面 3 / 平板 2 / 移动 1
- 卡片图片宽高比：16:9，适配方式 `object-fit: cover` + 居中
- 板块上下留白：桌面 80px / 移动 48px
- 基准来源：□ 采用本文档推荐基线值　□ 采用参考站实测值（站点：____，实测版心：____）
```

未填写本声明的 REQ，不允许进入编码阶段——这是 ``设计稿转代码流程` Capability` 第5.1节的硬性关口之一。

## 5. 落地写法（技术栈无关）

变量定义与容器类只写一处，全站引用：

```css
:root {
  --container-max: 1200px;
  --container-pad: 24px;
  --grid-gutter: 24px;
  --section-gap: 80px;
}

.container {
  width: 100%;
  max-width: var(--container-max);
  margin-inline: auto;
  padding-inline: var(--container-pad);
  box-sizing: border-box;
}

.card-grid {
  display: grid;
  grid-template-columns: repeat(3, 1fr);
  gap: var(--grid-gutter);
}

@media (max-width: 1024px) { .card-grid { grid-template-columns: repeat(2, 1fr); } }
@media (max-width: 640px)  {
  .card-grid { grid-template-columns: 1fr; gap: 16px; }
  :root { --container-pad: 16px; --section-gap: 48px; }
}

/* 图片卡片：比例锁定，避免单张图撑高卡片或贴底 */
.card-media {
  aspect-ratio: 16 / 9;
  overflow: hidden;
}
.card-media > img {
  width: 100%;
  height: 100%;
  object-fit: cover;
  object-position: center;
}
```

关键点：卡片等分用 `grid` 的 `1fr` 而不是百分比宽度 + `float`/`flex-basis` 手算，前者天然保证等宽；图片用 `aspect-ratio` + `object-fit: cover` 锁比例，天然规避"图片没有居中，现在是在下面"这类问题。

**实测印证**：真实项目定版源码里 `aspect-ratio` 用了 24 处、`object-fit:cover` 15 处、`contain` 8 处、`repeat(N,1fr)` 47 处——**本节写法在真实项目里是自然收敛的终态**，不是理论推荐。该项目当初正是因为没有一开始就这么写，才出现"图片没有居中，现在是在下面，很丑""图片又太小了"这类返工；改到最后用的就是上面这套。**先按本节写，能直接跳过那段返工。**

若项目选用 Tailwind，断点与间距必须按 `CSS方案选型与Tailwind规范.md` 第4.4节自定义覆盖默认值，且版心值同样只允许存在一个自定义容器类，不允许各页面手写 `max-w-*`。

## 6. 自查清单（收尾验收时逐项过）

- [ ] 全站是否只有一个版心宽度值，且以变量/单一容器类形式存在
- [ ] 是否存在某个板块自己写死宽度、绕过公共容器
- [ ] 相邻板块的大标题左边缘是否严格落在同一条竖线上
- [ ] 同一栅格内的卡片宽度是否完全一致（不因内容长短变化）
- [ ] 同组卡片内的图片是否统一宽高比、统一居中裁剪
- [ ] 各断点下"一行几个"是否与 `spec.md` 声明一致
- [ ] 板块上下留白是否统一，没有出现某个板块间距明显异常
