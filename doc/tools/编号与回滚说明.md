# 编号与回滚说明
> 文档版本：V1.1
> 创建日期：2026-09-03
> 最后更新：2026-09-03
> 关联需求：全局
> 文档状态：定稿

## 编号能否保证
能。做法是：
- REQ 编号永久不变
- Spec 变更时，同步相关文档和日志
- 变更记录写入 progress-log 和 changelog

## 新编号如何分配（防冲突）
- 新建 REQ/ADR/BUG 前，先看对应目录下已有的最大编号，新编号 = 最大值 + 1
  - REQ 看 `docs/01-需求模板/` 下现有 `REQ-XXX-*` 目录
  - ADR 看 `docs/00-治理/adr/` 下现有 `ADR-XXX-*.md`
  - BUG 看 `docs/00-治理/bugs-backlog.md` 里记录的最大编号
- 若两次并发新建导致编号冲突（同一个编号被用了两次）：以先合并进 main 分支的为准，后合并的一方改用下一个可用编号，并在 `changelog-global.md` 补记一条说明，避免编号张冠李戴

## 能否回退
能。具体动作见 `DOCS-GIT.md` 的"回滚原则"，摘要：
- 等级2/3 变更合并前打 tag：`git tag req-xxx-vX.Y.Z`
- 回退时先查 `progress-log.md` 定位目标版本，代码和文档一起回退，避免代码与文档不同步
- 回退后在 `progress-log.md` 补记一条记录

## 关键点
编号保证的是“可追踪”，回退保证的是“可恢复”。
