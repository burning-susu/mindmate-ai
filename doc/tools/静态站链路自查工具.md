# 静态站链路自查工具

> 文档版本：V1.0
> 创建日期：2026-09-07
> 最后更新：2026-09-07
> 关联需求：全局
> 文档状态：定稿

## 目的

一个零依赖 Python 脚本，扫全站 HTML 的内部引用，查两类问题：

- **文件不存在**（ERROR）——`href`/`src` 指向的文件在磁盘上找不到，确定性断链
- **锚点目标不存在**（WARN）——`#xxx` 在目标文件里查不到对应 `id`/`name`，可能有 JS 兜底，需人工确认

定位是**改完页面随手跑一次**的轻量自查，几秒钟出结果，不需要起服务器、不需要浏览器、不需要 npm。

来源：军事仿真门户网站项目实战（2026-09-07，26 个页面 2373 条引用 + 307 处锚点）。

## 1. 与 `SEO优化工具.md` 里 seo-audit.js 的分工

**两个工具都查链接，但覆盖面不同，不是重复建设。** 已逐行核对过 `lib/audit-checks.js` 的实现：

| 检查项 | 本工具 | `seo-audit.js` |
|---|---|---|
| `<a href>` 文件存在性 | ✅ | ✅ `checkLinks` |
| `<img src>` 文件存在性 | ✅ | ✅ `checkImages` |
| **`<link href>` 存在性**（favicon / css / preload） | ✅ | ❌ |
| **`<script src>` 存在性** | ✅ | ❌ 只数阻塞脚本个数 |
| **锚点目标 id/name 存在** | ✅ | ❌ `split('#')[0]` 丢掉锚点 |
| 空链接 `href="#"` | ❌ | ✅ |
| 静态内链数量（百度视角） | ❌ | ✅ |
| 图片 alt / 尺寸 / 懒加载 | ❌ | ✅ |
| 跨页聚合输出 | ✅ | ❌ 链接项逐页报 |

**怎么选**：

- 改完几个页面想立刻确认没搞坏引用 → 本工具（零依赖、秒级）
- 发布前要完整 SEO 体检 → `seo-all.js`（含 seo-audit 门禁）
- 两个都跑最稳，覆盖面互补，跑一次总共不到十秒

**实战验证的两处缺口**，都是 `seo-audit.js` 射程外、被本工具兜住的：

1. **favicon 断链**：21 个页面的 `<link rel="icon">` 路径缺 `../`。`checkImages` 只匹配 `<img>` 标签跳过它，`checkLinks` 只匹配 `<a href>` 也跳过它，两边都漏
2. **preload 指向不存在的文件**：`google-perf.js` 会自动注入 `<link rel="preload">`，但 `checkPerf` 只检查 head 里有没有 `rel="preload"` 字样，不验指向的文件在不在。首屏图改名或挪目录后 preload 会静默失败，审计报告却显示正常

## 2. 为什么锚点只报 WARN，不报 ERROR

静态扫描分不出这两种情况：

```html
<!-- 情况A：有 JS 兜底，功能正常 -->
<a href="about.html#honors">资质荣誉</a>
<!-- about.html 里 id 其实叫 tab-honors，但页内 JS 读 location.hash 做了映射 -->

<!-- 情况B：没有兜底，跳转静默失效 -->
<a href="media.html#news">新闻动态</a>
<!-- media.html 的 tab 只绑 click 事件，location.hash 出现 0 次，落地永远停在默认面板 -->
```

两者在 HTML 层面完全一样——都是"查不到 id"。要区分就得解析 JS 执行逻辑，那是另一个量级的复杂度（得上 Playwright 真开浏览器）。

所以脚本只负责**把可疑处摆出来**，判断留给人：看一眼目标文件有没有读 `location.hash` 的代码即可。

代价是会有已知正常的噪声。实战中 307 处锚点报了 307 条 WARN，其中 229 处是情况 A（正常），78 处是情况 B（真缺陷）。

**不建议加白名单把情况 A 屏蔽掉**——白名单容易变成掩盖问题的地方，哪天那段兜底 JS 被误删，白名单会让它静默通过。宁可每次多看 4 行输出。

## 3. 脚本

复制到站点根目录（HTML 所在目录）运行，跑完删除，不要提交进源码目录。

```python
"""
全站链路自查脚本
用法：复制到站点根目录（HTML 所在目录）运行 `python 全站链路自查.py`，跑完删掉。

检查两类问题：
  [ERROR] 内部 href/src 指向的文件不存在  —— 确定性断链，必须修
  [WARN ] 锚点目标 id/name 不存在        —— 可能有 JS 兜底，需人工确认

文件清单为自动发现（曾因硬编码清单漏检 404.html）。
"""
import re, os

# 按项目实际情况增删。目的是跳过备份目录与工具目录，避免把历史副本算进结果
SKIP_DIRS = {".git", "node_modules", "_backup", "备份", "backup", "dist", "tools"}

FILES = sorted(
    os.path.relpath(os.path.join(root, fn), ".").replace("\\", "/")
    for root, dirs, fns in os.walk(".")
    if not any(p in SKIP_DIRS for p in root.replace("\\", "/").split("/"))
    for fn in fns
    if fn.endswith(".html")
)

_id_cache = {}


def ids_of(path):
    """缓存每个文件的 id/name 集合，避免同一个目标文件被反复读盘"""
    if path not in _id_cache:
        try:
            c = open(path, encoding="utf-8").read()
        except OSError:
            _id_cache[path] = None
        else:
            _id_cache[path] = set(re.findall(r'\bid="([^"]+)"', c)) | \
                              set(re.findall(r'\bname="([^"]+)"', c))
    return _id_cache[path]


broken = []        # 文件不存在
anchor_bad = []    # 锚点 id 查不到
checked = 0        # 已验证的文件引用
anchors = 0        # 已验证的锚点
external = 0       # 外链/tel/mail/js，跳过不验

for f in FILES:
    content = open(f, encoding="utf-8").read()
    base_dir = os.path.dirname(f)
    for href in re.findall(r'(?:href|src)="([^"]+)"', content):
        if href.startswith(("http://", "https://", "//", "mailto:", "tel:",
                            "javascript:", "data:")):
            external += 1
            continue

        path_part, _, frag = href.partition("#")
        path_part = path_part.split("?")[0]          # 去掉 ?v=1 这类查询串

        # 省略路径的纯锚点（href="#top"）指向当前文件
        if path_part:
            target = os.path.normpath(os.path.join(base_dir, path_part)).replace("\\", "/")
            checked += 1
            if not os.path.isfile(target):
                broken.append((f, href, target))
                continue                             # 文件都没有，锚点不用验了
        else:
            target = f

        if frag:
            anchors += 1
            tids = ids_of(target)
            if tids is not None and frag not in tids:
                anchor_bad.append((f, href, target, frag))

# 输出一律用英文：Windows 终端默认 GBK，print 中文会乱码
print(f"scanned html files: {len(FILES)}")
print(f"checked file refs: {checked}, checked anchors: {anchors}, "
      f"external/tel/mail/js (skipped): {external}")
print(f"[ERROR] broken file refs: {len(broken)}")
for f, href, target in broken:
    print(f"  {f}  ->  {href}   (resolved: {target})")

# 按 目标文件#锚点 聚合，避免页脚同一条链接在 20+ 个页面里刷屏
print(f"[WARN ] anchors whose target id/name not found: {len(anchor_bad)}")
groups = {}
for f, href, target, frag in anchor_bad:
    groups.setdefault((target, frag), []).append(f)
for (target, frag), srcs in sorted(groups.items()):
    print(f"  {target}#{frag}  <- referenced {len(srcs)}x, e.g. {srcs[0]}")
    print(f"      check if {os.path.basename(target)} reads location.hash; "
          f"if not, this jump silently fails")

print()
print("exit code: 0 = no ERROR (WARN does not affect exit code, review manually); 1 = has ERROR")
raise SystemExit(1 if broken else 0)
```

## 5. 设计要点（改脚本前先看）

- **文件清单必须自动发现，不能硬编码**。V1 曾写死 `index/about/media + products/* + solutions/*`，全站 26 个 HTML 只覆盖 25 个，`404.html` 里的引用从没被检查过。这和 `SEO优化工具.md` 第 13 行记的教训同源：**照着已知页面列清单，会漏掉当时没想到的文件**
- **纯锚点不能直接 `continue`**。`href="#top"` 要解析成"指向当前文件的锚点"再校验，早期版本把它算进 external 跳过了
- **要剥查询串**。`style.css?v=2` 不剥 `?v=2` 会当成文件名的一部分，误报断链
- **输出按问题聚合，不按页面**。页脚里同一条链接会在 26 个页面各出现一次，逐页报会刷 26 屏。聚合成 `目标#锚点 <- referenced 26x` 一行
- **输出用英文**。Windows 终端默认 GBK，`print` 中文会乱码（实测撞过）
- **`id` 和 `name` 都要收**。老式页面用 `<a name="top">` 做锚点，只查 `id` 会误报

## 6. 局限（明确不在射程内）

- 不验外链是否可达（要发网络请求，且外链失效不是本项目代码问题）
- 不验锚点是否真能定位（见第 2 节，需要浏览器）
- 不查 CSS 里 `url()` 引用的资源
- 不查渲染结果、交互、样式——那是 Playwright 的领域，见 `04-设计资源/自动化测试选型与规范.md`
- 只认双引号属性（`href='x'` 单引号写法不匹配）。若项目混用引号需改正则
