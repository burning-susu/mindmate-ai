# 5要素Prompt工具
> 文档版本：V1.1
> 创建日期：2026-09-03
> 最后更新：2026-09-05
> 关联需求：全局
> 文档状态：定稿

## 目的
把任意自然语言需求整理成可执行的 5 要素 Prompt。

## 流程
0. **先查 `docs/03-Prompt模板库/Prompt模板库.md` 第2节目录索引，判断能否套用现成模板**（这一步优先于从零收集五要素，见下方"模板匹配判断"）
1. 若无可套用模板，再收集目标、约束、上下文、验收、输出格式
2. 检查缺失信息
3. 缺什么就补问什么
4. 你确认后，落成最终 Prompt
5. 追加到 `docs/03-Prompt模板库/processed-prompts.md`

## 模板匹配判断（第0步的具体做法）
拿到需求描述后，先对照模板库目录索引表判断当前场景属于哪一类，再决定怎么处理，不要跳过这一步直接从零收集五要素：

- **完全匹配**（场景描述和某个模板的"适用场景"完全对应，如"要给一个新页面新增开发任务"对应"页面模板"）：直接套用该模板，只替换 `{{}}`/`【】` 占位符里的具体信息，不用重新走五要素收集流程
- **部分匹配**（大体是某个模板的场景，但有一两处关键差异，如"页面模板"套上了但这次涉及响应式清单）：以匹配的模板为基础，把差异部分对应的约束/验收项补进去（如追加"响应式与浏览器兼容开发模板"里的断点约束），不要因为不完全匹配就整个推翻重新收集
- **无匹配**（模板库里没有对应场景，或者是全新类型的任务）：按下面第1~5步从零走五要素收集流程；收集完成后判断这次的 Prompt 是否有复用价值，若有，按 `Prompt模板库.md` 的格式补充成新模板，不是只记进 `processed-prompts.md` 就完事——这样下次遇到同类场景就能直接进入"完全匹配"分支

**判断依据来源**：`processed-prompts.md` 里已经记录过"网站内容修改/搭建"两份模板是用户自己整理成终态直接收编的案例，说明"已有成熟模板直接复用"本身就是被验证过的做法，不是这次新加的额外步骤，只是之前没有写进流程说明里。

## 缺失时的提问顺序
> 仅在"模板匹配判断"结论为**无匹配**、或**部分匹配**里差异部分仍缺信息时触发，不是每次任务的固定起点。
- 你要做什么
- 不能做什么
- 当前项目背景
- 怎么算完成
- 想要什么输出格式
